# Foundation DLL AI 测试代码生成

## 概述

对单个 capability family，读取 `method-capability-contracts.json` 和 `capability-family-contract.json`，对每个 `methodSubjectId` 自动生成带真实断言的手写测试代码，并写入 `verification/foundation-dll/<assembly>/<family>/test/<Class>Tests.cs`（与 AutoGenerated.cs 和 csproj 在同一目录）。同时自审核、记录测试目的。

**前置条件**（必须已存在）：
- `verification/foundation-dll/<assembly>/<family>/method-capability-contracts.json` — 含 methodSubjectIds
- `verification/foundation-dll/<assembly>/<family>/capability-family-contract.json` — 含 family 定义
- `verification/foundation-dll/<assembly>/<family>/test/<Class>Tests.AutoGenerated.cs` — Phase 1 生成的基线冒烟
- `<Class>Tests.csproj` 和 `README.md` — Phase 1 生成的项目文件

## 生成文件清单

对每个 family，AI 生成 4 个文件：

| 文件 | 路径 | 类型 | 用途 |
|---|---|---|---|
| **Test** | `test/<Class>Tests.cs` | handwritten partial class | 带 `[Fact]` + `Assert` 的测试方法 |
| **Benchmark** | `benchmark/<Class>Benchmarks.AutoGenerated.cs` | static class | 只含 `BenchmarkSubjectId`/`BenchmarkRoute`/`BenchmarkProfile` |
| **HotUpdate** | `host/<Class>HotUpdate.AutoGenerated.cs` | static class | 只含 `HotUpdateSubjectId`/`HotUpdateDirection.HostToPatch` |
| **Patch** | `patch/<Class>Patch.AutoGenerated.cs` | static class | 只含 `HotUpdateSubjectId`/`HotUpdateDirection.PatchToHost` |

### 各文件约束

1. **Test (`*Tests.cs`)**: partial class，用 `[CapabilityTest]`，每个 `[Fact]` 必须有 `Assert`
2. **Benchmark**: `public static class`，只能用 `BenchmarkSubjectId`、`BenchmarkRoute`、`BenchmarkProfile`，不能有 `[Fact]`
3. **HotUpdate (host)**: `public static class`，只能用 `HotUpdateSubjectId`、`HotUpdateDirection.HostToPatch`，不能有 `[Fact]`
4. **Patch**: `public static class`，只能用 `HotUpdateSubjectId`、`HotUpdateDirection.PatchToHost`，不能有 `[Fact]`
5. **Purpose 注释**：`// Purpose: ...` 必须在属性列表之前（方法上方第一行）

## 方法分类规则

对每个 methodSubjectId，解析签名并按以下规则分类：

```
System.Private.CoreLib/System.Convert::ToChar:System.Char(System.Int32,System.IFormatProvider)
  ├── type_name: Convert          (命名空间最后一段)
  ├── method_name: ToChar         (:: 后的方法名)
  ├── return_type: System.Char    (最后一个 : 到前括号)
  └── param_types: [System.Int32, System.IFormatProvider]  (括号内逗号分隔)
```

| 分类 | 条件 | 生成策略 |
|---|---|---|
| **simple** | 所有参数和返回值都在 PRIMITIVE_SET 中 | `var result = Method(args); Xunit.Assert.NotNull((object)result);` |
| **mixed** | 部分参数在 PRIMITIVE_SET，部分在 COMPLEX_SET | `_ = Method(primitiveArg, null!);` 冒烟不崩 |
| **needs-manual** | 含 ref/pointer/unsafe/泛型参数 | `// TODO: needs-manual — ref/pointer/unsafe parameters` |
| **excluded** | `method-capability-contracts.json` 中 benchmarkRequired/hotupdateFunctionalRequired 均为 false 且 routeCodes 不含 native | 跳过生成 |

### 自动生成约束规则

1. **`[Fact]` 方法必须有 `Assert`**：所有标记为 `[Fact]` 的测试方法（在 handwritten `*Tests.cs` 及 `*Tests.AutoGenerated.cs` 中的 simple 非 void 方法）必须包含 `Xunit.Assert.NotNull((object)result)`。不能只有 `var result` 没有断言。Void 和 mixed 方法除外。
2. **Benchmark 文件只使用 Benchmark 属性**：`benchmark/*.AutoGenerated.cs` 中的方法只能用 `BenchmarkSubjectId`、`BenchmarkRoute`、`BenchmarkProfile` 属性，不能用 `[Fact]`。使用 `public static class` 而不是 partial class。
3. **HotUpdate 文件只使用 HotUpdate 属性**：`host/*.AutoGenerated.cs` 中的方法只能用 `HotUpdateSubjectId`、`HotUpdateDirection`，不能用 `[Fact]`。使用 `public static class` 而不是 partial class。
4. **Patch 文件只使用 HotUpdate 属性**：`patch/*.AutoGenerated.cs` 中的方法用 `HotUpdateSubjectId`、`HotUpdateDirection.PatchToHost`，方向与 host 对称。
5. **Purpose 注释必须在属性之前**：`// Purpose: ...` 注释必须放在属性列表之前（方法上方第一行），而不是放在方法体之后。
6. **Test 文件分层**：`*Tests.cs`（handwritten）包含 AI 生成的测试方法（`[Fact]` + Assert），`*Tests.AutoGenerated.cs`（Phase 1）包含自动生成的骨架（`[Fact]` + Assert/`_ =`）。两者通过 C# partial class 机制合并。

### PRIMITIVE_SET

```
System.Boolean, System.Byte, System.SByte, System.Int16, System.UInt16,
System.Int32, System.UInt32, System.Int64, System.UInt64,
System.Single, System.Double, System.Decimal,
System.Char, System.String, System.Byte[], System.Array,
System.IntPtr, System.UIntPtr, System.Type, System.Guid,
System.TimeSpan, System.DateTime, System.DateOnly, System.TimeOnly,
System.Uri, System.Version, System.Enum, System.ValueType, System.Object,
System.ReadOnlySpan<T>, System.Span<T>, System.ReadOnlyMemory<T>, System.Memory<T>
```

注：`System.Object` 视为 primitive（可传 `42` / `"test"`），`System.Enum` 视为 primitive（可传 `DayOfWeek.Monday`），`System.Type` 用 `typeof(byte)`。

### COMPLEX_SET

```
System.IFormatProvider, System.Globalization.CultureInfo, System.Globalization.NumberFormatInfo,
System.Globalization.DateTimeFormatInfo, System.Globalization.CompareInfo,
System.IO.Stream, System.IO.TextReader, System.IO.TextWriter,
System.Collections.IEqualityComparer, System.Collections.Generic.IEqualityComparer<T>,
System.Collections.Generic.IComparer<T>, System.Text.Encoding,
System.Runtime.Serialization.StreamingContext, System.Runtime.Serialization.ISerializable,
以及所有非标准命名空间中的类型
```

## 生成流程

### Step 1: 加载输入

```
1. 确定 family 标识：<assembly_name>/<family_slug>
   - family_id: "family/System.Private.CoreLib/convert/char"
   - assembly_name: "System.Private.CoreLib"
   - family_slug: "convert-char"
   - class_name: "ConvertCharTests" (family_slug 按 "-" split → Capitalize 拼接 + "Tests")
   - capability_family_enum: "SystemPrivateCoreLib_ConvertChar" (从 ledger 或 contract 读取)

2. 读取文件：
   - verification/foundation-dll/<assembly>/<family_slug>/capability-family-contract.json
   - verification/foundation-dll/<assembly>/<family_slug>/method-capability-contracts.json
   - verification/foundation-dll/<assembly>/<family_slug>/review/bundle.json (更新用)

3. 提取方法列表：
   - methodSubjectIds 从 capability-family-contract.json
   - routeCodes, benchmarkRequired, hotupdateRequired 从 method-capability-contracts.json
```

### Step 2: 逐方法生成

对每个 methodSubjectId：

**simple 类方法** — 生成带断言的测试：
```csharp
[Fact]
public void Method_<sanitized_subject_id>()
{
    // Purpose: Verify <method> returns expected value for typical input
    // Family: <family_id>
    var result = Convert.ToChar(65);
    Xunit.Assert.Equal('A', result);
}
```

**mixed 类方法** — 生成冒烟调用：
```csharp
[Fact]
public void Method_<sanitized_subject_id>()
{
    // Purpose: Smoke test — verify <method> executes without throwing for typical input
    // Family: <family_id>
    // Note: Contains complex parameter (IFormatProvider) — passes null as placeholder
    _ = Convert.ToChar(65, null!);
}
```

**needs-manual 类方法** — 生成 Skip 标记：
```csharp
[Fact(Skip = "needs-manual — ref/pointer parameter requires unsafe context")]
public void Method_<sanitized_subject_id>()
{
    // TODO: Implement test for method with ref/pointer parameter
    // Purpose: <family_id> / <method>
}
```

### Step 3: 集成 benchmark / hotupdate / patch

对于每个方法，检查 `method-capability-contracts.json`：

- `benchmarkRequired: true` → 在 benchmark 文件中生成 body（`_ = Method(args);`）
- `hotupdateFunctionalRequired: true` → 在 host 文件中生成 body（`_ = Method(args);`，方向 HostToPatch）
- Patch 文件始终生成全部方法（方向 PatchToHost），与 host 对称

**约束**：
- benchmark 只用 `BenchmarkSubjectId`、`BenchmarkRoute`、`BenchmarkProfile` 属性，不用 `[Fact]`
- host 只用 `HotUpdateSubjectId`、`HotUpdateDirection.HostToPatch`
- patch 只用 `HotUpdateSubjectId`、`HotUpdateDirection.PatchToHost`
- benchmark/hotupdate/patch 不需要断言，只需要有调用即可。框架自行处理计时和执行验证。
- `// Purpose:` 注释放在属性列表之前（方法上方第一行）

### Step 4: 生成 expected value

对 simple 类方法，AI 需要推理出正确的预期值：

```
推理原则：
1. 如果方法是 "ToXxx" 转换 → 用已知转换计算 expected
   - Convert.ToChar(65) → 'A'  （ASCII）
   - Convert.ToInt32("42") → 42
   - Math.Abs(-5) → 5
   - "hello".Length → 5

2. 如果方法是纯计算 → 心算或使用 round-trip
   - Enum.Parse<DayOfWeek>("Monday") → DayOfWeek.Monday
   - Guid.Parse("...") → 已知值

3. 如果不能确定预期值 → 用冒烟 (mixed) 替代，避免生成错误断言
```

**重要**：如果不能 100% 确定预期值，降级为 mixed（冒烟）。错误的断言比没有断言更糟糕。

### Step 5: 写出文件

**写入 handwritten Tests.cs**：
```
路径: verification/foundation-dll/<assembly>/<family_slug>/test/<Class>Tests.cs
格式: partial class，只包含 handwritten 内容（不要复制 AutoGenerated 中的内容）
```

```csharp
using System;
using Chaos.TestFramework;
using Xunit;

[CapabilityTest("family/<assembly>/<family_id>", IncludeBenchmark = <has_benchmark>, IncludeHotUpdate = <has_hotupdate>)]
public partial class <Class>Tests
{
    // AI-generated tests for <family_id> — generated at <timestamp>
    // Reviewed: <review_status>

    // === simple methods ===
    // 每个带断言的测试...

    // === mixed methods ===
    // 每个冒烟测试...

    // === needs-manual ===
    // 标记需要手写的测试...
}
```

### Step 6: 自审核

写入 review notes：
```
路径: verification/foundation-dll/<assembly>/<family_slug>/review/notes.md
```

格式：
```markdown
# Review Notes — <display_name>

## AI 生成的测试 (<timestamp>)

### 审核摘要
- simple（带断言）: N 个
- mixed（冒烟）: N 个
- needs-manual: N 个
- excluded: N 个

### 逐方法审核

#### <method_name>
- **分类**: simple / mixed / needs-manual
- **测试目的**: <测试这个方法的什么>
- **输入**: <使用的参数>
- **预期**: <期望的行为>
- **风险**: <已知的边界情况或风险>

#### <method_name>
...

### 未覆盖的场景
- <列出已知但未测试的边界情况>

### 审核结论
- [ ] 所有 simple 测试断言合理
- [ ] 所有 mixed 测试至少能冒烟通过
- [ ] needs-manual 方法已正确标记
- [ ] benchmark/hotupdate 已生成 body
```

### Step 7: 更新 review bundle

更新 `verification/foundation-dll/<assembly>/<family_slug>/review/bundle.json`：
- 在 `generatedArtifacts` 中添加：
  - `verification/foundation-dll/<assembly>/<family_slug>/test/<Class>Tests.cs`
  - `verification/foundation-dll/<assembly>/<family_slug>/review/notes.md`
- 将 `notesPath` 指向 notes.md

## 常见错误

| 错误 | 后果 | 避免方式 |
|---|---|---|
| 生成错误 expected value | 测试通过但不验证正确行为 | 不确定时降级为 mixed |
| null! 参数导致 NPE | 冒烟失败，需要手动修复 | 对明显会 NPE 的方法标记 needs-manual |
| 忘记更新 review bundle | 审核链断裂 | 写完 notes.md 后立即更新 bundle.json |
| 断言太弱（`Assert.NotNull` 对值类型） | 编译失败 | `Assert.Equal` 对值类型，`Assert.NotNull` 对引用类型 |
| 没处理 static vs instance 方法 | 编译失败 | static 方法用 `TypeName.Method()`，instance 方法需要先 new |
