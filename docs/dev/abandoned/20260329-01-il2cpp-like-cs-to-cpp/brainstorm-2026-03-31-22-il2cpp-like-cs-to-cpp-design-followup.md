## 本轮重点观察

从当前设计稿来看，最值得继续深挖的不是“是否需要这些模块”，而是“这些模块之间的契约究竟长什么样”。高优先级细化点主要集中在以下几个方向：

1. `Metadata Graph -> Typed IL IR -> Runtime-Contract IR` 三层之间的边界与最小信息集
2. `AOT manifest` 的字段设计、稳定性要求以及它在增量构建中的职责
3. 运行时对象模型与 GC 协议，尤其是 root、handle、write barrier、safepoint 的精确接口
4. 泛型实例化、共享与特化策略在 Phase 1 的取舍
5. 反射保留、序列化保留与闭世界分析之间的关系
6. `Generated C++ -> Runtime Core` 内部 ABI 的版本化方式
7. 异常、线程和 safepoint 之间的耦合协议如何拆解，以避免运行时不稳定

## 当前判断

- 如果下一轮要优先推进“最容易落地的实现规划”，优先级最高的切入点通常是：
  1. `AOT manifest`
  2. Runtime-Contract IR
  3. 内部 ABI
- 原因是这三者共同定义了分析结果如何稳定落盘、代码生成如何依赖运行时、以及系统如何保持跨阶段演进而不频繁推翻前面产物。

## 待继续讨论的问题

- Phase 1 的 `AOT manifest` 是否只服务于代码生成，还是也要直接服务调试、增量构建和兼容性诊断？
- Runtime-Contract IR 是否应当按“语义动作”分层，例如分成对象/类型/控制/异常/互操作五大类？
- 内部 ABI 是先做“纯 C 风格函数表”，还是允许部分模板化/内联包装，仅将稳定边界固定在较小核心？
- 泛型 Phase 1 是优先“全特化保正确性”，还是“有限共享 + 明确回退策略”？
