# Chaos IL2CPP 发布路线图 (v2 — 最终版）

> **推进用任务计划** — 纬度：版本模型 / 里程碑次序 / 任务粒度 / 决策门
> 基线：v0.2.4 (2026-09-07) · 目标：Windows GA v1.0.0

---

## 版本模型

```
v0.2.4 ─┬─ M1: GC稳定 ─── v0.2.5 (仅内部修复，不发布)
         │
         ├─ M2: Harness首绿 ─ v0.2.6 (CI/Nightly/质量/报告全自动)
         │
         ├─ M3: CoreLib三轴 ─ v0.3.0 ← 首个内部 feature 里程碑
         │
         ├─ M4: Foundation三轴 ─ v0.4.0
         │
         ├─ M5: 引擎端到端 ── v0.5.0
         │
         └─ M6: Windows GA ── v1.0.0 ← 产品发布
                │
                ├─ M7: Linux GA ── v1.1.0 (post-1.0)
                │
                └─ M8: 移动/主机 ── v1.2.0+ (post-1.0)
```

**核心原则**：
- Gate 驱动，非每步发号 — 每一里程碑的决策门(G0-G7)全绿才推进到下一个
- 第一个 GA = Windows 引擎可接 — 不等 Linux/移动/主机。Linux/Mobile/Console 在 1.1/1.2+ 逐平台追加
- 引擎 IL2CPP 字节级兼容 + PS5 属远期(需厂商合同/NDA)，不阻塞 1.0

## M1：GC 稳定性闭环

**目标**：GC 达到可重复全绿基线，消除非确定性崩溃。M1 是后续所有 CI 门禁的前提。

**版本**：v0.2.5（内部修复，不发布 tag）

**决策门**：G0 — GC 全量测试在 WKS Debug/Release 下可重复绿

| 任务 | 优先级 | 估算 | 决策门 | 备注 |
|------|--------|------|--------|------|
| GC-N7 真机 page-heap 定位坏字节并定点修复 | P0 | 5d | G0 | YoungGcPauseUnderLoad 非确定堆破坏。沙箱 A/B/C/X 已全回滚。唯一路径：真机 gflags page-heap 归因确切坏字节，定点修。阻塞 GC-N8<5%量化、GC-N9。 |
| GC-N6 typed young 死循环诊断修复 | P1 | 5d | G0 | 内容校验原型暴露 typed young 挂起。重载 harness 后 cdb 定位。mode3 提升拷贝源址错 + instance_size==0 guard 已合，确认环是否全关。 |
| GC-N9 Server harness 修复 | P1 | 5d | G0 | AdjustHeapCountGrowShrink 被 #if __GC_SERVER 守卫。WKS 下 heap_manager 3/3 绿。Server 构建需 GC-N3 框架。 |
| GC-N3 Server GC 测试框架就绪 | P1 | 5d | G0 | GcTestBase::SetUp 在 Server 构建下仍 SEH。GC-N9 runtime 前置。 |
| GC-N12 profile 调参 | P2 | 5d | G0 | 依赖 N7 稳定 Release 基准后量化调参（size/pause/mode-heuristics）。 |
| GC 已知失败数据库维护 | P2 | 3d | G0 | 6 项(loh/gen1/stress 等)隔离绿并行门偶翻。no-skip 政策保留至实证摘除。持续追踪，非一次性交付。 |
| GC 全量回归基线锁定并自动化 | P1 | 2d | G0 | 默认 WKS + HeapVerify=2 0 hard ERROR 的全量回归基线，作为后续 GC 改动的回归锚。 |

**版本号说明**：M1 是内部修复基线，不发布 tag/release。修复完成后直接把代码合入 main，为后续 M2 CI 门禁提供稳定的 GC 基础。
