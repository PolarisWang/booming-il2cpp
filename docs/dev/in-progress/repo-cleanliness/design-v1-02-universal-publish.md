# 通用 IL2CPP 发布引擎 — 设计文档

> 2026-08-29 · 域：CodeGen + 翻译 + 构建
> 状态：brainstorm 阶段（待清零后批准）

---

## 1. 产品目标

让 `chaos-il2cpp publish` 能从**任意 .NET 项目**（csproj / dll / exe）产出**双形态 native exe**：

- **`--mode app`**：纯应用 exe。运行用户的 Main，透传 argv/exit code。用户感知不到任何测试框架。
- **`--mode test`**：测试 harness exe（当前 publish 的形态）。分派到 subject 方法，支持 `--fact-json`、`--benchmark-all` 等子命令。
- **`--mode fact`**（future）：精简版，只保留 fact 功能。

**底层翻译引擎（IL→C++）三者共享同一套代码。** 差异只在 entry point 实现和 CMake 项目模板。

### 各层职责

#### ConvertService（新建，或重构现有 ConvertToCppHandler）

**输入**：任意 .NET 程序集路径（.dll/.exe）或 csproj 路径

**职责**：
- `.csproj` → 内部 `dotnet build` → 定位输出 DLL
- 扫描 DLL 的 entry point（与 .NET host 规则一致：`Main` / `[STAThread] static void Main` / `<StartupObject>`）
- 调用 `PipelineOrchestrator.RunNativeAot()` 做 IL→C++ 翻译（现有代码，复用）
- 产出 `native-aot.generated.cpp` + `type-info-defs*` + `enum_metadata.generated.h`（现有）
- 返回 `ConversionResult`（含 `AssemblyName`、`EntryPointSubjectId`、`GeneratedDirs`、`SubjectMethods`）

**关键改动**：探测 entry point 后，把 `EntryPointSubjectId` 传入 codegen，codegen 已支持（`EntryPointSubjectIdOverride` 字段存在）。

```csharp
public sealed record ConversionResult
{
    public required string AssemblyName { get; init; }
    public string? EntryPointSubjectId { get; init; }  // "Program::Main:System.Int32(System.String[])"
    public required IReadOnlyList<string> GeneratedDirs { get; init; }
    public required IReadOnlyList<string> SubjectMethods { get; init; }  // 全量 subject IDs
    public required string OutputRoot { get; init; }
}
```

#### SdkService（复用 + 扩展现有 SdkEmitter）

现有 `SdkEmitter.EmitSdk()` 已覆盖：
- 拷贝 runtime 头文件（`include/`）
- 拷贝 runtime_stubs 源码
- 拷贝/生成 native libs（`lib/`）
- 生成 `chaos-config.cmake` + `chaos-targets.cmake` + `CMakePresets.json`

**扩展**：
- 平台抽象接口 `INativePlatform`（Windows x64，预留 Linux x64/ARM64/macOS/Android）
- 新增 `EmitAppSdk()` / `EmitTestSdk()` 不同变体（当前 SdkEmitter 已足够，不需要变体）

#### EntryEmitters（双形态）

**app_main.cpp（新）**：
```cpp
// Generated by chaos-il2cpp publish --mode app
#include "runtime_entry.h"  // 现有运行时头

extern int UserMain(int argc, char* argv[]);

int main(int argc, char* argv[])
{
    // 初始化运行时 (GC, VTable, hot-update data)
    ChaosRuntimeInitialize();
    
    // 转调用户 Main
    int result = UserMain(argc, argv);
    
    // 清理 (GC shutdown, profile flush)
    ChaosRuntimeShutdown();
    return result;
}
```

**UserMain（codegen 生成）**：从用户 DLL 的 `Main` 方法经 IL→C++ 翻译生成，名字固定为 `UserMain`，由 codegen 在 `native-aot.generated.cpp` 中生成。

**runtime-entry.cpp（现有）**：保留测试 harness 的逻辑（`--fact-json`、`--benchmark-all`、dispatch 分派表）。

#### CMake 项目模板

**现有**：`TestProject.CMakeLists.txt.scriban`（harness 项目，含 `verification_dispatch.generated.cpp`）

**新增**：`AppProject.CMakeLists.txt.scriban`（应用项目，无 harness，直接链接 `app_main.cpp` + `native-aot.generated.cpp`）

```cmake
# AppProject.CMakeLists.txt.scriban（新）
cmake_minimum_required(VERSION 3.20)
project({{ project_name }} CXX)
find_package(chaos REQUIRED PATHS {{ sdk_dir }})
add_executable({{ executable_name }}
    app_main.cpp
    {% for src in generated_sources %}
    {{ src }}
    {% endfor %}
)
target_link_libraries({{ executable_name }} PRIVATE chaos::runtime)
```

#### PublishController（顶层编排）

```bash
chaos-il2cpp publish <path> [--mode app|test] [--output <dir>] [--rid <target>]
```

| 参数 | 说明 | 默认 |
|------|------|------|
| `<path>` | `.csproj` / `.dll` / `.exe` | 必填 |
| `--mode` | `app`（纯应用）/ `test`（harness） | `app` |
| `--output` | 输出目录 | `<project>/output` |
| `--rid` | 目标运行时标识 | `win-x64` |
| `--config-tier` | `check` / `profile` / `ship` | `check` |
| `--source-only` | 只产 C++ 源码，不编译 | false |

**内部编排**：
```
publish <path> --mode app
  ├─ ConvertService: 探测 entry → codegen → 生成 .cpp
  ├─ SdkService: 拷贝 runtime libs/headers
  ├─ CppProjectEmitter (App template): 生成 CMakeLists.txt + app_main.cpp
  ├─ BuildService.ConfigureAndBuild: cmake → exe
  └─ 写 publish.manifest.json
```

## 3. 与现有架构的关系

### 保留不变（零改动）
- `PipelineOrchestrator.RunNativeAot()` — 核心 IL→C++ 翻译（含 closure/entry point 路由）
- `SdkEmitter.EmitSdk()` — runtime SDK 生成
- `BuildService.ConfigureAndBuild()` — 刚刚修复的 CMake 构建
- ATG 测试管线（`foundation-dll` / `build.py`）— 完全不受影响
- `publish --mode test` — 当前行为不变（TPG generate-dll harness）

### 新增
- `ConvertService.cs` — 从 `ConvertToCppHandler` 提取泛化逻辑
- `AppProject.CMakeLists.txt.scriban` — 应用级 CMake 模板
- `app_main.cpp.scriban` — 应用入口模板
- `PublishController.cs` — 顶层编排（接受 csproj/dll/exe，路由到 mode）

### 修改
- `DriverEntry.cs` — 把 `publish` 路由到 `PublishController`，新增 `--mode` 参数
- `ConvertToCppHandler.cs` — 提取泛化逻辑到 `ConvertService`，自身保留为兼容入口

## 4. 平台抽象（跨平台扩展预留）

```csharp
public interface INativePlatform
{
    string Name { get; }                    // "windows-x64", "linux-x64", "osx-arm64"
    string CmakeGenerator { get; }          // "Visual Studio 17 2022", "Ninja", "Unix Makefiles"
    string CmakePlatform { get; }           // "x64", "arm64"
    string StaticLibExtension { get; }      // ".lib", ".a"
    string ExecutableExtension { get; }     // ".exe", ""
    string BuildConfig { get; }             // "RelWithDebInfo", "Release"
    string SdkPreset { get; }               // "windows-x64-reference", "linux-x64-profile"
}
```

阶段 1 只实现 `WindowsX64Platform`，预留接口让后续添加 `LinuxX64Platform`、`MacOSArm64Platform`、`AndroidArm64Platform`。

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| Entry point 探测不准确（泛型/async Main） | 中 | 复用 .NET 的 EntryPointToken 而非启发式扫描 |
| csproj 构建失败（TFM 不匹配） | 低 | 默认用 net10.0，用户可 `--tfm` 覆盖 |
| app_main.cpp 与 runtime 初始化顺序不匹配 | 中 | 参考现有 `runtime-entry.cpp` 的初始化顺序 |
| 跨平台扩展导致 Windows 初期设计过度抽象 | 低 | YAGNI 约束：`INativePlatform` 接口只包含已知 Windows 需要的字段 |

---

## 7. 验收口径

1. `chaos-il2cpp publish HelloWorld.dll --mode app --output out/` → `out/entry.exe` 产出，运行打印 "HelloWorld"
2. `chaos-il2cpp publish HelloWorld.csproj --mode app --output out/` → 同上（自动 build）
3. `chaos-il2cpp publish <subjects.dll> --mode test --output out/` → 现有 harness 行为不变
4. `python tests/runner/test_driver.py --layer unit` → 无回归
5. `publish --source-only` 产出纯 C++ 源码（可被人类阅读/检查）
