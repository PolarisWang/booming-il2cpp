## 二、逐项证据

### 2.1 Thread.Yield —— 不是缺陷，是期望不可移植 ⚠️

生成断言（`Thread.AutoGenerated.cs:91`）：

```csharp
var result_1_0 = global::System.Threading.Thread.Yield();
Assert.AreEqual(false, result_1_0);      // ← 断言恒 false
```

**native 侧是正确的**（`threading_stubs.cpp:156`）：

```cpp
CHAOS_IL2CPP_INT32 chaos_thread_yield(void) noexcept
{
    std::this_thread::yield();
    return 1;                    // ← 恒返 1
}
```

**.NET 8 实测（连跑 5 次）**：

```
Thread.Yield() = False
Thread.Yield() = True
Thread.Yield() = False
Thread.Yield() = True
Thread.Yield() = False
```

**`Thread.Yield()` 的返回值是非确定的**，取决于 yield 时是否有其他就绪线程。
ATG 探针在某一次运行中捕获到 `false` 并把它固化成期望值 ——
**这个期望在任何实现上都不可移植**（.NET 自己跑也会时对时错）。

**判定**：native 无需改（`return 1` 是合法实现）。应把该项归入
ATG 的 envSensitive 类（同 `env_sensitive_ids` 机制），不要在 native 侧"修"。

### 2.2 Thread.GetDomainID —— 缺 native 🔴

生成断言（`Thread.AutoGenerated.cs:494`）：`Assert.AreEqual(1, result_29_0)`
**.NET 8 实测恒 = 1**（3 次运行一致）。

wrapper 是 catch-all（`native-aot.generated.cpp:11626`）：

```cpp
chaos_external_runtime_System_Threading_Thread_System_Threading_Thread__GetDomainID_System_Int32__() noexcept
{ ... "no native body; delegates to Phase 1/2, else returns 0" ... }
```

**零参、返回 0** → 断言失败。**可修**：`.NET Core` 只有单一 AppDomain，
`GetDomainID()` 语义上恒为 1，新增 native 返回 1 即正确（非占位）。

### 2.3 Thread.VolatileRead(object) —— 缺 native 🔴

生成断言（`Thread.AutoGenerated.cs:781`）：
`Assert.AreEqual(default(object)!, result_40_0)`
**.NET 8 实测恒 = null**。

同类 wrapper 零参 catch-all。注意 `VolatileRead` 的**其他 8 个重载**
（Byte/Double/Int16/Int32/Int64/SByte/Single/UInt16）也都是 catch-all
（见 `native-aot.generated.cpp` 11 个 wrapper），本 chunk 只测到 Object 一个。

**可修**：native 已有 `ChaosVolatileRead`（Int32 版，`interlocked_stubs.cpp:84`），
但缺引用类型（Object）版本 —— 引用类型 volatile 读在本运行时是普通 load。

### 2.4 LazyInitializer.EnsureInitialized<T> —— 泛型实例化 🟡

IR 中确有闭合实例：
```
System.Threading/LazyInitializer::EnsureInitialized<System.Int32>:System.Int32(System.Int32&,System.Boolean&,System.Object&)
```
但生成的是**零参 catch-all**（`native-aot.generated.cpp:9982`），
且错误信息里是**开放泛型**拼写 `EnsureInitialized<System.Int32>...<T>`。

`.NET 8 实测`：`EnsureInitialized(ref 0, ref false, ref null)` **返回 0**，
且 `init` 变 `true`、`sync` 被赋值 —— 与 ATG 期望一致。

**判定**：属 `generic-instantiation-materialization` 的 L2 线
（跨程序集泛型实例化不物化），不是本 chunk 能独立修的。
与 ContinueWith 的 factoryGap 同源。

## 三、可立即修的两项 — ✅ 已实施并验证（commit `c013be67c`）

| 项 | 修法 | 实测 |
|---|---|---|
| `Thread.GetDomainID` | 新增 `chaos_thread_get_domain_id` 恒返 1 + shape 注册 | → `real value=1` |
| `Thread.VolatileRead(object)` | 新增 `ChaosVolatileReadObject`（指针宽度）+ shape 注册 | → `real value=0` |

**实现要点**：
- `ChaosVolatileReadObject` **不是** `ChaosVolatileRead` 的别名 ——
  后者返回 INT32，会把 64 位对象引用**截断到低 32 位**，
  产生一个损坏的引用而非干净的失败。二者刻意分开。
- `GetDomainID` 的多域语义（.NET Framework 的递增 id）不适用，
  因为本运行时不实现多 AppDomain。

**管线实测**：`failed` 12 → **11**，`real` 91 → **92**。
生成物判据：两个 wrapper 从零参 catch-all 变为带参转发。

**回归测试**：`interlocked_arithmetic_test.cpp` 扩到 **15 用例**
（新增 3 个 VolatileRead 宽度断言，含「高位非零」用例以暴露 32 位截断），
实测 15/15 PASSED。

## 三·补、不要修的一项 ⚠️

**`Thread.Yield` 不要在 native 侧改。** 实测其返回值**非确定**
（同机 5 次运行 False/True 交替），任何固定期望都不可移植 ——
.NET 自己跑也会时对时错。正确做法是把它并入 ATG 的 envSensitive 集合
（`_get_env_sensitive_subject_ids` 机制），而不是在 native 侧"修"。

在 native 侧改成恒返 0 只会让当前这一次运行碰巧通过，掩盖真实问题。

## 四、`GetCurrentProcessorId` — 同类（期望不可移植）⚠️

生成断言（`Thread.AutoGenerated.cs:1591`）：`Assert.AreEqual(0, result_60_0)`

**.NET 8 实测（同机 24 核，3 次运行）**：

```
14 8 8 8 8 8
 6 6 6 6 6 6
16 4 4 4 4 4
```

**返回值由调度决定**，同一进程内两次调用都可能不同（实测出现过 `1` 然后 `2`）。
本机不存在稳定的 0 —— ATG 断言 `0` **只是碰巧**。

**判定**：与 `Thread.Yield` 同属「期望不可移植」，**不在 native 侧修**。

> 不触及该方法的类型与调用路径。是断言碰巧/不碰巧的结果（时序敏感）。

## 五、`CompareExchange<int>` — 系统性缺陷，单独立项 🟡

**根因**：显式泛型实例化 callee 的 method 名带 `<T>`：

```
callee: ...Interlocked::CompareExchange<System.Int32>:System.Int32(...)
GetMethodNameFromSubjectId → "CompareExchange<System.Int32>"
注册键                     → "CompareExchange"
→ canonicalKey 不等 → 永不命中 → 落 catch-all
```

**实测对照**（同 chunk，其余全通）：

| 方法 | 结果 |
|---|---|
| `CompareExchange(sbyte/short/byte/ushort/uint/ulong/float/double/long/object)` | ✅ real |
| **`CompareExchange(int,int,int)`** | ❌ **failed** |

**影响面：单 chunk 38 处**，横跨 6 个类型族（`SubjectInstanceFactory::Create<T>`
16 处、`DefaultInterpolatedStringHandler::AppendFormatted<T>` 13 处、
`ThreadPool::QueueUserWorkItem<T>`、`Interlocked::CompareExchange<T>`、
`LazyInitializer::EnsureInitialized<T>`、`Volatile::Read/Write<T>`）。

**本轮未修**，理由见 `generic-callee-method-name-never-matches.md`：
属 registry 匹配层的架构性改动，且与并发会话在修的 `Create<T>` 线重叠。
