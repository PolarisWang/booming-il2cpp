### 🟡 P1-1：XmlTextReader 输入未接 managed TextReader

**现状**：硬编码 `<root/>`。
**影响**：reader 的读取路径只覆盖空根元素，`ReadString`/`GetAttribute` 等永远返回空。
**修法**：需要调用 managed `TextReader.ReadToEnd()` 或逐块 `Read()`，把内容拷进 native buffer。这需要 codegen 侧生成对 managed 方法的调用，或走 `ChaosExternalRuntimeFallback` 的解释器路径取文本。

---

### 🟡 P1-2：ATG `SubjectInstanceFactory` 裸对象问题（系统性）

**现象**：无公共无参构造的具体类（如 `XmlTextWriter`、`XmlTextReader`）走
```csharp
SubjectInstanceFactory.Create<T>()  // → RuntimeHelpers.GetUninitializedObject
```
返回**字段全 null 的裸对象** → 所有实例方法 NRE → ATG 标 `[UNVERIFIED]`。

**影响面**：**不止 XML**。所有「有参构造的具体 BCL 类」都受影响。

**已尝试且未生效**：在 `CSharpExpressionBuilder.KnownInstances` 加 fixture——因为 `GetInstanceExpression` 的查找 key 格式不匹配（`typeFullName` 实际格式待查）。

**排查方法**（1 轮内可完成）：
```csharp
// 在 CSharpExpressionBuilder.GetInstanceExpression 开头加：
Console.Error.WriteLine($"[DIAG] typeFullName='{typeFullName}' csType='{csType}'");
```
跑一次 build stage，从 ATG stderr 看实际格式。

**这是本次会话投入最多但未突破的点**——建议作为独立任务立项。

## 4. 关键操作知识（踩过的坑）

### 4.1 pipeline 缓存三层

改动 codegen/ATG 后必清，否则跑的是旧产物：

```bash
# 1. Hephaestus 缓存（两处）
rm -rf testing/foundation-dll/<Assembly>/.hephaestus-cache
rm -rf artifacts/foundation-dll/<Assembly>/chunks/.hephaestus-cache
rm -rf tests/e2e/translation/<Assembly>/chunks/.hephaestus-cache

# 2. ATG probe 结果
rm -rf tests/e2e/translation/<Assembly>/chunks/<slug>/managed/.autogen

# 3. chunk 产物
rm -rf artifacts/foundation-dll/<Assembly>/chunks/<slug>/{results,native,managed}

# 4. TPG 必须重建（它捆绑自己的 Generator.dll 副本）
dotnet build src/tools/Chaos.IL2CPP.Tools.TestProjectGenerator/Chaos.IL2CPP.Tools.TestProjectGenerator.csproj
```

### 4.2 codegen 注册的三个硬约束

| 约束 | 症状 | 规避 |
|:-----|:-----|:-----|
| **IL 64KB 方法体积** | 运行期 `InvalidOperationException`（`dotnet build` 不报） | 新注册放进 `Part1.S<N>.cs` 分片 |
| **Shape 键冲突** | `Shape already registered: 'Type::Method()'` | 重载必须有不同 `paramTypes` |
| **void ABI 必须声明为 Void** | C3313 `const void chaos_result` | 用 `CreateVoidAbiSlot()` |

### 4.3 每次只 stage 自己的文件

`git add -A` 会扫进并行 agent 的临时文件（`.parallel-work-saved/`、`tmp_*.json`、`sarif_out/` 等）。
**必须显式列文件名**：
```bash
git add <明确路径1> <明确路径2>
git diff --cached --name-only   # 提交前核对
```

## 5. 路线图建议（为 worktree 并行优化）

### 关键洞察：现有 roadmap 的 Phase 划分不适合并行

现有 `docs/dev/in-progress/json-xml-production-readiness/roadmap-v1-01.md` 按 **Phase（时间顺序）** 切分，但实际依赖是**按类型族**的。M1-M8 之间大多是独立的。

### 建议：按「可独立验证的类型族」重新分轨

| 轨 | 内容 | 冲突面 | 可并行度 |
|:---|:-----|:-------|:--------:|
| **A** | M5 XmlTextReader 收尾（输入接 managed TextReader） | `xml_reader_stubs.*`, S19 | ✅ 独立 |
| **B** | M6 XmlTextWriter 收尾（剩余 20 个方法：WriteBase64/WriteChars/WriteDocType 等） | `xml_writer_stubs.*`, S19 | ⚠️ 与 A 共享 S19 |
| **C** | P1-2 ATG 裸对象问题（诊断 key 格式 + 修 fixture 路径） | `CSharpExpressionBuilder.cs` | ✅ 完全独立 |
| **D** | P0-2 codegen failure count 17 排查 | `CodegenFailureCount` 递增点 | ✅ 完全独立 |
| **E** | M3 Utf8JsonWriter（写面，类型面干净） | 新文件 | ✅ 独立 |
| **F** | M1 Utf8JsonReader（需 span 支持，**重**） | 新文件 + eval stack | ❌ 不建议并行 |

### worktree 并行建议配置

**推荐 3 轨并行**（跨文件冲突最小）：

```
worktree-1: 轨 A（M5 收尾）      → xml_reader_stubs.* + S19
worktree-2: 轨 C（ATG 裸对象）    → CSharpExpressionBuilder.cs
worktree-3: 轨 D（codegen 17）    → Methods.ModuleData.Helpers.cs
```

**S19 是共享文件**——轨 A 和轨 B 会冲突。建议：
- 让每轨**新建自己的分片**（轨 A → S20，轨 B → S21）
- 只有 `Part1.cs` 的调用行会冲突，且冲突面只有 1 行，手工合并成本极低

### 每轨的验收标准（统一）

```bash
# 必须全绿才能推
dotnet build src/managed/Chaos.IL2CPP.Generator/Chaos.IL2CPP.Generator.csproj
dotnet build src/tools/Chaos.IL2CPP.Tools.TestProjectGenerator/Chaos.IL2CPP.Tools.TestProjectGenerator.csproj
cmake --build artifacts/presets/windows-x64-reference --target chaos_runtime_core --config Release
# pipeline（清缓存后）
CHAOS_FOUNDATION_DLL=$(pwd)/testing/foundation-dll PYTHONPATH=$(pwd)/tests/e2e \
  python tests/e2e/verification/chunk_pipeline.py --assembly <asm> --chunk <slug> \
  --stages build,fact --native-config check
```

**硬指标**：`kCodegenFailureCount` 必须为 0（或 ≤ chunk 容差）；`smokeUnknown` 不上升。
