## 四、为什么翻译器是难点（已查明的核心事实）

### 运行时的目标形状（spike 已证明）
`async Task<int> One(){ await Task.Yield(); return 1; }` 应翻译成 native C++：

```cpp
struct AsyncStateMachine_One {       // 镜像 Roslyn <One>d__0
  int state = -2;                    // <>1__state: -1=done,0=await,.. 
  CHAOS_IL2CPP_INTPTR builder_slot=0;// <>t__builder (Task handle, box)
  YieldAwaiter awaiter;              // <>u__awaiter0
  int result=0;                      // <result>5__0
  void MoveNext(){
    switch(state){ case -1:return; case 0: goto AFTER; }
    if(!awaiter.is_completed){
      state=0;
      // <>t__builder.AwaitUnsafeOnCompleted(ref awaiter, ref this)
      awaiter.UnsafeOnCompleted(continuation_wraps_moveNext, this);
      return;                        // 挂起
    }
    AFTER:
    result=1; state=-1;
    async_task_builder_set_result_raw(&builder_slot, result); // 完成+派发
  }
};
```
spike 测试证明了：MoveNext 挂起 → 续列(ThreadPool) 重入 MoveNext → set_result → Task 完成 result=1。

### 复用的关键（已查证）
1. **`>d__` struct 字段访问已有发射器支持**：`stfld/ldfld/ldflda` 在 `StructuredIR.Emit.cs:1322-1382`，struct 由 `StructFieldDescriptorArtifact` 描述
2. **`MoveNext` 是普通实例方法**（`IsStatic=false`, `this`=状态机 struct）：`Methods.ModuleData.Helpers.cs` 已建 `BuildAsyncMoveNextIndex`
3. **现有结构化发射**：`TryBuildStructuredMethodBody`（StructuredIR.Emit.cs:1554）已把普通方法 IL(含 switch/branch/goto) → C++

### 剩下要写的三段（真翻译器）
| 段 | 内容 | 落点 |
|----|------|------|
| **A. `>d__` struct 固化**(对象模型带字段) | MoveNext 的 `this` 需是含 `<>1__state/<>t__builder/<>u__awaiterN/locals` 的 native struct。确认 AOT IR 是否已给 `>d__` 建 `StructFieldDescriptorArtifact`；若未有则需在 object model synth 补。 | `ObjectModelUtilities/StructLayout` 路径 |
| **B. builder/awaiter `Call` 解析到 runtime extern** | MoveNext 体里的 `call AsyncTaskMethodBuilder<T>::AwaitUnsafeOnCompleted/SetResult/SetException/Create/Start` + `call TaskAwaiter...get_IsCompleted/…UnsafeOnCompleted` 需变成调用 `async.h`/`task_runner` 的 native extern（很多已存在：`async_task_builder_*`,`async_task_on_completed`, 但 `Start`/`AwaitUnsafeOnCompleted`/`GetStateMachineBox` 的等价 native 尚未有，需加） | AsyncAwaiterCatalog + CallSite extern 解析 |
| **C. async 方法入口 wrapper** | 真正的 `Task<int> One()`(非 MoveNext, 含 `new <One>d__0` + `builder.Create`+`MoveNext()` 调用) 需驱动状态机起动并返回 Task。当前应该落到普通发射/fallback；需补成"建 box+回调 MoveNext+返回 Task" | MethodEmission 入口 |

### 三个 "why"（续做前必读）
- **为什么不能走 C++20 coroutine**：frame 布局编译时固定不可替换(破坏 hotupdate 关键 - P3)、EC/SyncCtx 全要手写、IL 已扁平化难反推 await 链、pinned 不可 GC compact。（详见 brainstorm 调研）
- **为什么 MoveNext 当普通方法翻**：它不是 coroutine 体;就是 switch(state)+字段读写+call，可复用结构化发射，保住 hotupdate(函数指针可重定向+struct 可替换)
- **为什么 spike 先做 native 手写**：在多线程/ThreadPool 异步里验证"续列重入→set_result→完成"的时序与数据正确性，隔离出来不用先建翻译器
