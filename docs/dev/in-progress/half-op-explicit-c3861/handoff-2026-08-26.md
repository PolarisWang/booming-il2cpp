## 精确 drop-off（真根因）
**post-scan 是唯一 catch-all stub 发射点，但没能看到这个符号**：
- `Methods.Remaining.cs:644-710`：`externalRuntimeSymbolsReferenced` post-scan 迭代 `_methodsBySubjectId.Values` 的 **already-lowered IR instructions**，只检查 `instr.TargetSymbol`（:674-678）和 `instr.Callee`（:683-689）。
- 但 `Half::op_Explicit(Half→Double)` 的调用点在 **emit-time** 经 `EmitLinearResolvedInvocation`（`NativeAotLoweringPlanner.LinearEmission.Advanced.cs:369` else 分支）从 **`invocationTarget.TargetSymbol`** 解析——该 resolution 值**没有写回 IR instruction 的 `TargetSymbol`/`Callee` 字段**。
- → post-scan 三个检查（TargetSymbol / Callee 两条分支）都漏掉它 → `externalRuntimeSymbolsReferenced` 不含该符号 → 不 emit stub → C3861。

### 证据链
- `EmitLinearResolvedInvocation`（ExceptionEmission.Utilities.cs:113）emit `targetSymbol(...)`，targetSymbol 来自 `invocationTarget.TargetSymbol`（调用点 Advanced.cs:369 传入）。
- post-scan 读的是 `m.Instructions`（Remaining.cs:668-691），不读 emit 层的 `invocationTarget` 映射。
- `_emittedExternalRuntimeSymbols`（Path 1）是 typed-stub 集合，被 Remaining.cs:699-704/745 用作排除（防止 C2556），不是 post-scan 的遗漏补丁。

## 权威修复方向（core from `dev-il2cpp-external-runtime-expert` SKILL "CodeGen 层洁净"）
post-scan 的 `externalRuntimeSymbolsReferenced` 应**额外收集 emit 层实际解析出的 `TargetSymbol`**——即 `EmitLinearResolvedInvocation` / `EmitInvocation` 解析的 targetSymbol 应注册进一个 与 post-scan 共享的集合（而不仅是写进 `_emittedExternalRuntimeSymbols`），让 post-scan 能 emit 该符号的静态 inline stub。

具体候选修改：
- 在 emit 层解析 targetSymbol 时，若符号以 `chaos_external_runtime_` 开头且未被外部声明，将其加入一个 post-scan 也读取的集合（例如现成的 `seenTargetSymbols`，Remaining.cs:474/486/541/605 —— 它已被 post-scan 在 :665 读作 exclude）。核对其收集来源是否覆盖 emit-time-resolved 符号。
- 或者：post-scan 的 `externalRuntimeSymbolsReferenced` 增加对 emit 期解析集合的扫描（不只 IR instruction 字段）。
