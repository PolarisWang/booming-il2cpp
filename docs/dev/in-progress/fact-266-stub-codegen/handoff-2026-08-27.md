## 2026-08-27 首轮推进(归因 + 根因确认)
**266 failed 全部是 `AutoGenerated.System_Private_CoreLib.<Type>Tests::<method>` 的 ATG 测试 wrapper**(调用被测方法并校验,如 `ConvertTests::ToDecimal_224_sbyte_0` → 被测 `System.Convert::ToDecimal(System.SByte)`)。

**按 TypeTests 族归因**(methodIndex→s_hotpatch_entries 注释, 解析自 native-aot.generated.cpp):
```
System_StringTests 91 | System_TypeTests 76 | System_ConvertTests 34 | System_DecimalTests 26
System_EnumTests 13 | System_MathTests 8 | 其余(BitConverter/Delegate/Activator 等)各1-2
```
前 4 族 = 227 (85%)。

**根因(codegen 层, 非运行时)**:
- wrapper 在 `native-aot.methods.json` **只有 index/nativeSymbol/subjectId/paramCount/params/isInstance 元数据, 无 body/instructions**(对照: 完整 lower 的方法有 rawBody)。
- 因此 codegen 对 wrapper **只生成 extern "C" 声明**(grep 到 chaos_generated_module.cpp:7056 等), **不生成定义体**。
- fn table `reinterpret_cast<void*>(&wrapper)` 引用, 但无定义 → 靠 /FORCE 链接, 运行时 return 0 → fact value=0 与预期不符 → failed。
- 被测方法(Convert/String/Type/Decimal 的方法)在 codegen 也未真实 AOT-lower(与 P0-B AOT fallback 缺口同族)。

**修入口(两种, 规模差异大)**:
- **A. 规范修复**: codegen 为"methods.json 无 body"的 wrapper 生成 fallback stub **定义**(而非只有声明) → fn table & 有效、不靠 FORCE。但值仍 return 0, **passed 不升**。
- **B. 真实现修复(用户期望"测试通过")**: 让被测方法(Convert/String/Type/Decimal 等数百 BCL 方法)在 codegen 生成真实实现返回真值 → passed 上升。这是 **P0-B 同族的大工程**(跨多 session), 需按方法族分批实现, 或依赖 interpreter 正确返回值。

**首轮结论**: 已定位 266 wrapper 归因 + codegen 无-body 根因。真实现修复(走 passed 上升)是宏大专项, 与 [[perf-line-benchmark-credibility-and-dispatch]] (111 fallback 缺口)同族。
