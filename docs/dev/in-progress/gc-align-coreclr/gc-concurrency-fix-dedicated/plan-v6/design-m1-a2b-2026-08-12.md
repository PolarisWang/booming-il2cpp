# M1-A2b 设计 — store-barrier 原子化（3 层汇聚设计，2026-08-12）

> 域：GC(6)+运行时(2)+CodeGen(4)。前置：instrument 锁死根因 + 3 层 Workflow 汇聚。
> 状态：设计完成，实现待专门会话。裁决：对齐 CoreCLR。

## 1. 锁死根因（instrument 实证，勿再质疑）

`gc_region_barrier_stress_test` dangling = **young-GC Phase-1 晋升存活缺口**。
- DIAG-DANGLE：danglings 的年轻地址**全真 nursery**（`young∈oldpage=0`）→ 排除 region-gen 字节碰撞（层1）。
- 机制 = **store-then-barrier 非原子竞态**（测试注释 L119-126 + 3 层 agent 一致确认）：
  1. mutator store `槽=nursery_ptr`（card 未置）
  2. GC `RequestGlobalSafepoint` → 线程在 store 后 barrier 前某次 poll ack+park
  3. Phase-1 扫 card，该槽 card=0 → 整 card 跳过 → 该槽的 nursery 引用对 Phase-1 不可见
  4. 仅被该槽引用的 nursery 对象被回收（Phase-4）→ 槽悬垂
  5. mutator 恢复执行 barrier（已晚）
- **关键**：竞态发生在线程已 ack/park 之后 → "等所有 ack" 无法排除它；ack 只证线程到某 safepoint，不保证已 store 的 card 已置。

## 2. 3 层汇聚方案（Workflow wf_3e2ded31）

| 层 | 结论 | 推荐 |
|----|------|------|
| GC屏障+youngGC | 竞态=store/card 两指令非原子；候选A Phase-1 补扫（O(heap) 贵）；候选B no-safepoint 包裹（贴 CoreCLR 但需改 codegen） | 组合：B 主线 + A 兜底 |
| 线程+safepoint | **硬挂起证伪**：硬 SuspendThread/SIGUSR2 仍可停 store 与 barrier 之间 → 硬 STW 单独不修此竞态。CoreCLR 安全=安全点不落 store/card 之间（codegen 属性） | store+barrier 原子化（poll 抑制 `tls_forbid_suspend_depth`，mechanism 已存在）+ Phase-1 重扫兜底 |
| codegen 发射 | 三套发射全把序列裂成 store→card（LinearEmission.cs:86/89,263/273、jit_helpers CodegenSt* 等）。**JIT/解释器已走共享 helper**（CodegenStFld/StElem/StObj/StSFld 6-8 个）天然收口 | **不改 3 套发射契约**（回归大）；改共享 helper 内禁 GC 临界区 + **运行时兜底（Phase-1 页级重扫/卡 flush，发射 0 改动风险最低）** |

**汇聚主推荐（最低风险、发射 0 改动、确定性修复）**：
1. **主修复（确定性）**：young-GC Phase-1 在 dirty-card 扫描后，对 **in-use old 页做一次 slot 级补扫**（用 `IsInNursery` 同一谓词），确保无槽持有 nursery ref 被漏。此时所有线程已 park（无并发写卡）→ 扫描无 race。
   - 成本控制：**只对有未 ack/临界区线程涉及或含 GC_END_STUBBORN_CHANGE 的页补扫**，或低频（dirty_card_count 命中率判断）；纯常开全扫 O(heap) 不可接受。
2. **辅助（性能/语义）**：在共享 helper（jit_helpers CodegenSt* + 解释器 .inc 站点）内把 store→card 包进 `tls_forbid_suspend_depth`（mechanism 已存在于 thread_state.cpp:66/L274），收窄竞态窗口。

## 3. 实现分步（下一专门会话）

1. **P-1（正确性主修复）**：Phase-1 补扫。定位 gc_young_collector.cpp:474-505。在 ScanDirtyCardsInPagesBatched 后加：遍历 `G_OldGen().GetPageArray()` 所有 in_use 页，逐 pointer 槽 `IsInNursery`→`GcScavengeObjectKnownNursery`→回写。先跑通正确性（dangling→0），再上成本控制（2）。
2. **P-2（成本控制）**：补扫范围的 bounded 化——只扫"未 ack 线程涉及的页"或脏卡率阈值触发。
3. **P-3（辅助）**：共享 helper 禁 GC 临界区。
4. **验证**：`chaos_gc_region_barrier_stress_test.exe` 20x 全 0；`ctest -R gc_ -L unit` 无回归；`CHAOS_GC_HeapVerify=2` stress。
5. **caveat（必须验）**：交接文档前会话"store 前 blocking Poll 仍确定性 212/thread7" → 可能存在**第二漏根**（晋升回写 `*ptr_slot=tenured` 或 Page 覆盖）。P-1 落地后须确认 dangling 真归零，非掩盖。

## 3b. ⚡ 实证否决 P-1 naive 全槽重扫（2026-08-12，第 2 次失败）

我实现并实测了 P-1 的 naive 形态（Phase-1 后对所有 in-use old 页逐 slot `IsInNursery`→scavenge→回写）：
**回归：dangling 从既有 ~32-307/1024 恶化到 1023/1024（几乎全槽悬垂）**。已 revert（git checkout 恢复，工作区干净）。

**原因（实证）**：全槽重扫**无法区分真实 GC-ref 槽与非指针数据/自由空间**。旧代页内非引用槽位里恰落在 nursery 地址范围的值被误当作存活引用去 `GcScavengeObjectKnownNursery`，导致错误晋升/scavenge 破坏 nursery 一致性 → 大面积污染。这正是 3 层设计预警的"无法廉价区分真实引用 vs 数据槽"。

**修正结论**：P-1 不能是 naive 全槽扫描——必须**只扫精确 GC-ref 槽**（依赖对象 GcLayout 的 pointer_offsets），或回到 3 层汇聚的主线（候选B/D）：**store+barrier 原子化（poll 抑制）**。
→ 主线修正为：`tls_forbid_suspend_depth`（thread_state.cpp:66/L274，mechanism 已存在）包裹 store→card（共享 helper CodegenSt* + 解释器 .inc 站点 + codegen 发射点），使线程不可被 park 在 store 与 barrier 之间。**这 3 层都推荐，是 M1 真正主修复**。辅助 = 精确布局 slot 重扫（仅扫 pointer_offsets 声明槽），非全槽。

## 3e. 用户选 Option A（精确布局 slot 重扫）→ 系统性调查证伪（2026-08-13）

用户选 A（精确布局 slot 重扫）。但系统性调查（读 GcLayout + OldGen Allocate + stress 源码）得出**决定性负结果**：

**old-gen 任意 `Allocate(size, bool scanning)` 分配没有关联 `GcTypeLayout`。**
- `G_OldGen().Allocate(size, true)`（gc_old_gen.cpp:721）不传 stable_id、不 `Register` layout。
- stress test 的 `OldMessage`（128× void*）**从未注册 layout**；首字 = `nursery_slot[0]`（真 nursery 引用），非合法 TypeInfo。
- 故线性对象 walk（Phase-1b 精确布局扫）在第一个 OldMessage 处 `IsValidTypeInfoPointer` 失败 → 无法按 `pointer_offsets` 扫。
- 即使注册了 layout，`Register` 把 `pointer_count` clamp 到 `kGcLayoutMaxInlinePointers=32`（gc_layout.cpp:158），128 槽只认前 32 → 覆盖仍不全。

**架构结论（决定性）**：old-gen 对 `Allocate(size,true)` 对象的扫描**本质是卡驱动的**（`scanning=true` = 该页作为 card-scan 源），
**不依赖 per-type layout**。精确布局扫描（Option A）在结构上不可用于此类无类型页 → **Option A 证伪**。

→ 正确修复方向回到 **Option C（卡写读一致性）**：`g_heap_base` 启动固定（消除 DIAG-4 写读断开）
+ 屏障用 `IsNurseryPointer` 而非 `GetRegionGen`（DIAG-3 dst 误标）—— 与 memory 方向 a 一致。
**已如实否定用户所选 A，需回退重选；非盲改。**
