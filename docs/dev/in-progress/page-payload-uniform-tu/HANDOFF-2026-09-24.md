## 二、🔴 开工前必读（三条纪律）

### 2.1 每次构建前查 Generator 新鲜度

**pipeline 跑的是 TPG 内嵌的 Generator 副本**，不是你刚构建的那个。只重建
Generator 不重建 TPG → 构建成功但跑的是**旧 codegen**，唯一症状是"改动没生效"。

```bash
# 改了 Generator 源码后、跑 chunk 构建前：
bash tools/check-generator-freshness.sh <你改动的符号名>
# 若报 STALE：
dotnet build src/tools/Chaos.IL2CPP.Tools.TestProjectGenerator/Chaos.IL2CPP.Tools.TestProjectGenerator.csproj -c Debug
# 再确认一次 fresh 才开始构建
```

### 2.2 C2712 阻断完整构建 —— 用数据 TU 独立编译绕过

C2712（`__try` + 对象展开）**只出现在承载方法体的 page 文件**。承载数据
（hotpatch/反射分包/vtable/GC slot map）的 payload TU **不含 `__try`**：

```bash
# 验证数据 TU 可编译（不需要等 C2712 修好）：
bash tools/verify-payload-tu.sh \
  artifacts/foundation-dll/System.Private.CoreLib/chunks/system/native \
  subjects/native-aot.payload.page-0066.cpp ...
```

⚠️ 这只证明单 TU 是合法 C++，**不证明**能链接或运行时正确。
