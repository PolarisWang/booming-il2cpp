## 用户原始请求

用户要求检查 `docs/booming` 下的文档，并整理到新的 `docs/dev` 结构下。关键约束有两条：

1. 不要替换或丢失之前的内容
2. 如果遇到不确定事项，再单独提出问题

## 现状盘点

`docs/booming` 下目前有 6 组历史目录：

1. `2026-03-29-il2cpp-like-cs-to-cpp`
2. `2026-03-30-roadmap`
3. `2026-03-31-roadmap-0-contract-freeze-and-skeleton`
4. `2026-04-02-harness-engineer-automation`
5. `2026-04-03-unified-run-entrypoint`
6. `2026-04-03-unified-test-framework`

它们共同特征是：

- 属于旧流程下的任务过程文档
- 缺少新流程要求的 `STATUS.md`
- 文档正文内部仍保留大量 `docs/booming/...` 路径引用

## 方案比较

### 方案 A：直接移动旧目录到 `docs/dev`

优点：

- 目录最终只保留一份
- 新结构最干净

缺点：

- 不改写正文就会破坏文档内部的旧路径引用
- 一旦出现遗漏，恢复成本高
- 与“不要丢失内容”的要求冲突风险较大

### 方案 B：复制导入到 `docs/dev/completed/`，保留 `docs/booming` 原件

优点：

- 可在新结构下建立完整归档
- 原始路径继续可用，不会因为迁移导致历史引用失效
- 最符合“先保证不丢内容”的优先级

缺点：

- 短期内会有双份文档
- 后续若要彻底移除 `docs/booming`，还需要再做一轮引用清理

## 当前结论

采用方案 B。

原因：

- 这是一次历史文档整理任务，不是正文改写任务
- 当前目标是结构归档，不是做全量链接重写
- 可以直接写出稳定执行计划，不需要先拆 roadmap

## 分流结果

进入 `plan`，不进入 `roadmap`。
