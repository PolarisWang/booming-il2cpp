# ctor 句柄 ABI 修复 实现计划

> **面向执行 Agent：** 必须使用 dev:subagent-driven-development（如果可用子 Agent）或 dev:executing-plans 来执行本计划。步骤使用复选框（`- [ ]`）语法跟踪。

**目标：** 修复「引用类型 `newobj` 的 native 工厂返回值被丢弃」这一机制缺陷，使句柄式 native stub 工厂返回的 handle 能真正到达后续 `callvirt`，从而消除 XML 句柄家族的静默失败。

**架构：** 在 shape 注册层新增 `CtorReturnsNativeHandle` 元数据标记，沿 `ShapeEntry → ExternalRuntimeHelperDefinition → InvocationTarget` 传递到 `EmitLinearNewObject`；当标记置位时，codegen 把**工厂返回值**推上 eval 栈（而非 `chaos_object` 地址），且 native wrapper 返回类型由 `void` 改为 `CHAOS_IL2CPP_INTPTR`。

**技术栈：** C# (.NET 8) codegen / MSVC C++ native runtime / Python chunk pipeline

**架构审核模式：** critical（触及 codegen + AOT 主线）

**结构告警重点：**
- **重复逻辑**：`CreateVoidAbiSlot` / 标记传递在多处 shape 注册点重复 → 需确认是否应提取 helper
- **codegen 与 Scriban 分层**：本改动全部在宿主 C# 侧，**不得**下沉到 Scriban 模板
- **文件职责**：`EmitLinearNewObject` 已承载四条分支，新增标记判断是否应提取子方法

**权责图审核主题：**
`native 工厂返回值的 authority` —— 谁有权决定 eval 栈上是「托管对象地址」还是「native handle」？
预期 proof：未标记 ctor 的产物**逐字节 diff 为空**（证明 authority 边界未被越权扩张）。
