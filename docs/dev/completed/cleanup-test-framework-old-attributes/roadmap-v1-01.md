# Roadmap: 清理 Chaos.TestFramework 旧属性类型

## 1. 目标

移除 Chaos.TestFramework SDK 和 Runtime 中所有不再存在的旧属性类型（`CapabilityFamilyId`、`BenchmarkSubjectId`、`BenchmarkRoute`、`BenchmarkProfile`、`MethodSubjectId`、`VerificationRoute`、`HotUpdateSubjectId`、`HotUpdateDirection`），使 `test_code_generator.py` 只生成 `[Fact]` / `[Benchmark]` / `[HotUpdate]` + `Assert.*` 模式。

## 2. 范围边界

- `src/reference/Chaos.TestFramework.Sdk/` — SDK 源码
- `src/reference/Chaos.TestFramework.Runtime/` — Runtime 源码  
- `testing/.../stages/test_code_generator.py` — 测试代码生成器
- `testing/.../stages/native_code_generator.py` — Native 代码生成器
- `testing/foundation-dll/System.Collections.Immutable/**/*.AutoGenerated.cs` — 自动生成文件
- `testing/foundation-dll/System.Collections.Immutable/**/benchmark/*.cs` — benchmark 手写文件
- `testing/foundation-dll/System.Collections.Immutable/**/host/*HotUpdate.cs` — host 手写文件
- `testing/foundation-dll/System.Collections.Immutable/**/patch/*Patch.cs` — patch 手写文件
- `testing/project-test/runtime-self-test/patch/ArithmeticPatch.cs` — 唯一编译的旧属性文件
- `tests/verification/unit/projections/foundation_dll/test_*.py` — Python 单元测试
- `build/toolchains/run/testing/foundation_dll_audit_generator.py` — Pipeline 审计
- `build/toolchains/run/testing/subject_reporting.py` — 报表
- `build/toolchains/run/subject/project_workspace.py` — workspace

## 3. 非目标

- 不改动已使用新模式（`[Fact]` + `Assert.*`）的 family（如 boxing-unboxing-casts）
- 不改动已重构的 pipeline 流程（只清理属性引用，不改 orchestration/stage 逻辑）
- 不重跑 foundation-dll 全量 pipeline（仅清理代码，不改翻译行为）
- 不清理 `tests/fixtures/subjects/SolutionCorePack/` 下的生成产物（非源码）
- 不改动 `wiki/` 文档（后续单独更新）

## 4. 阶段列表

### Phase 1: SDK 与关键修复

修复会导致编译失败的 breakage，确保 NuGet 包与源码一致。

### Phase 2: Python 代码生成器清理

更新 `test_code_generator.py` 和 `native_code_generator.py`，不再生成旧属性。

### Phase 3: 存量 .cs 文件清理

删除/更新所有使用旧属性的 .cs 文件（auto-generated + handwritten），转换为新模式。

### Phase 4: Pipeline 脚本与测试更新

更新 `build/toolchains/` 中的 pipeline 脚本和 Python 单元测试。

### Phase 5: 发布 SDK + 收口

Rebuild NuGet 包，运行自测验证，确保无回归。

## 5. 每阶段完成定义

### Phase 1: SDK 与关键修复

| 字段 | 内容 |
|------|------|
| **goal** | 确保 SDK 源码干净，NuGet 包与源码一致，修复唯一会编译失败的文件 |
| **exit_criteria** | `dotnet build Chaos.TestFramework.Sdk` 成功；`dotnet build Chaos.TestFramework.Runtime` 成功；NuGet 包在 `testing/_packages/` 中已更新 |
| **deliverables** | 更新的 NuGet 包；`ArithmeticPatch.cs` 转为使用 `[HotUpdate]` |
| **dependencies** | 无 |
| **resolved_decisions** | SDK 源码中旧属性类型已删除；NuGet 包需重新 build 发布；`ArithmeticPatch.cs` 是唯一被编译且会 break 的文件 |
| **watch_items** | NuGet 缓存可能未更新导致 CI 失败；注意 `~/.nuget/packages/chaos.testframework.sdk/0.1.0/` 是否同步 |

### Phase 2: Python 代码生成器清理

| 字段 | 内容 |
|------|------|
| **goal** | 更新 `test_code_generator.py` 只生成 `[Fact]` / `[Benchmark]` / `[HotUpdate]` + `Assert.*` 模式；更新 `native_code_generator.py` 移除旧属性引用 |
| **exit_criteria** | `generated_source()` 不再输出任何旧属性；Python 语法检查通过；unit tests 全部 pass |
| **deliverables** | 修改后的 `test_code_generator.py`；修改后的 `native_code_generator.py` |
| **dependencies** | Phase 1 |
| **resolved_decisions** | 新生成模式 = 只保留 `[Fact]` / `[Benchmark]` / `[HotUpdate]` 三个 marker attribute，所有元数据通过 method name 约定路由；`[MethodSubjectId]` 和 `[CapabilityFamilyId]` 由调用方通过 JSON contract 提供，不再编码到 attribute 中 |
| **watch_items** | 调用 `generated_source()` 的地方是否都兼容新签名；`VerificationRoute` 移除后是否影响路由逻辑 |

### Phase 3: 存量 .cs 文件清理

| 字段 | 内容 |
|------|------|
| **goal** | 删除所有 `.AutoGenerated.cs` 文件（14 个），删除或重写所有使用旧属性的 benchmark/host/patch 手写文件（12 个） |
| **exit_criteria** | 所有旧属性文件已物理删除或重写；`git grep -E "CapabilityFamilyId|BenchmarkSubjectId|BenchmarkRoute|BenchmarkProfile|MethodSubjectId|VerificationRoute|HotUpdateSubjectId|HotUpdateDirection" -- "*.cs"` 在 `testing/foundation-dll/` 下返回空 |
| **deliverables** | 删除 14 个 `.AutoGenerated.cs`；更新 12 个手写文件 |
| **dependencies** | Phase 2（因为需要新生成器来重新生成内容） |
| **resolved_decisions** | 手写 benchmark/host/patch 文件如果实现与 SDK 中已有逻辑重复可直接删除；如果有独特逻辑，需改为仅使用新 attribute 模式 |
| **watch_items** | 删除文件前确认确实未被任何 csproj 引用；`ImmutableSortedSet.cs` 的 `partial class` 拆分是否有影响 |

### Phase 4: Pipeline 脚本与测试更新

| 字段 | 内容 |
|------|------|
| **goal** | 更新 `build/toolchains/` 中的 pipeline 脚本移除旧属性匹配逻辑；更新 Python unit tests 适配新的生成器输出 |
| **exit_criteria** | `python -m pytest tests/verification/unit/` 全部通过 |
| **deliverables** | 更新的 `foundation_dll_audit_generator.py`；更新的 `subject_reporting.py`；更新的 `project_workspace.py`；更新的 3 个 test files |
| **dependencies** | Phase 2 |
| **resolved_decisions** | Pipeline 脚本中的旧属性匹配应改为匹配新的 attribute 名或 method 命名约定 |
| **watch_items** | `subject_reporting.py` 的接口变更是否影响上游调用方 |

### Phase 5: 发布 SDK + 收口

| 字段 | 内容 |
|------|------|
| **goal** | 重新 build `Chaos.TestFramework.Sdk` NuGet 包并发布到 `testing/_packages/`，清理 NuGet 缓存，运行 pipeline 确认无回归 |
| **exit_criteria** | NuGet 包重新发布；CI pipeline 通过 |
| **deliverables** | 新 NuGet 包；CI 绿色 |
| **dependencies** | Phase 1-4 |
| **resolved_decisions** | 包版本仍为 `0.1.0`（不 bump 版本号，当前为开发阶段，无兼容性要求） |
| **watch_items** | 全局 NuGet 缓存可能被锁定；Windows 文件锁导致 build 失败 |

## 8. 风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| NuGet 缓存未同步导致 CI 使用旧 DLL | 中 | 高 | Phase 5 中增加 `nuget locals all -clear` + 重新 restore |
| Auto-generated .cs 文件被某些 csproj 隐式包含 | 低 | 高 | 删除前检查所有 csproj 确认 `EnableDefaultCompileItems=false` 或明确排除 |
| `partial class` 拆分导致删除 auto-generated 文件后编译失败 | 中 | 中 | 删除前检查对应 .cs 文件是否依赖 partial 拆分 |
| `benchmark/` 下的手写文件有独特逻辑需要迁移 | 中 | 中 | Phase 3 中逐个 review，有独特逻辑的手动重写 |
| Windows 文件锁导致 NuGet 包替换失败 | 低 | 低 | Phase 5 中使用 temp 文件 + MoveFileExW 策略 |

## 9. 备选路径

- **如果 T3 发现某些 `.AutoGenerated.cs` 确实被 csproj 引用**（当前审计显示未被引用）：暂停删除，改为更新生成器重新生成新格式文件
- **如果 T4 的 pipeline 脚本改动影响生产 pipeline**：切换到 `--dry-run` 模式先验证匹配结果
- **如果 T5 的 CI 因 NuGet 缓存问题失败**：在 CI 脚本中添加 `dotnet nuget locals all --clear` 步骤

## 10. 当前建议推进顺序

串行推进：T1 → T2 → T3 → T4 → T5
