# il2cpp-mainline

## 主题说明

- 这一组文档专门承接 IL2CPP 主线的长期讨论。
- 先有总骨架，再围绕阶段边界、优先级、平台策略和输入兼容逐层细化。

- `20260408-18-phase-a-method-semantic-body-contract-v1-01.md`

- `20260408-19-phase-a-method-semantic-body-well-formedness-v1-01.md`

- `20260408-20-phase-a-semantic-world-diagnostics-contract-v1-01.md`
  - 继续冻结 `SemanticWorld` 的 structured diagnostics contract，比较异常/日志、structured diagnostics + error 阻断、以及允许 downstream 部分消费 invalid body 三种路线，并推荐 `Phase A` 采用 semantic-scope diagnostics、与 `Linker`/`CodeGen` 明确分层、且 `error` 阻断 `Linker` 消费的强边界方案。
- `20260408-21-phase-a-semantic-world-output-contract-v1-01.md`

- `20260408-22-phase-a-capability-bundle-contract-v1-01.md`
  - 继续冻结 `CapabilityBundles` 的正式 contract，比较 method-only、method + world aggregate、任意 subject 粒度 capability 三种路线，并推荐 `Phase A` 采用 method-level primary bundles 加 world-slice aggregate bundle 的方案，同时收口首轮 shared capability vocabulary 与 capability/operation 边界。
- `20260408-23-phase-a-semantic-shapes-contract-v1-01.md`
  - 继续冻结 `SemanticShapes` 的正式 contract，比较平面 shape 名字表、按 subject kind 分族的 typed shapes、以及依赖下游隐式推断三种路线，并推荐 `Phase A` 采用 `TypeShape / FieldShape / MethodShape` 三族最小 shape family，同时明确 `MethodShape = Role + BodyAvailability` 且 `entry` 不属于 semantic shape。
- `20260408-24-phase-a-canonical-subjects-contract-v1-01.md`
  - 继续冻结 `CanonicalSubjects` 的正式 contract，比较极薄 typed id 集合、typed subject family + 显式 declaring graph + 轻量 `MemberId` 投影、以及统一 generalized subject graph 三种路线，并推荐 `Phase A` 采用 `TypeId / MethodId / FieldId` 作为 primary canonical subject family、把 `MemberId` 定位为 field/method 的 umbrella projection，同时明确 owner/declaring 关系属于 `CanonicalSubjects` 且 definition identity 与 closed instantiation identity 分层处理。
- `20260408-25-phase-a-stable-metadata-lookup-boundary-v1-01.md`
  - 继续冻结 `stable metadata lookup` 的正式边界，比较把 metadata 塞回 canonical output、定义独立的 definition-level companion lookup、以及支持 instantiated-context 查询三种路线，并推荐 `Phase A` 采用 canonical-id keyed 的 definition-level lookup 边界，同时明确它不是第七块 canonical output、不能回推 semantic facts、也不承接 closed generic context。
- `20260408-26-phase-a-generated-native-performance-first-governing-decisions-v1-01.md`
  - 将性能优先 review 的发现直接提升为主导性决策，正式确立“generated native 工程性能最优”为后续核心层架构的最高目标之一，同时保留 `SemanticWorld` 六块 canonical output 与 definition-only 边界，并新增 `OptimizationFacts` 作为 `LinkedWorld -> CodeGen` 的 first-class 性能导向合同，且把 `LoweringFamily` 选择主规则修正为“合法性过滤 + 性能裁决”。
