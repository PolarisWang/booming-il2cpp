# 语义漂移守卫方案 — 从"字节 diff"升级到"行为验证"

> 2026-08-27 · 承接 drift-prevention-comprehensive-report.md。
> 需求：守卫要能**主动提示代码/语义漂移**，不只抓机械漂移。
> 诚实前提：语义漂移无字节 oracle，但**有行为 oracle**——本仓已存在的
> 编译器、契约/权威测试、stub-audit 机制都可当 oracle。方案据此设计。

---

## 〇、核心思想

机械 diff 抓 L1/L2。语义漂移（L3/L4）只能靠"**行为 oracle**"：
任何 AI 改动，若与 oracle 冲突 → 就是语义漂移信号。本仓已有的 oracle：

| Oracle | 是什么 | 能抓的语义漂移 |
|--------|--------|---------------|
| **编译器/链接器** | 引用符号必须存在、签名匹配 | 符号存在但实现缺失 / 签名漂移 |
| **契约/权威测试** | `tests/authority/contracts/*` 不变式 | 需求-实现语义漂移 |
| **stub-audit** | `verification_codegen_stubs.py` | stub 与真实实现的覆盖 gap |
| **static_assert / 数值不变** | 生成物内建断言 | 数量/值漂移 |

---

## 方案 ①：链接/签名契约门（抓"符号存在但实现缺失"——本仓真实炸过）
**现实依据**：memory 记录过 `OverrideUnresolvedExternalRuntimeEntries` 0xC0000005 —— stub 在 fn-table
里、但没有真实 C++ 实现（符号漂移→运行崩）。`kMaxOverrides` 常量 vs 数组 bound 不符。

**做法**：pre-commit 第 8 道 `[symbol-contract]`：
- 对 staged 的 native C++，跑 `nm`/编译期审计：**extern 声明/引用 的符号，必须有对应定义**。
- 复用 `verification_codegen_stubs.py` 的 stub 清单：对比"引用了但只有 stub 无真实实现"的符号→报。
- 常量-vs-bound：扫 `#define`/`constexpr` 与数组边界不匹配（如 kMaxX vs array[N]）。

**收益**：直接抓到实际 crash 的语义漂移形态。
**成本**：中；需 nm/审计脚本（会跑得慢）。
**风险**：extern 定义跨 TU 的前向声明会误报（需白名单 extern-C 桥）。

---

## 方案 ②：行为锚测试门（抓"AI 重写后行为变了"）
**现实依据**：本仓已有 `tests/authority/contracts/*`（identity/model/obligation 不变式）+ 单测。

**做法**：为**关键语义**（解释器 opcode 派发、枚举映射、GC 不变式、stub return 语义）
建"行为锚"最小测试集，挂 pre-commit：
- 每个锚 = 一个"输入→期望输出"的确定性用例。
- AI 重写逻辑 → 锚失败 = 语义漂移信号（不靠 diff，靠行为）。

**收益**：对 AI 手写逻辑（无 oracle 的 L3）提供**行为** oracle。
**成本**：中高；需人先定义锚（或从现有单测挑选已有锚）。
**风险**：低；纯加测试。锚太少则覆盖弱（先覆盖有 crash 历史的域：interpreter/GC/stubs）。

---

## 方案 ③：生成器输出签名 hash（抓"生成器迭代导致的漂移/误报"）
**现实依据**：我在 drift 守卫里被 whitespace 误报复扰；AI 改生成器输出格式=假漂移。

**做法**：
- 记录每个**生成器的自身 hash**（+ 输入 schema hash）→ 生成物。
- drift 守卫区分两种失败：
  - **"生成器没变、输入没变、但输出变了"** = 真漂移（env/repo 被手改）。
  - **"生成器或 schema 变了"** = 生成器迭代（需人确认是否同步重生成，非事故）。
- 这样守卫**少误报**，把信号集中到真正的文件漂移。

**收益**：解 AI 生成器迭代的假阳，让守卫信号可信。
**成本**：低；只在 registry 加 hash 字段 + 守卫比对。
**风险**：低。

---

## 方案 ④：开箱语义标签 + 提交策略（治理辅助）
**做法**：
- README/规约：AI 改动**生成物**必须"重生成提交"，禁止手改 `.generated.*`（git blame 威慑）。
- 在生成物头部加"`// generated by X (hash) — do not hand-edit`"，diff/守卫读到即知。
- CI 加"生成物手改检测"：若 `.generated.*` 的 diff 无法用对应生成器重生成复现 → 拦。

**收益**：从源头减少 AI 手改生成物。
**成本**：最低。
**风险**：低。

---

## 五、权衡与推荐

| | ①符号契约 | ②行为锚 | ③生成器hash | ④治理 |
|---|---|---|---|---|
| 抓真实语义漂移 | 高(符号/链接) | 高(行为) | 中(去误报) | 中(源头) |
| 对 AI 手写无 oracle 逻辑 | 无用 | ✅有价值 | 无用 | 部分 |
| 成本 | 中 | 中高 | 低 | 最低 |
| 风险 | 中(前向声明白名单) | 低 | 低 | 低 |

> **推荐组合**：
> - **③（生成器 hash 去误报）先做**——守卫可信是前提。
> - **②（行为锚）+ ①（符号契约）主推**——②对 AI 手写逻辑提供真行为 oracle，
>   ① 直接抓论文提到的 crash 形态。
> - **④ 兜底治理**。
>
> **诚实边界**：② 的锚需要人定义，AI 仓里这是**持续投入**（每加一域语义，补一锚）。
> ①③④ 是一次性机制。真正防 L3/L4，靠的是"锚测试 + 编译门 + 人"，守卫提供信号、不替代判断。
