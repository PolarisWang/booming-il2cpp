# 托管线程模型与 GC 协作

> 托管线程的标识、创建、生命周期管理、Monitor 轻量锁、GC 协作以及原生线程池基础。所有代码位于 `chaos_runtime_core` 模块的 `thread_state.*`、`thread_pool.*` 以及 `runtime_core.cpp` 中。

## 线程标识

### 整体架构

| 组件 | 位置 | 职责 |
|------|------|------|
| `ManagedThread` struct | `thread_state.h` | 线程描述符（TLS + 全局链表） |
| TLS 变量 | `thread_state.cpp` | O(1) 自身份查询 |
| Lock-free 全局链表 | `thread_state.cpp` | GC 与调试器线程枚举 |

### 核心设计

每个托管线程在 `RegisterThread()` 时分配一个 `ManagedThread`，并通过 TLS 指针实现 O(1) 自身份查询：

```cpp
thread_local ManagedThread* tls_this_thread  = nullptr;
thread_local int32_t        tls_this_thread_id = kMainThreadId;  // 主线程 = 1

inline int32_t GetCurrentThreadId() noexcept { return tls_this_thread_id; }
```

### 注册与反注册

```cpp
void RegisterThread(int32_t managed_id, void* managed_obj);
void UnregisterThread();
```

- `RegisterThread`: 分配 `ManagedThread` → 发布 TLS → CAS 插入全局链表头部
- `UnregisterThread`: 仅标记 `is_running = false`，不从链表中移除（避免 ABA 问题）

### 线程枚举

```cpp
void EnumerateThreads(bool (*callback)(ManagedThread*)) noexcept;
int32_t GetThreadCount() noexcept;
```

## Monitor 轻量锁 (Thin Lock)

### 架构

| 组件 | 文件 | 职责 |
|------|------|------|
| ObjectHeader::sync_state | `runtime_core.cpp` | 64-bit 锁状态字 |
| Thin lock fast path | `runtime_core.cpp` | CAS 无竞争上锁（O(1)） |
| SyncBlock inflation | `runtime_core.cpp` | 竞争时膨胀到带互斥量的 SyncBlock |
| SyncBlockStripe table | `runtime_core.cpp` | 64 桶并发安全的 SyncBlock 映射 |

### sync_state 编码

```
bits [1:0] 锁状态: 00=free, 01=thin, 10=inflated, 11=reserved
bits [31:2] thin lock: thread_id (29 bits) / inflated: SyncBlock*
bits [63:32] recursion count (thin lock 模式)
```

### ObjectHeader 布局 (B2+, 56 字节)

```cpp
struct ObjectHeader {
    const void**    vtable      = nullptr;  // B2+ O(1) dispatch (8 字节)
    const TypeInfo* type_info   = nullptr;   // 类型身份 (8 字节)
    uint64_t        sync_state  = 0;         // 轻量锁状态 (8 字节)
    unsigned char   field_storage[32];        // 字段存储
};
```

### MonitorEnter 快速路径

```cpp
if ((sync & kSyncLockedBit) == 0) {
    // Free → CAS acquire
    if (AtomicCAS(&header->sync_state, sync, kSyncLockedBit | tid_bits,
                  __ATOMIC_ACQUIRE, __ATOMIC_RELAXED))
        return true;
}
```

### SyncBlock Inflation

当自旋 `kSyncBlockSpinMax` (1000) 次后竞争仍未解决：

1. 分配 `SyncBlock`（内含 `std::recursive_mutex`）
2. 在 64 槽 striped 映射表中注册
3. 原子地将 `sync_state` 标记为 inflated
4. 在 `SyncBlock::mutex` 上阻塞

### MonitorExit

```cpp
// Inflated → SyncBlock::unlock
// Thin: recursion > 0 → decrement; recursion == 0 → final release
```

## Hybrid GC Safepoint

### 设计原则

| 路径 | 实现 | 说明 |
|------|------|------|
| 托管代码 | 显式 `SafepointPoll()` | 在循环回边、方法调用处插入 |
| 原生 AOT 帧 | bdwgc 保守扫描 | 无显式 poll，由 GC 保守扫描栈 |

### API

```cpp
// 每个安全点调用（循环回边、调用点）
void SafepointPoll() noexcept;

// GC 线程：请求所有托管线程进入安全点
uint32_t RequestGlobalSafepoint() noexcept;

// GC 线程：释放所有线程
void ReleaseGlobalSafepoint(uint32_t generation) noexcept;
```

### 实现机制

`SafepointPoll()` 检查全局原子标志 `s_safepoint_active_gen`，若为非零：
1. 设置线程级 `ManagedThread::at_safepoint = true`
2. 自旋（`std::this_thread::yield`）直到标志归零
3. 恢复 `at_safepoint = false` 并更新 `safepoint_generation`

### 与 ObjectHeader 的关系

```cpp
struct ManagedThread {
    int32_t                  managed_id;
    void*                    managed_object;
    bool                     is_running;
    std::atomic<ManagedThread*> next;
    // GC safepoint 协作
    bool                     at_safepoint{false};
    uint32_t                 safepoint_generation{0};
};
```

## ThreadPool 基础

### 架构

| 组件 | 文件 | 说明 |
|------|------|------|
| WorkItem struct | `thread_pool.cpp` | callback + context |
| FIFO 队列 | `thread_pool.cpp` | `std::queue<WorkItem>` (mutex 保护) |
| Worker 线程 | `thread_pool.cpp` | `WorkerLoop` 自动注册 + 等待工作 |
| Gate 线程 | `thread_pool.cpp` | 定时器线程（500ms 周期） |

### API

```cpp
void ThreadPoolInitialize() noexcept;
void ThreadPoolShutdown() noexcept;
void ThreadPoolQueueUserWorkItem(void (*callback)(void*), void* context) noexcept;
int32_t ThreadPoolWorkerCount() noexcept;

constexpr int32_t kThreadPoolMinWorkerCount = 1;
constexpr int32_t kThreadPoolMaxWorkerCount = 32;
```

### 工作线程生命周期

1. `WorkerLoop` 自动调用 `RegisterThread()` 获取托管身份
2. 在 `std::condition_variable` 上等待新工作
3. 执行回调（锁外）
4. shutdown 信号到达时退出循环并反注册

### 线程数量调整

- 初始: `kThreadPoolMinWorkerCount (1)`
- 队列深度超过活跃线程数时增长（上限 32）
- Gate 线程每隔 500ms 检查：空闲时收缩，繁忙时扩张
