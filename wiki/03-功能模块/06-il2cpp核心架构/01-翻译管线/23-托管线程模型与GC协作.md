# 托管线程模型与 GC 协作

> 托管线程的标识、创建、生命周期管理、Monitor 轻量锁、GC 协作、线程池、同步原语以及信令原语。所有代码位于 `chaos_runtime_core` 模块的 `thread_state.*`、`thread_pool.*`、`synchronization.*`、`wait_handle.*`、`timer_queue.*` 以及 `runtime_stubs/` 中。

## 线程标识

### 整体架构

| 组件 | 位置 | 职责 |
|------|------|------|
| `ManagedThread` struct | `thread_state.h` | 线程描述符（TLS + 全局链表） |
| TLS 变量 | `thread_state.cpp` | O(1) 自身份查询 |
| Lock-free 全局链表 | `thread_state.cpp` | GC 与调试器线程枚举 |

### 核心设计

每个托管线程在 `RegisterThread()` 时分配一个 `ManagedThread`，并通过 TLS 指针实现 O(1) 自身份查询：

```cpp
thread_local ManagedThread* tls_this_thread  = nullptr;
thread_local int32_t        tls_this_thread_id = kMainThreadId;  // 主线程 = 1

inline int32_t GetCurrentThreadId() noexcept { return tls_this_thread_id; }
```

### ManagedThread 结构体

```cpp
struct ManagedThread {
    int32_t                  managed_id;          // 唯一线程 ID (main = 1)
    void*                    managed_object;      // System.Thread 引用
    bool                     is_running;          // false after UnregisterThread
    bool                     is_background;       // Thread.IsBackground
    std::atomic<ManagedThread*> next;             // 无锁链表链接
    std::atomic<uint32_t>    gc_mode{0};          // 0=COOPERATIVE, 1=PREEMPTIVE
    uint32_t                 last_seen_gen{0};    // 最后确认的 generation
    std::atomic<bool>        pending_abort{false};    // Thread.Abort 待处理
    std::atomic<bool>        pending_interrupt{false}; // Thread.Interrupt 待处理
    void* stack_base{nullptr};   // 栈高地址
    void* stack_limit{nullptr};  // 栈低地址
};
```

### 注册与反注册

```cpp
void RegisterThread(int32_t managed_id, void* managed_obj);
void UnregisterThread();
```

- `RegisterThread`: 分配 `ManagedThread` → 发布 TLS → CAS 插入全局链表头部
- `UnregisterThread`: 仅标记 `is_running = false`，不从链表中移除（避免 ABA 问题）

### 线程枚举

```cpp
void EnumerateThreads(bool (*callback)(ManagedThread*)) noexcept;
int32_t GetThreadCount() noexcept;
```

### Thread.Abort 机制

通过 safepoint 系统实现：
1. `chaos_thread_abort()` 设置目标线程的 `pending_abort = true`
2. 目标线程在下次 `SafepointPoll()` 时检测到标志
3. 在 unlikely 分支中抛出 `chaos_managed_exception`

### Thread.Interrupt 机制

与 Thread.Abort 相同的 safepoint 模式：
1. `chaos_thread_interrupt()` 设置目标线程的 `pending_interrupt = true`
2. 目标线程在下次 `SafepointPoll()` 时检测到标志并抛出

## Monitor 轻量锁 (Thin Lock)

### 架构

| 组件 | 文件 | 职责 |
|------|------|------|
| ObjectHeader::sync_state | `core/monitor.cpp` | 64-bit 锁状态字 |
| Thin lock fast path | `core/monitor.cpp` | CAS 无竞争上锁（O(1)） |
| SyncBlock inflation | `core/monitor.cpp` | 竞争时膨胀到带互斥量的 SyncBlock |
| SyncBlockStripe table | `core/monitor.cpp` | 64 桶并发安全的 SyncBlock 映射 |

### sync_state 编码

```
bits [1:0] 锁状态: 00=free, 01=thin, 10=inflated, 11=reserved
bits [31:2] thin lock: thread_id (29 bits) / inflated: SyncBlock*
bits [63:32] recursion count (thin lock 模式)
```

| API | 实现 | 说明 |
|-----|------|------|
| `MonitorEnter()` | 完整 | Thin lock → spin → inflate 三级路径 |
| `MonitorExit()` | 完整 | 处理递归释放、inflated 路径 |
| `MonitorTryEnter()` | 完整 | 带超时的 ABI 版本：`ChaosMonitorTryEnter` |
| `Monitor.Wait()` | 完整 | 膨胀到 SyncBlock→cond.wait() |
| `Monitor.Pulse()` | 完整 | 委托给 SyncBlock→cond.notify_one() |
| `Monitor.PulseAll()` | 完整 | 委托给 SyncBlock→cond.notify_all() |

### MonitorEnter 快速路径

```cpp
if ((sync & kSyncLockedBit) == 0) {
    // Free → CAS acquire
    if (AtomicCAS(&header->sync_state, sync, kSyncLockedBit | tid_bits,
                  __ATOMIC_ACQUIRE, __ATOMIC_RELAXED))
        return true;
}
```

### SyncBlock Inflation

当自旋 `kSyncBlockSpinMax` 次后竞争仍未解决：
1. 分配 `SyncBlock`（内含 `std::recursive_mutex` + `std::condition_variable`）
2. 在 64 槽 striped 映射表中注册
3. 原子地将 `sync_state` 标记为 inflated
4. 在 `SyncBlock::mutex` 上阻塞

## 信令原语

### WaitHandle（wait_handle.h/.cpp）

支持 ManualResetEvent 和 AutoResetEvent 两种类型，最大 2048 个句柄。

| API | 说明 |
|-----|------|
| `WaitHandleCreate(initial_state, type)` | 创建等待句柄 |
| `WaitHandleClose(handle_id)` | 关闭句柄 |
| `WaitHandleSet(handle_id)` | 设置为信令状态 |
| `WaitHandleReset(handle_id)` | 重置为非信令状态 |
| `WaitHandleWaitOne(handle_id, timeout_ms)` | 等待单个句柄 |
| `WaitHandleWaitAny(handle_ids, count, timeout_ms)` | 等待任意句柄 |
| `WaitHandleWaitAll(handle_ids, count, timeout_ms)` | 等待所有句柄 |

### 类型语义

- **ManualResetEvent**: Set 保持信令状态直到 Reset，notify_all 唤醒所有等待者
- **AutoResetEvent**: Set 唤醒一个等待者并自动重置，notify_one 唤醒单个等待者

### WaitAny/WaitAll 实现

使用 `std::condition_variable` 实现，无轮询。每个等待句柄关联一个 condition_variable；WaitAny 在多个 cv 上等待（通过通知计数 + atomic 状态 + `notify_one`/`notify_all` 协调），WaitAll 在所有 cv 都触发后返回。

- WaitAny: 对所有候选句柄注册监听，任意句柄 Set 时唤醒等待线程
- WaitAll: 对所有候选句柄注册监听，所有句柄均 Set 后唤醒等待线程
- 支持超时（通过 `wait_for`）和跨线程信令

### Hill-Climbing 调度

- 8 样本移动平均窗口
- 吞吐量启发式：改进→添加工作者，下降→回退，空闲→收缩
- Gate 线程 500ms tick 中调用 `HillClimbingController::OnGateTick(completed_count)`

### IOCP 集成（Windows）

```
ThreadPoolInitializeIOCP() → CreateIoCompletionPort()
IOCPThreadLoop() → GetQueuedCompletionStatus() → QueueUserWorkItem(callback, context)
```

### 工作线程生命周期

1. `WorkerLoop` 自动调用 `RegisterThread()` 获取托管身份
2. 在 `std::condition_variable` 上等待新工作
3. 执行回调（锁外）
4. shutdown 信号到达时退出循环并反注册

## ExecutionContext / AsyncLocal

### 架构

| 组件 | 文件 | 职责 |
|------|------|------|
| `AsyncLocalMap` | `execution_context.cpp` | 线程本地 AsyncLocal 值存储（小数组回退模式） |
| `ExecutionContext` struct | `execution_context.h` | 捕获的 AsyncLocal 值快照（内联存储 + 堆分配回退） |
| `ExecutionContextCapture()` | `execution_context.cpp` | 快照当前线程的 AsyncLocal 值 |
| `ExecutionContextRun()` | `execution_context.cpp` | 临时安装上下文值，调用回调，恢复原值 |
| `ExecutionContextFree()` | `execution_context.cpp` | 释放上下文（处理堆分配数组） |

### 设计要点

- **零成本优化**：无 AsyncLocal 值时 `ExecutionContextCapture()` 返回 nullptr
- **小数组回退**：1-4 个值使用内联存储（无堆分配），5+ 使用堆分配数组（罕见）
- **Thread.Start 集成**：`chaos_thread_start()` 在创建线程前捕获 ExecutionContext，在新线程中运行委托前恢复
- **ThreadPool 集成**：`WorkerLoop` 在每次执行工作项时捕获并恢复 ExecutionContext
- **Task.Run 集成**：`TaskRun()` 在排队前捕获 ExecutionContext，在回调中通过 `ExecutionContextRun()` 恢复

### API


## Hybrid GC Safepoint

### 设计原则

| 路径 | 实现 | 说明 |
|------|------|------|
| 托管代码 | 显式 `SafepointPoll()` | 在循环回边、方法调用处插入 |
| 原生 AOT 帧 | CRAG 保守扫描 | 无显式 poll，由 GC 保守扫描栈 |

### Generation-based 快速路径（Scheme C）

```cpp
// 全局原子 generation 计数器
// LSB 翻转表示 GC 请求
// 快速路径：~1ns（单次 atomic load + compare）
bool SafepointRequested() noexcept {
    return (s_generation.load(std::memory_order_relaxed) & 1) == 0;
}
```

### SafepointPoll 完整路径

```cpp
void SafepointPoll() noexcept {
    // 快速路径：检查 generation LSB（~1ns）
    if (CHAOS_IL2CPP_LIKELY(lsb(s_generation) != 0)) return;

    // ── pending_abort 检查（unlikely 分支）──
    if (thread != nullptr && thread->pending_abort.load(std::memory_order_acquire)) {
        thread->pending_abort.store(false, std::memory_order_release);
        throw chaos_managed_exception{0};
    }

    // ── pending_interrupt 检查（unlikely 分支）──
    if (thread != nullptr && thread->pending_interrupt.load(std::memory_order_acquire)) {
        thread->pending_interrupt.store(false, std::memory_order_release);
        throw chaos_managed_exception{0};
    }

    // GC safepoint spin...
}
```

### API

```cpp
void SafepointPoll() noexcept;
uint32_t RequestGlobalSafepoint() noexcept;
void ReleaseGlobalSafepoint(uint32_t generation) noexcept;
void GcScanAllThreadRoots(void (*callback)(void*, bool, void*), void* user_data) noexcept;
```
