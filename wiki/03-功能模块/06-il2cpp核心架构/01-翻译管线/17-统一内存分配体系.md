# 统一内存分配体系

## 概述

IL2CPP native AOT 生成代码涉及三种隔离的分配域：GC 托管堆、Domain 模块堆、原始 C++ 堆。
本设计通过 `CHAOS_IL2CPP_*` 宏体系统一所有分配入口，确保：
- 生成代码（codegen 输出）可被直接引入游戏引擎源码，无全局 `operator new` 污染
- 分配策略可在 A→B→C 三阶段无缝切换，codegen 输出无需修改
- 三种分配域的边界清晰，不会出现跨域分配/free 不匹配

## 三域模型

| 分配域 | 用途 | 生命周期 | 回收方式 | 当前实现 |
|--------|------|---------|---------|---------|
| **GC 域** | 托管对象、数组、字符串、装箱值 | GC 控制 | 自动回收 | `GC_MALLOC` / `GcBumpCache` |
| **Domain 域** | 模块元数据、运行时内部结构 | 模块生命周期 | 模块卸载时批量 `Destroy()` | Windows: `HeapCreate` / `HeapAlloc`；非 Windows: mmap region + bump alloc |
| **Raw 域** | 临时缓冲区、vtable 数组、非 GC 内部结构 | 显式管理 | `free()` / `delete` | `std::malloc` / `std::free` |

## 宏接口定义

所有宏定义位于 `src/native/common/chaos/native_types.h`，以 `CHAOS_IL2CPP_` 为前缀。

### GC 域分配（codegen 主目标）

```cpp
// ========== GC 域（托管对象/数组） ==========
// 分配 + 构造 GC 跟踪对象。返回 T*，内存由 GC 管理。
// 使用 placement new，不依赖全局 operator new 重载。
#define CHAOS_IL2CPP_NEW_GC(T, ...) \
    ::new (chaos::il2cpp::runtime_core::GcAllocate(sizeof(T))) T{__VA_ARGS__}

// 分配 + 构造 GC 非扫描对象（不含指针的数据，如 string UTF-8 字节）
#define CHAOS_IL2CPP_NEW_GC_ATOMIC(T, ...) \
    ::new (chaos::il2cpp::runtime_core::GcAllocateAtomic(sizeof(T))) T{__VA_ARGS__}

// 分配零初始化 GC 数组元素（POD 类型，已由 GC_MALLOC 归零）
#define CHAOS_IL2CPP_NEW_GC_ARRAY(T, count) \
    static_cast<T*>(chaos::il2cpp::runtime_core::GcAllocate(sizeof(T) * (count)))
```

### Domain 域分配（运行时模块元数据）

```cpp
// ========== Domain 域（模块元数据/运行时内部结构） ==========
// 分配 + 构造。内存由模块卸载时的 heap->Destroy() 批量回收，
// 正常情况下无需单独 free。
#define CHAOS_IL2CPP_DOMAIN_ALLOCATE(domain, size) \
    ((domain)->heap->Allocate(size))

#define CHAOS_IL2CPP_DOMAIN_NEW(domain, T, ...) \
    ::new ((domain)->heap->Allocate(sizeof(T))) T{__VA_ARGS__}

// 通过当前 TLS 域分配（无需显式传递 domain）
// 无 domain 上下文时 fallback 到 std::malloc（安全处理 AOT root 场景）
#define CHAOS_IL2CPP_DOMAIN_CURRENT_ALLOCATE(size)                             \
    (::chaos::il2cpp::memory_domain::CurrentDomain()                           \
         ? ::chaos::il2cpp::memory_domain::CurrentDomain()->heap->Allocate(size) \
         : CHAOS_IL2CPP_MALLOC(size))

#define CHAOS_IL2CPP_DOMAIN_CURRENT_NEW(T, ...) \
    ::new (CHAOS_IL2CPP_DOMAIN_CURRENT_ALLOCATE(sizeof(T))) T{__VA_ARGS__}

// 通过当前域释放（仅用于错误回退路径；正常路径无需释放）
#define CHAOS_IL2CPP_DOMAIN_CURRENT_FREE(ptr)                                  \
    do {                                                                        \
        if (::chaos::il2cpp::memory_domain::CurrentDomain())                    \
            ::chaos::il2cpp::memory_domain::CurrentDomain()->heap->Free(ptr);    \
        else                                                                    \
            CHAOS_IL2CPP_FREE(ptr);                                             \
    } while (false)
```

### Raw 域分配（临时/非 GC 结构）

```cpp
// ========== Raw 域（临时/非 GC 结构） ==========
// 已有宏保持不变，语义等同于 std::malloc/free/realloc
#define CHAOS_IL2CPP_MALLOC(s)     std::malloc(s)
#define CHAOS_IL2CPP_FREE(p)       std::free(p)
#define CHAOS_IL2CPP_REALLOC(p,s)  std::realloc(p, s)
```

### 派生便捷宏

```cpp
// ========== 类型擦除版本（用于 codegen 不确定类型的场景） ==========
#define CHAOS_IL2CPP_NEW_GC_PTR(type_expr, size_expr) \
    ::new (chaos::il2cpp::runtime_core::GcAllocate(size_expr)) type_expr

// ========== 字符串专用分配（UTF-8 字节缓冲区，GC 非扫描域） ==========
#define CHAOS_IL2CPP_NEW_GC_STRING_BUF(count) \
    static_cast<char*>(chaos::il2cpp::runtime_core::GcAllocateAtomic(count))
```

## 使用规范

### codegen 输出规则

| IL 指令 | 当前生成 | 替换为 |
|---------|---------|--------|
| `newobj` → 引用类型 | `new chaos_type_T{}` | `CHAOS_IL2CPP_NEW_GC(chaos_type_T, {})` |
| `newobj` → 委托类型 | `new chaos_delegate_subclass_T{}` | `CHAOS_IL2CPP_NEW_GC(chaos_delegate_subclass_T, {})` |
| `newarr` | `new chaos_managed_array{}` | `CHAOS_IL2CPP_NEW_GC(chaos_managed_array, {})` |
| `newarr` → elements | `new CHAOS_IL2CPP_INTPTR[N]{}` | `CHAOS_IL2CPP_NEW_GC_ARRAY(CHAOS_IL2CPP_INTPTR, N)` |
| `newobj` → 值类型 | 栈分配（不变） | 不变 |
| `box` → 标量 | 栈分配（不变） | 不变 |
| 字符串构造 | `GcAllocate(sizeof(String))` + `GcAllocateAtomic(n)` | `CHAOS_IL2CPP_NEW_GC(chaos_string_type, ...)` |

### 运行时代码规则

| 场景 | 使用宏 |
|------|--------|
| 模块注册时创建 meta 对象 | `CHAOS_IL2CPP_DOMAIN_NEW(domain, T, ...)` |
| 运行时内部临时 buffer | `CHAOS_IL2CPP_MALLOC(size)` |
| 运行时内部临时对象 | `CHAOS_IL2CPP_NEW(T)`（栈或用 raw 域） |
| 跨模块调用时分配 | 通过 TLS domain stack 隐式标记 |

### 禁止模式（项目级约束）

| 禁止 | 原因 |
|------|------|
| 全局 `operator new` / `operator delete` 重载 | 生成代码会引入游戏引擎，全局重载污染引擎分配行为 |
| codegen 生成裸 `new T{}` / `new T[N]` | 必须使用 `CHAOS_IL2CPP_NEW_GC` / `CHAOS_IL2CPP_NEW_GC_ARRAY` |
| codegen 生成裸 `malloc` / `free` | 必须使用 `CHAOS_IL2CPP_MALLOC` / `CHAOS_IL2CPP_FREE` |
| 跨域 `free`（如用 `std::free` 释放 GC 内存） | 各域内存必须由对应回收机制释放 |
| 使用 `new (ptr) T` 时未包含 `<new>` | placement new 需要 `<new>` 头文件 |

## 阶段演进（A → B → C）

### A 阶段：Bump Arena（当前）

宏展开目标：
```
CHAOS_IL2CPP_NEW_GC(T, {...})
  → GcAllocate(sizeof(T))          // TLS GcBumpCache
  → placement new 构造
```

**特点：**
- 线程本地 bump pointer 缓存（GcBumpCache），无锁分配常见大小
- 缓存 miss 回退到 BDWGC `GC_MALLOC`
- 所有对象通过 BDWGC 回收
- 无分代、无压缩
- 宏定义固定，不依赖运行时配置

### B 阶段：Thread-Local GC Bump Cache（已实现 = A阶段实际就是B）

当前实现即 Phase B：GcBumpCache 已实现并激活，作为 `tls_gc_arena` 线程局部变量部署在 `runtime_core.cpp`。`GcAllocate` / `GcAllocateAtomic` 直接委托给 `tls_gc_arena`。

### C 阶段：区域感知分代垃圾回收器（CRAG）

宏展开目标（同上，透明切换）：
```
CHAOS_IL2CPP_NEW_GC(T, {...})
  → GcAllocate(sizeof(T))          // CRAG: Region-aware GC
  → placement new 构造
```

**特点：**
- 区域（Region）驱动的分代收集，统一 GC/Domain/Raw 三域分配器
- 精确扫描栈/寄存器根，消除 BDWGC 保守扫描的假指针问题
- 年轻代 + 老年代两点分代
- Card table 写屏障同时服务跨代和跨域引用追踪
- **热更新域卸载 = O(region) 批量释放，不支持逐个对象清理**
- 宏接口不变，codegen 输出无需修改
- 详见 `docs/dev/designs/c-phase-region-aware-generational-gc.md`

### 阶段切换原则

1. **codegen 零改动** — 宏定义和 `GcAllocate` 内部实现切换，codegen 输出不变
2. **逐步替换** — 每个阶段可独立部署和验证
3. **兼容层** — B 阶段兼容 A 阶段的 GC_MALLOC 对象；C 阶段兼容 B 阶段的 TLS 缓存
