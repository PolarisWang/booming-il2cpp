# 泛型执行模型

## GenericContextShapeKind

3 种泛型上下文形状：

| Kind | 描述 | 存储方式 |
|------|------|---------|
| None | 非泛型方法 | 不需要上下文 |
| ByStaticStorage | 封闭泛型实例化 | 全局静态存储 |
| ByContext | 开放泛型（运行时决策） | 运行时传递 context 参数 |

## 封闭泛型实例化

- 封闭泛型类型/方法在 AOT 编译期完全实例化
- 每个封闭实例化生成独立的 C++ 函数
- Method handle 通过 `resolve_method_by_token` 解析

## 双路径执行架构（Gen-2 Handle）

本系统采用双路径设计处理泛型执行：

```
────────────────────────────────────────────────────────────
  快路径（AOT 泛型）:  慢路径（运行时 MakeGenericType）
────────────────────────────────────────────────────────────
  Codegen 发射静态      先查 GenericContextRegistry
  数据数组                      │
      ↓                命中 ←──┴──→ 未命中
  Bootstrap                     │
  token→handle 解析        返回 handle     ↓
      ↓                              Interpreted Fallback
  GenericContextRegistry              │
  (handle-based O(1) 查询)            ↓
      │                          构造 RuntimeInstantiatedType
      │                          (heap-allocated descriptor)
      │                                  │
      │                          注册到 Registry
      │                                  │
      └────────── 后续调用 ──────────────┘
                走快路径
────────────────────────────────────────────────────────────
```

### 快路径：AOT 编译的泛型

- Codegen 发射纯数据常数组（`GenericTypeRegistrationEntryV0[]`）
- `MetadataRegistrationV0` 嵌入指向这些数组的指针
- `BootstrapRuntime()` 调用 `RegisterModuleGenerics()`：
  - 对每个条目调用 `resolve_type_by_token()` 将 token 解析为 `TypeInfoHandle`
  - 以 handle 为 key 注册到 `GenericContextRegistry`
- 查询：`TypeInfoHandle` 指针比较，O(1)

### 慢路径：运行时泛型

- `MakeGenericType` / `MakeGenericMethod` 通过 `RuntimeInstantiationBridgeV0` 调用
- 先查 `GenericContextRegistry`，命中直接返回 handle
- 未命中 → `RuntimeInstantiateType` 在堆上构造封闭类型：
  1. 分配 `RuntimeInstantiatedType` 结构
  2. 构建封闭的 `ReflectionQueryTypeDescriptor`（subject_id、token 等）
  3. 对值类型计算 `value_size` 和 `field_offsets`
  4. 为每个方法创建解释器存根
  5. 注册到 `GenericContextRegistry`
- 后续调用走快路径

## 运行时 Token 分配

运行时泛型类型需要唯一的 metadata token。AOT token 空间为 0x00000000–0x7FFFFFFF，运行时 token 从 0x80000000 开始分配：

```cpp
static std::atomic<CHAOS_IL2CPP_UINT32> s_next_runtime_token{0x80000000u};

CHAOS_IL2CPP_UINT32 AllocateRuntimeToken() {
    return s_next_runtime_token.fetch_add(1u, std::memory_order_relaxed);
}
```

这确保了 AOT 编译期生成的 token 与运行时分配的 token 不会冲突。

## RuntimeInstantiationEngine

运行时泛型实例化引擎，负责 MakeGenericType / MakeGenericMethod 的执行：

### 核心结构

```cpp
struct RuntimeInstantiatedType {
    ReflectionQueryTypeDescriptor descriptor;    // 堆分配的封闭描述符
    TypeInfoHandle* type_args;                   // 类型参数 handle 数组
    CHAOS_IL2CPP_UINT32  arg_count;
    CHAOS_IL2CPP_UINT32  value_size;            // 值类型 sizeof(T)
    CHAOS_IL2CPP_UINT32* field_offsets;          // 字段偏移数组
    CHAOS_IL2CPP_UINT32  field_offset_count;
    CHAOS_IL2CPP_UINT32  module_id;              // 所属模块（0 = AOT root）
    bool is_registered;                          // 是否已注册到 GenericContextRegistry
};
```

RuntimeInstantiatedType 不存储独立的方法存根。方法元数据直接从开放泛型类型的 `ReflectionQueryTypeDescriptor` 引用（`descriptor.methods = open_desc->methods`）。

### 关键函数

| 函数 | 说明 |
|------|------|
| `AllocateRuntimeToken()` | 分配运行时唯一 token（0x80000000 起始） |
| `BuildClosedDescriptor(open_type_handle, type_args, arg_count)` | 堆分配 RuntimeInstantiatedType，构造封闭 subject_id、display_name，生成 runtime token |
| `BuildClosedSubjectId(open_desc, type_args, arg_count)` | 构造封闭类型的 subject_id，格式 `OpenType`N[Arg1,Arg2,...]` |
| `ComputeValueTypeLayout(rt_type)` | 运行时计算值类型 size 和 field_offsets（按指针宽度顺序布局） |
| `ResolveOrInstantiateType(open_type, type_args, count)` | 先查 registry 快路径，未命中再走 BuildClosedDescriptor 慢路径 |
| `ResolveOrInstantiateMethod(open_method, type_args, count)` | 方法泛型实例化（Phase 5 预留，返回 nullptr） |
| `UnregisterModuleGenerics(module_id)` | 按模块清理：注销注册表中的条目并释放所有关联的 RuntimeInstantiatedType 堆内存 |
| `GetBridgeV0()` | 返回 RuntimeInstantiationBridgeV0 实例 |

### ABI 桥接

`RuntimeInstantiationBridgeV0` 作为独立 bridge 导出，与 `CodegenBridgeV0` / `RuntimeAbiV0` 同级。通过 `chaos_runtime_instantiation_get_bridge_v0()` 获取。

## 约束

- **AOT 泛型**：不允许在运行时动态实例化开放泛型 → 严格控制快路径
- **运行时泛型**：方法体走 IL 解释器，性能低于 AOT。允许 MakeGenericType / MakeGenericMethod
- 泛型共享（generic sharing）不做，每个封闭实例化独立生成
- 泛型虚方法需要完整的类型 hierarchy 展开（vtable registry 支持运行时 token）

## 运行时注册与解析

C++ 端 `generic_context` 子系统处理泛型实例化的运行时注册和查询：

### 关键函数（Handle-Based API）

| 函数 | 说明 |
|------|------|
| `RegisterGenericInstantiation(open_handle, closed_handle, type_args_handles, count)` | 开放泛型 handle + 类型参数 handle → 封闭 handle |
| `RegisterMethodGenericContext(method_token, class_type_args_handles, method_type_args_handles)` | 关联类型参数和方法参数（handle 数组） |
| `GetGenericContextForMethod(method_token)` | 查询方法的泛型上下文 |
| `GetClassTypeArg(context, index)` | 从上下文中查询类类型参数 |
| `GetMethodTypeArg(context, index)` | 从上下文中查询方法类型参数 |
| `RegisterModuleGenerics(ModuleGenericRegistrationV0)` | 按模块批量注册 |
| `UnregisterModuleGenerics(module_id)` | 按模块清理泛型注册 |

### Registry 内部结构

```cpp
GenericContextRegistry {
    CHAOS_IL2CPP_UNORDERED_MAP(TypeInfoHandle, InstantiationVector) by_open_type;
    CHAOS_IL2CPP_UNORDERED_MAP(uint32_t, MethodGenericContextEntry*) by_method_token;
    CHAOS_IL2CPP_UNORDERED_MAP(uint32_t, TypeInfoVector) types_by_module;   // hotupdate
    CHAOS_IL2CPP_UNORDERED_MAP(uint32_t, TokenVector) methods_by_module;    // hotupdate
}
```

### 与 codegen 的关系

- 对 AOT 编译中遇到的每个封闭泛型实例化（如 `List<int>`），codegen 发射纯数据数组，bootstrap 时注册
- 对泛型方法实例化，发射 `GenericMethodRegistrationEntryV0` 数组
- 运行时 `typeof(T)` 或 `MakeGenericMethod` 通过 `RuntimeInstantiationBridgeV0` 解析
