### Hotpatch 注册数据结构

`CodegenBridgeV0` 同时定义了 Hotpatch dispatch 的注册数据类型：

| 结构 | 用途 |
|------|------|
| `CodeRegistrationV0` | 方法指针表 + reverse PInvoke + invoker + vtable 统合注册 |
| `MetadataRegistrationV0` | 泛型实例化 + field offset + metadata usage |
| `CodegenRegistrationOptionsV0` | image_name 等注册选项 |
| `HotpatchEntryV0` | dispatch 表条目（direct_ptr + interrupt_ptr + method_key + flags） |
| `HotpatchTypeEntryV0` / `HotpatchMethodEntryV0` | 类型/方法名索引（PatchLoader NameIndex 查找） |
| `HotpatchSlotEntryV0` | token→dispatch slot 反向映射 |
| `HotpatchModuleV0` | 每模块注册束 |
| `ModuleGenericRegistrationV0` | 模块级泛型注册束（含 AOT entries） |

### AotDirectFn Table

除了 Hotpatch dispatch 表，codegen 还生成 AotDirectFn table 供 interpreter 的 direct_fn 快速路径：

```cpp
// codegen 在 native-aot.generated.cpp 中生成
extern "C" const void* kAotDirectFnTable[];
extern "C" const char* kAotSubjectIds[];
```

通过 `ChaosRegisterDirectFnTable()` 注册到 runtime-core，`aot_core_ir_reader.cpp` 的 `ResolveDirectFn` 回调在反序列化时通过 subjectId 查找对应的 direct_fn 指针。

### IRInstruction::direct_fn

每个 Call 指令的 `direct_fn` 在 `DeserializeAotCoreIr` 时设置：

```
ResolveDirectFn(callee_subjectId)
  → kAotDirectFnTable 二分查找
  → 找到: instr.direct_fn = fn_ptr
          instr.direct_ret_tag = InferValueTagFromReturnTypeName(...)
  → 未找到: instr.direct_fn = nullptr (走 dispatch callback 路径)
```

状态码：`CHAOS_BRIDGE_STATUS_OK`(0) 至 `CHAOS_BRIDGE_STATUS_RUNTIME_CALL_FAILED`(16)。

## 版本兼容性

AOT 主包版本与热更新补丁版本的 compatibility band 定义：

- **版本格式**：`major.minor.patch`
- **compatibility band**：`major.minor` 相同视为兼容
- **major 不同**：不兼容（破坏性架构变更）
- **minor 不同**：默认不兼容，除非显式兼容矩阵放宽
- **patch 不同**：仍兼容

## 功能支持状态词汇

跨文档使用统一的四个状态：

| 状态 | 含义 |
|------|------|
| `supported` | 在声明范围内有稳定证据，且无已知降级 |
| `partial` | 有证据，但只覆盖部分平台、模式或语义子集（必须带 reason code） |
| `unsupported` | 当前明确不支持（必须带 reason code） |
| `not-applicable` | 对该 subject/archetype/mode 不适用 |

Reason code 分类：`platform_host_gap` / `toolchain_gap` / `runtime_gap` / `metadata_gap` / `compatibility_gap` / `policy_blocked` / `scope_not_targeted`。
