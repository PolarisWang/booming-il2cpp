# 反射查询模型（AOT 反射数据）

## 核心职责

不可变的、基于描述符的反射元数据模型。所有反射数据（类型、字段、方法、属性、参数）编码为扁平描述符结构体，由 AOT 编译器预先布局并通过指针标记句柄访问。

## 关键类型

| 类型 | 说明 |
|------|------|
| `ReflectionQueryImageDescriptor` | 每程序集顶层描述符（包含类型数组） |
| `ReflectionQueryTypeDescriptor` | token、SubjectId、名称、泛型定义链接、子数组 |
| `ReflectionQueryFieldDescriptor` | 字段描述符（DeclaringType、FieldName、MetadataToken） |
| `ReflectionQueryMethodDescriptor` | 方法描述符（MethodSubjectId、MethodName、ParameterNames 等） |
| `ReflectionQueryPropertyDescriptor` | 属性描述符 |
| `ReflectionQueryParameterDescriptor` | 参数描述符 |

## 句柄编码

使用高位标记（`kReflectionQueryHandleTag`）区分描述符指针和其他句柄类型：
- `EncodeReflectionQueryHandle(ptr)` — 给指针打标记
- `TryDecodeReflectionQueryHandle(handle)` — 解标记验证

## 查找函数

| 函数 | 说明 |
|------|------|
| `FindReflectionQueryTypeByToken(image, token)` | 按 token 查找类型 |
| `FindReflectionQueryTypeByName(image, name)` | 按名称查找类型 |
| `FindReflectionQueryFieldByToken(type, token)` | 按 token 查找字段 |
| `FindReflectionQueryMethodByToken(type, token)` | 按 token 查找方法 |
| `FindReflectionQueryField(type, name)` | 按名称查找字段 |
| `FindReflectionQueryMethod(type, name)` | 按名称查找方法 |

## 与 codegen 的关系

- AOT 编译器为每个模块发射一个 `ReflectionQueryImageDescriptor`，完全填充嵌套描述符树为 `const` 数据
- 返回给托管代码的句柄（TypeInfoHandle、MethodInfoHandle）仅是此只读数据的标记指针
- `typeof()`、`FieldInfo.GetValue()`、`MethodInfo.Invoke()` 等操作直接解码句柄
- 无需堆分配、无需惰性填充——反射就是 AOT 数据的一次指针解引用

## Planner 的物化模型

Planner 侧的对应模型：
- `AssemblyReflectionSupportModel` — 按程序集索引的类型列表
- `ReflectionMemberSupportModel` — 类型条目（TypeSubjectId、TypeName、GenericDefinitionTypeSubjectId 等）

## B2 架构变更（Module Registry + Two-Tier）

在 B2 架构中，句柄编码从标记指针改为 `(module_id, token)` uint64_t 编码，替代原有的 TLS `g_current_aot_image` + constexpr 全表模式。

### 变更要点

| 维度 | 原方案 | B2 方案 |
|------|--------|---------|
| TypeInfoHandle | `void*`（标记指针） | `uint64_t`（module_id << 32 \| token） |
| 模块寻址 | `thread_local g_current_aot_image` | 全局 `ModuleDescriptor g_modules[64]` |
| 每 DLL 元数据 | 全量 `ReflectionQueryTypeDescriptor[]` | Tier 1 flags + Tier 2 条件生成 |
| 跨 DLL 类型身份 | 指针不等 | `(module_id, token)` 自描述 |

### 分层元数据（Two-Tier）

- **Tier 1**（总是生成）：`type_flags[]`、`type_names[]`、`type_namespaces[]`、`type_parent_tokens[]`，每类型 ~16 bytes
- **Tier 2**（条件生成）：完整 `ReflectionQueryTypeDescriptor` + methods/fields 数组，仅当 family 使用 GetMethods/GetFields/Invoke 等冷路径时生成

### 与旧模型的关系

- `ReflectionQueryImageDescriptor` 保留用于 Tier 2 冷路径，Tier 1 热路径绕过它直接查 registry flags
- `FindReflectionQueryTypeByToken` / `FindReflectionQueryFieldByToken` 等查找函数改为通过 Module Registry 路由
- `ReflectionQueryImageDescriptor` 改由 `ModuleRegistry.image` 指针访问，不再是 TLS

详细架构决策见 [历史决策/14-B2-ModuleRegistry-TwoTier](../04-历史决策/14-B2-ModuleRegistry-TwoTier-%E5%86%B3%E7%AD%96.md)。
