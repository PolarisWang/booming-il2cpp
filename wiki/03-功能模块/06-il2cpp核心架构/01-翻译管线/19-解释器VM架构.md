# 解释器 VM 架构

## 核心职责

基于栈的 IL 解释器，运行时执行 IR 指令。是热更新路径的 fallback 执行引擎。

## IR Opcode（78 个）

原始 54 个 opcode（LdcI4=0 ~ Ret=53）在 Phase A 中扩展了 24 个新 opcode，覆盖 ECMA 335 完整指令集。

| 类别 | Opcode 集合 |
|------|-----------|
| 加载 | `LdcI4`, `LdcI8`, `LdcR4`, `LdcR8`, `Ldstr`, `Ldnull`, `Ldarg`, `Ldloc`, `Ldloca`, `Ldarga`, `Ldind`, `Ldobj` |
| 存储 | `Starg`, `Stloc`, `Stind`, `Stobj` |
| 字段 | `Ldfld`, `Stfld`, `Ldsfld`, `Stsfld` |
| 数组 | `NewArr`, `Ldlen`, `Ldelem`, `Stelem`, `Ldelema` |
| 调用 | `Call`, `Callvirt`, `NewObj`, `Ldftn`, `Ldvirtftn`, `Calli`, `Ret` |
| 对象 | `Box`, `Unbox`, `CastClass`, `IsInst` |
| 类型转换 | `ConvI4`, `ConvI8`, `ConvR4`, `ConvR8`, `ConvRUn`, `ConvI`, `ConvU`, `ConvOvf` |
| 分支 | `Br`, `Brtrue`, `Brfalse`, conditional branches, `Switch` |
| 比较 | `Ceq`, `Cgt`, `Clt` |
| 算术 | `Add`, `Sub`, `Mul`, `Div`, `DivUn`, `Rem`, `RemUn`, `Neg`, `And`, `Or`, `Xor`, `Not` |
| 移位 | `Shl`, `Shr`, `ShrUn` |
| 异常 | `Throw`, `Rethrow`, `Leave`, `EndFinally`, `EndFilter` |
| 杂项 | `Dup`, `Pop`, `LdToken`, `InitObj`, `SizeOf`, `LocAlloc` |

## 关键类型

| 类型 | 说明 |
|------|------|
| `InterpreterValue` | 带 tag 的联合体（i32/i64/f32/f64/obj），含类型工厂方法 |
| `InterpreterObject` | 轻量对象存储，含 type_token 字段支持虚方法分派 |
| `IRInstruction` | opcode + operand index + immediates + branch target + string operand + secondary_index |
| `IRMethod` | IR 指令向量 + SEH clause 向量 |
| `ExecutionFrame` | 参数 + 局部变量 + 求值栈的独立向量 |
| `ExecutionResult` | 执行结果（正常/异常/外部派发） |

## 执行模型

```
IRMethod → InterpreterVM::Execute(IRMethod, ExecutionFrame) → ExecutionResult
```

- 纯栈机——无寄存器
- InterpreterValue 带 tag 跟踪类型
- 支持完整的 EH（throw/rethrow/leave/endfinally/endfilter），使用两阶段模型（搜索→展开→处理）
- 对象模型基于堆分配（InterpreterObject、ArrayStorage、BoxedValue）
- 虚方法分派通过 `vtable_registry::ResolveVirtualMethodPointer` 实现

### EH 两阶段模型

1. **Phase 1（搜索）**：`Throw`/`Rethrow` 时在 SEH clause 列表上反向扫描，寻找匹配的 catch handler
2. **Phase 2（展开）**：找到 catch 后，收集中间的所有 finally/fault handler 依次执行，最后转移控制权到 catch handler
3. **跨帧传播**：当前方法未找到 catch 时，`ExecutionResult.threw_exception = true` 返回给调用者

### 虚方法分派

`CallVirt` 使用 `vtable_registry` 在执行期解析：
1. 从 `this` 对象的 `type_token` 获取实例类型
2. 调用 `ResolveVirtualMethodPointer(instance_type_token, declared_method_token)`
3. 沿继承链向上查找最近的重写实现
4. 结果存入 `call_target` 供外部派发

## 与热更新的关系

- 热更新加载补丁 IL 后，可编译为 IRMethod
- 通过 `method_replacement` 表将 AOT 方法重定向到解释器执行
- 解释器作为 fallback 执行引擎
