# 解释器 VM 架构

## 核心职责

基于栈的 IL 解释器，运行时执行 IR 指令，支持 5 级执行管线。是热更新路径的 fallback 执行引擎，也是 JIT 未覆盖方法的默认执行方式。

## 5 级执行管线

| 层级 | 名称 | 执行模型 | 数据表示 | 调用开销 | 触发条件 |
|------|------|---------|---------|---------|---------|
| T1 | FastExecute | 栈机（computed-goto） | FastFrame（扁平数组） | ~30ns | 首次调用 |
| T2 | FastExecute + direct_fn | 栈机（computed-goto） | FastFrame（扁平数组） | ~30ns | `direct_fn` 解析命中 |
| T3 | RegisterExecute | 寄存器机（虚拟寄存器） | RegisterFrame（r0-r95） | ~15ns | Tier promotion + IR reg alloc |
| T4 | Quick JIT | 本地代码栈帧 | x86-64 / ARM64 原生栈帧 | ~3ns | 热点计数过阈值 |
| T5 | Full JIT (Opt) | 本地代码（优化后） | x86-64 / ARM64 原生栈帧 | ~3ns | 优化编译就绪 |

升级路径：T1 → T2 → T3 → T4 → T5（由 `tier_manager::EvaluateTierPromotion` 控制）。

降级路径：任何层级可通过 OSR（On-Stack Replacement）回退到 T1-T3。

## 关键类型

### FastFrame（T1/T2 执行帧）

`src/native/runtime-core/fast_dispatch.h`

基于**扁平数组**的栈帧，取代旧版 `ExecutionFrame` 的 `std::vector<InterpreterValue>`。消除堆分配和间接寻址：

```cpp
struct FastFrame {
    uint32_t frame_type;          // 0x54534146u ("FAST" LE) — GC scanner 辨识
    uint64_t stack[64];           // 求值栈值（纯位模式）
    uint8_t  stack_tags[64];      // 每 slot 的 ValueTag
    uint64_t locals[32];          // 局部变量
    uint8_t  local_tags[32];      // 局部变量 tag
    uint32_t sp;                  // 栈顶指针
    uint32_t local_count;         // 局部变量数量
    uint32_t arg_count;           // 参数数量
    // ...
    // 返回值
    uint64_t ret_val;
    uint8_t  ret_tag;
    bool     has_ret;
    // 异常状态
    bool     threw_exception;
    uint64_t exception_obj_val;
    // 调用分发
    void*    dispatch_fn;
    void*    dispatch_ctx;
    // 调用缓存
    CachedCallInfo* call_cache;
    uint32_t call_count;
    // 执行控制
    uint32_t pc;                  // 程序计数器
    void*    patch_method;        // Tier 状态访问（OSR backedge）
    int32_t  loop_counter;        // 循环 backedge 计数
    bool     osr_reenable;        // T4 deopt 后首次 backedge 立即 OSR
    // SEH 状态
    SEHClause* seh_clauses;
    // 跟踪对象（解释器堆对象生命周期管理）
    void*    tracked_objs[32];
    DtorFn   tracked_dtors[32];
    bool     tracked_is_pool[32];
    uint32_t tracked_cnt;
};
```

ValueTag 枚举：

| Tag | 值 | 含义 |
|-----|-----|------|
| `Int32` | 0 | 32 位整数 |
| `Int64` | 1 | 64 位整数 |
| `Float32` | 2 | 32 位浮点 |
| `Float64` | 3 | 64 位浮点 |
| `ObjectRef` | 4 | 对象引用 |
| `Null` | 5 | 空引用 |
| `ValueType` | 6 | 值类型 |

### RegisterFrame（T3 执行帧）

`src/native/interpreter/ir_reg_alloc.h`

基于寄存器文件的执行帧，指令直接操作虚拟寄存器而非栈：

```cpp
struct RegisterFrame {
    uint32_t frame_type;          // 0x00474552u ("REG\0" LE)
    RegisterFile regs;            // 统一寄存器文件
    //   - uint64_t gpr[64] + uint8_t gpr_tags[64]   ← GP 寄存器
    //   - uint64_t fpr[32] + uint8_t fpr_tags[32]   ← FP 寄存器
    uint8_t* args;                // 参数字节
    uint32_t arg_count;
    // ...（返回值、异常、SEH、跟踪对象等与 FastFrame 类似）
};
```

### RegisterInstruction（T3 指令编码）

16 字节、cache-line 友好：

```cpp
struct RegisterInstruction {
    uint64_t header;              // op_code(16) | dst_reg(8) | src1_reg(8)
                                  // | src2_reg(8) | flags(8) | call_arg_cnt(15) | is_inst(1)
    union imm {                   // 8 字节联合体
        int32_t i4;
        int64_t i8;
        double  r8;
        void*   ptr;              // call_target / direct_fn / string / switch_targets
        size_t  branch_target;
        uint32_t operand_index;
        // ...
    };
};
```

IRInstruction（104 字节）到 RegisterInstruction（16 字节）的压缩比为 **6.5:1**。

### IRInstruction（中间表示）

`src/native/interpreter/interpreter_vm.h`

```cpp
struct IRInstruction {
    IROpCode op_code = IROpCode::Ret;
    int32_t  operand_index = 0;
    int32_t  immediate_i4 = 0;
    size_t   branch_target = 0;
    int64_t  immediate_i8 = 0;
    double   immediate_r8 = 0.0;
    const char* string_operand = nullptr;
    size_t   field_offset = 0;
    size_t   secondary_index = 0;
    void*    call_target = nullptr;
    uint32_t arg_count = 0u;
    bool     is_instance_call = false;
    void*   direct_fn = nullptr;           // 预解析的 AOT 函数指针
    uint8_t direct_ret_tag = 0xFF;         // direct_fn 返回值的 ValueTag
    const size_t* switch_targets = nullptr;
    size_t        switch_target_count = 0u;
};
```

### OsrState（OSR 状态捕获）

`src/native/interpreter/osr_state.h`

Move-only 结构体，用于不同执行层级之间的状态转移：

```cpp
struct OsrState {
    static constexpr uint32_t kMaxStack = 64;
    static constexpr uint32_t kMaxLocals = 32;
    static constexpr uint32_t kMaxTracked = 32;

    uint32_t pc = 0;
    uint32_t sp = 0;
    uint64_t stack[kMaxStack]{};
    uint8_t  stack_tags[kMaxStack]{};
    uint64_t locals[kMaxLocals]{};
    uint8_t  local_tags[kMaxLocals]{};
    uint32_t local_count = 0;
    // 跟踪对象（TCB 所有权）
    void*    tracked_objs[kMaxTracked]{};
    DtorFn   tracked_dtors[kMaxTracked]{};
    uint32_t tracked_cnt = 0;
};
```

非拷贝、仅移动。析构函数自动清理跟踪对象。

## 寄存器分配器

`src/native/interpreter/ir_reg_alloc.cpp` — `AllocateRegisters()`

### 算法

Linear-scan 寄存器分配器。将基于栈的 IRMethod 转换为基于寄存器的 RegisterMethod：

1. **虚拟栈模拟**：顺序扫描每条 IR 指令，维护虚拟栈（`virt_stack[256]`，`virt_sp`）
2. **寄存器分配约定**：
   - r0-r7 = 参数寄存器（映射自 LdArg operand_index）
   - r8-r15 = 局部变量专用寄存器（r8 = local[0], r9 = local[1], etc.）
   - r16+ = 求值栈虚拟寄存器（顺序分配，`next_vreg` 从 16 起始）
3. **指令编码**：为每条 IR 指令生成 RegisterInstruction：
   - push 指令（LdcI4等）：分配 dst_reg = next_vreg++，压入 virt_stack
   - pop 指令（Add等）：从 virt_stack 弹出 src_reg，分配 dst_reg
   - store 指令（StLoc等）：直接写入 r8+N，标记 `kRegIsStore`
   - branch 指令：保留 branch_target，设置 `kRegIsBranch`
   - call 指令：设置 `kRegIsCall`，参数数量编码在 header
4. **最大寄存器数**：`result.max_regs = next_vreg`（已分配虚拟寄存器数量）
5. **SEH 子句**：原样复制到 RegisterMethod

### 输出

```cpp
RegisterMethod AllocateRegisters(const IRMethod& ir_method) noexcept;
```

返回 `RegisterMethod`，包含：
- 压缩后的 `RegisterInstruction` 向量
- 每条指令处的栈映射（`RegStackMapEntry`：slot→寄存器映射，用于 OSR）
- SEH 子句（索引不变）
- IL offset 映射

## 执行引擎

### T1: FastExecute — 栈机（Computed-Goto）

`src/native/runtime-core/fast_dispatch*.cpp`

基于 computed-goto 的分派循环，直接操作 FastFrame 的扁平数组：

```
FastExecute 主循环:
  while (true) {
      instr = &frame.ir_instrs[frame.pc];
      DISPATCH_CASE(opcode):
          // 每个 handler 直接读写 frame.stack/frame.locals
          frame.pc++;
          NEXT();  // computed goto
  }
```

特点：
- **扁平数组**：`uint64_t stack[64]` + `uint8_t stack_tags[64]`，无堆分配、无虚函数
- **Computed-goto**：GCC 扩展 `&&label` + `goto*`，单次分派 ~2ns
- **直接返回值**：通过 `frame.ret_val` / `frame.ret_tag`，无需 `DispatchResult`
- **SEH 内联处理**：Throw/Leave/EndFinally 直接在循环内处理两阶段展开，无需外部 try/catch
- **CachedCallInfo**：内联调用缓存（MIC），重复调用时跳过 MethodTable 查找

### T2: FastExecute + direct_fn

当 IR 预编译阶段成功解析出 `direct_fn`（通过 `kAotDirectFnTable` 或 `ResolveMethodTable`），Call 指令的执行路径从 ~2200ns（InterpreterDispatchRaw）降至 ~30ns（直接函数指针调用）：

```
Call 指令（direct_fn != nullptr）:
  ├─ 从 frame.stack 弹出参数 → 原生类型转换
  ├─ reinterpret_cast<DirectFn>(instr.direct_fn)(args...)
  ├─ try/catch chaos_managed_exception（SEH 方法需要）
  └─ 按 direct_ret_tag 确定返回值类型，push 到 frame.stack
```

`direct_fn` 在 `patch_method_lower.cpp` 中通过以下方式解析：
1. 检查 subjectId 是否在 `kAotDirectFnTable` 中
2. 未命中时尝试 `ResolveMethodTable(method_token)`
3. 解析成功则设置 `IRInstruction.direct_fn` 和 `direct_ret_tag`
4. 如果所有调用的 direct_fn 都命中，该方法可跳过 InterpreterVM 直接执行

### T3: RegisterExecute — 寄存器机

`src/native/interpreter/ir_reg_alloc.cpp`

基于寄存器文件的执行引擎，将 IR 寄存器分配结果直接执行：

```
RegisterExecute 主循环:
  while (true) {
      instr = &rm.instructions[frame.pc];
      switch (instr.op_code()):
          // 每个 handler 直接读写 RegisterFrame.regs.gpr[] / .fpr[]
          GPR[dst] = GPR[src1] + GPR[src2];
          frame.pc++;
  }
```

特点：
- 消除栈操作（push/pop）：指令直接编码源和目标寄存器
- 寄存器文件分 GP（r0-r63）和 FP（r64-r95）
- 每条指令 16 字节，L1 cache 命中率更高
- SEH 方法同样支持，但执行模式是寄存器机而非栈机

### MIC（Multiple Invocation Count）

`src/native/runtime-core/fast_dispatch_call.cpp`

Call/CallVirt 的内联调用缓存，基于调用方 + 槽位签名来缓存 vtable 解析结果，避免重复的 `ResolveVirtualMethodPointer` 查找：

- `CachedCallInfo`：每个 call site 一个，缓存目标函数指针和类型检查结果
- `call_count`：帧级计数，跟踪分配的缓存数量
- `Handle_Call` / `Handle_CallVirt`：先查缓存，未命中则调用 `ResolveMethodTable`
- 缓存写回：T3 RegisterExecute 时直接写入 `RegisterFrame.call_cache`

## OSR（On-Stack Replacement）

`src/native/interpreter/osr_state.cpp`

在不同执行层级之间的热转移，无需方法返回：

```
OSR 方向                Capture → OsrState → Restore
─────────────────────────────────────────────────────
T1/T2 (FastExecute)  →  T3 (RegisterExecute)    ↑ 升级
T3 (RegisterExecute) →  T1 (FastExecute)         ↓ 降级
T4 (Native Code)     →  T1/T3 (Interpreter)      ↓ 降级（Deopt）
FastExecute ↔ VM     →  双向                     ←→ fallback
```

关键转换函数：

| 函数 | 源 | 目标 | 场景 |
|------|-----|------|------|
| `CaptureFastFrame` | FastFrame | OsrState | T1→T3 升级 |
| `RestoreOsrToFastFrame` | OsrState | FastFrame | T3→T1 降级 |
| `CaptureRegisterFrame` | RegisterFrame + RegStackMapEntry | OsrState | T3→T1 降级 |
| `RestoreOsrToRegisterFrame` | OsrState + RegStackMapEntry | RegisterFrame | T1→T3 升级 |
| `CaptureNativeFrame` | gpr_file + fpr_file + RegStackMapEntry | OsrState | T4→T1/T3 降级（Deopt）|

所有权转移规则：
- `Capture*` 函数**转移**跟踪对象所有权（源帧 `tracked_cnt` 归零）
- `Restore*` 函数**接收**跟踪对象所有权（目标帧负责析构）
- `OsrState` 析构函数是安全网：未转移的跟踪对象会被自动清理

## SEH 异常处理模型

两阶段模型（所有层级通用）：

1. **Phase 1（搜索）**：`Throw`/`Rethrow` 时在 SEH clause 列表上反向扫描，寻找匹配的 catch handler
2. **Phase 2（展开）**：找到 catch 后，收集中间的所有 finally/fault handler 依次执行，最后转移控制权到 catch handler

层级差异：

| 层级 | 异常处理方式 |
|------|------------|
| T1/T2 FastExecute | 内联在 FastExecute 循环中，通过 `unwind_finally_list` / `exception_in_flight` 状态字段管理 |
| T3 RegisterExecute | 内联在 RegisterExecute 循环中，通过 RegisterFrame 的 SEH 状态字段管理 |
| T4/T5 Native Code | sigsetjmp/siglongjmp（POSIX）或 VEH（Windows）|
| InterpreterVM (legacy) | 外部 try/catch `chaos_managed_exception` |

### Opcode 分布

- **0-98**：标准 CIL 对应 opcode（99 个）
- **99**：`Calli` — 间接函数指针调用
- **100-102**：`Abs`/`Min`/`Max` — 一元算术扩展
- **103**：`StFldBarrier` — 带 GC 写屏障的字段存储
- **104-106**：`LdElemNoChk`/`StElemNoChk`/`LdElemANoChk` — 无边界检查数组操作
- **107-110**：`Simd`/`Popcnt`/`Lzcnt`/`SimdFma` — SIMD 与位操作扩展

## 与热更新的关系

- 热更新加载补丁 IL 后，编译为 IRMethod
- 通过 `method_replacement` 表将 AOT 方法重定向到解释器执行
- 解释器作为 fallback 执行引擎，确保热更新方法在任何层级均可执行
- OSR 确保热更新前后正在执行的方法可平滑转移
