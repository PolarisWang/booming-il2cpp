# 引导程序与引擎桥接

## 引导程序（Bootstrap）

### 核心职责

管理运行时的代码注册和初始状态。在 AOT 主模块加载时执行一次性的引导流程。

### BootstrapState

| 字段 | 说明 |
|------|------|
| `code_registration` | 代码生成注册表指针 |
| `metadata_registration` | 元数据注册表指针 |
| `options` | 运行时选项 |
| `aot_domain_id` | AOT 主模块的内存域 ID |

### 访问器

| 函数 | 说明 |
|------|------|
| `PeekBootstrapState()` | 读取当前引导状态 |
| `GetCodegenBridgeV0()` | 获取 codegen bridge 实例 |
| `FindRegisteredTypeCapabilityEntry()` | 查找已注册的类型能力条目 |
| `FindInvokerPointer()` | 查找调用器函数指针 |
| `FindMethodPointerByToken()` | 按 token 查找方法指针 |
| `GetAotDomainId()` | 获取 AOT 内存域 ID |

### 与 MemoryDomain 的关系

- AOT 主模块的内存域在引导期间设置
- AOT domain id 通过 `GetAotDomainId()` 全局可用

### 位置

- 模块: `chaos_bootstrap`
- 文件: `src/native/bootstrap/bootstrap.*`

## Codegen Bridge 注册流程

### RegisterCodegen + BootstrapRuntime

AOT 模块启动时依次调用两个 bridge 函数完成引导：

```
entry.exe (或 engine host) 启动
  │
  ├─ 1. RegisterCodegen(CodeRegistrationV0, MetadataRegistrationV0, Options)
  │       ├─ 注册 kAotMethods[] 方法指针表
  │       ├─ 注册 Hotpatch dispatch table (NameIndex + TokenSlot)
  │       ├─ 注册 AotDirectFn table (external runtime 函数指针)
  │       ├─ 注册泛型类型/方法实例化
  │       ├─ 注册 vtable
  │       ├─ 注册 field offsets / metadata usages
  │       └─ 设置 module.image → ReflectionQueryImageDescriptor
  │
  ├─ 2. BootstrapRuntime()
  │       ├─ 最终化运行时状态
  │       └─ 设置 BootstrapState (code_registration + metadata_registration + aot_domain_id)
  │
  └─ 引导完成 → 可执行 managed 代码
```

### Codegen 生成的数据

codegen 在 `native-aot.generated.cpp` 中生成以下数据结构：

| 数据 | 类型 | 用途 |
|------|------|------|
| `kAotMethods[]` | `void*[]` | 所有 AOT 编译方法函数指针表 |
| `g_dispatch_table[]` | `HotpatchEntryV0[]` | 热更新 dispatch 表 |
| `g_type_index[]` | `HotpatchTypeEntryV0[]` | 类型名→方法索引 |
| `g_method_index[]` | `HotpatchMethodEntryV0[]` | 方法名→token 映射 |
| `g_token_slot[]` | `HotpatchSlotEntryV0[]` | token→dispatch slot |
| `kAotDirectFnTable[]` | `void*[]` | external runtime 函数指针表 |
| `kAotSubjectIds[]` | `const char*[]` | subjectId 字符串表 |
| `CodeRegistrationV0` | struct | codegen 注册束 |
| `MetadataRegistrationV0` | struct | 元数据注册束（泛型/字段/metadata） |
| `CodegenRegistrationOptionsV0` | struct | 注册选项（image_name 等） |
| `ReflectionQueryImageDescriptor` | struct | 反射查询描述符（module.image） |

### SetAotBridge

在 `ApplyPatchFromMemory` 中调用，为 HotpatchNameRegistry 设置 bridge + aot_image：

```
ApplyPatchFromMemory(.patchdata)
  │
  ├─ 1. GetCodegenBridgeV0() → bridge
  ├─ 2. PeekBootstrapState() → code_registration
  ├─ 3. code_registration → image → ReflectionQueryImageDescriptor
  ├─ 4. HotpatchNameRegistry::SetAotBridge(bridge, aot_image_handle)
  │       └─ interpreter 的 ResolveSubjectId 通过 bridge→resolve_*_by_token 查询
  │
  └─ 5. 继续加载补丁方法
```

`SetAotBridge` 替代了旧版 `InterpreterEntryDirect::Step0_Bridge` 每次调用都设置 bridge 的方式。现在 bridge 在 patch 加载时只设置一次。

### AotDirectFn 表注册

`ChaosRegisterDirectFnTable(subjects, table, count)` 由 codegen 生成的 C++ 代码自动调用：

```cpp
// codegen 生成
extern "C" const void* kAotDirectFnTable[] = { ... };
extern "C" const char* kAotSubjectIds[] = { ... };
extern "C" const int kAotDirectFnCount = ...;

// 静态初始化时自动注册
struct AotDirectFnRegistrar {
    AotDirectFnRegistrar() {
        ChaosRegisterDirectFnTable(kAotSubjectIds, kAotDirectFnTable, kAotDirectFnCount);
    }
} g_aot_direct_fn_registrar;
```

注册后，`aot_core_ir_reader.cpp` 在 `DeserializeAotCoreIr` 的 `ResolveDirectFn` 回调中通过 subjectId 二分查找找到对应的函数指针，填入 `IRInstruction::direct_fn`。

### 三种运行场景对比

| 场景 | RegisterCodegen 调用者 | SetAotBridge 时机 | 特点 |
|------|----------------------|-------------------|------|
| **真实 host (游戏引擎)** | host 调用 `RegisterCodegen` + `BootstrapRuntime` | 内置在 BootstrapRuntime 中 | 完整 reflection query model |
| **entry.exe 测试管线** | `runtime-entry.cpp` 直接调用 `RegisterCodegen` + `BootstrapRuntime` | `ApplyPatchFromMemory` 内调用 | bypass 脚本不再剥离 code registration |
| **native unit test** | 测试 fixture 手动构造注册 | 按需调用 | 可控环境 |

## 引擎桥接（Engine Bridge）

### 核心职责

连接运行时核心和引导程序到引擎主机。实现 engine contracts（lifecycle.h、ownership.h、callback.h）的 C++ 侧。

### 桥接函数

| 函数 | 说明 |
|------|------|
| `CreateEngineObjectHandle(object)` | 创建引擎对象句柄 |
| `ResolveEngineObjectHandle(handle)` | 解析引擎对象句柄为指针 |
| `RegisterEngineLifecycleCallback(callback)` | 注册引擎生命周期回调 |
| `DispatchEngineLifecycleCallbacks(event)` | 分发生命周期事件 |
| `IsMainThreadLane()` | 检查是否为主线程通道 |

### Engine Contracts 实现

| 合约 | 桥接实现 |
|------|---------|
| `lifecycle.h` | engine_init/shutdown/reload → `RegisterEngineLifecycleCallback` + `DispatchEngineLifecycleCallbacks` |
| `ownership.h` | engine_retain/release/transfer → `CreateEngineObjectHandle` / `ResolveEngineObjectHandle` |
| `callback.h` | engine_register_callback / engine_dispatch_callback → 桥接分发 |

### 位置

- 模块: `chaos_engine_bridge`
- 文件: `src/native/engine-bridge/engine_bridge.*`
