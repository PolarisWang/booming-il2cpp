# 模式间切换指南

> AOT / JIT / Hybrid 三模式之间的切换操作指南。涵盖构建期配置、运行时检测、跨模式 dispatch 路由和平台约束。

---

## 构建期切换

三模式通过 `chaos-il2cpp convert-to-cpp` CLI 的 `--mode` 选项选择：

```bash
# AOT 模式（默认）
chaos-il2cpp convert-to-cpp --assembly GameLogic.dll --mode aot ...

# JIT 模式
chaos-il2cpp convert-to-cpp --assembly GameLogic.dll --mode jit ...

# Hybrid 模式
chaos-il2cpp convert-to-cpp --assembly GameLogic.dll --mode hybrid ...
```

### 模式输出差异

| 维度 | AOT | JIT | Hybrid |
|------|-----|-----|--------|
| C++ 函数体 | 完整编译 | AotCoreIr JSON + precode stub | 完整 C++ + AotCoreIr JSON |
| 启动入口 | 直接执行 | `RegisterJitEntryMethods()` | `RegisterHybridMethods()` |
| HotpatchEntryV0::direct_ptr | AOT 函数地址 | JIT trampoline 地址 | Hybrid trampoline 地址 |
| 运行时入口表 | — | `.jit-entries` 段 | `.jit-entries` 段 |

### JitEntry 数据结构

JIT/Hybrid 模式生成 `.jit-entries` 段包含所有方法的序列化 IR：

```c
struct JitEntry {
    uint32_t token;               // ECMA method token
    uint32_t module_id;           // 模块 ID
    uint32_t json_len;            // AotCoreIr JSON 长度
    const char* json;              // AotCoreIr JSON (RegisterMethod 输入)
};
```

`RegisterJitEntryMethods` 运行时遍历此表为每个方法创建 `JitPrecode`，设置 trampoline。

## 运行时模式检测

### CHAOS_IL2CPP_JIT_MODE 预处理器

```cpp
// hotpatch_dispatch.h — CHAOS_IL2CPP_JIT_MODE 的 dispatch 路由
#if defined(CHAOS_IL2CPP_JIT_MODE)
    // JIT 或 Hybrid 模式：direct_ptr 指向 precode trampoline
    // 首次调用通过 trampoline → dispatch → Compile()
#else
    // AOT 模式：direct_ptr 直接指向 AOT 函数
    // 调用零开销
#endif
```

### 编译器宏检测

```cpp
namespace chaos::il2cpp::jit {
    // 这些函数在 AOT 模式下为空（由 #if 守卫）
    extern "C" void RegisterJitEntryMethods(const JitEntry*, uint32_t);
    extern "C" void RegisterHybridMethods(const HybridEntry*, uint32_t);
}
```

在纯 AOT 构建中，`jit_registration.h` 中的 `RegisterJitEntryMethods`/`RegisterHybridMethods` 展开为空函数，不链接 JIT 子系统。

### 三模式 dispatch 路由总结

```
                      HotpatchEntryV0::direct_ptr
                               │
             ┌─────────────────┼──────────────────┐
             │                 │                   │
             ▼                 ▼                   ▼
           AOT函数         JIT trampoline      Hybrid trampoline
        (直接执行)             │                   │
                              ▼                   ▼
                       JitStubEntry          HybridStubEntry
                              │                   │
                              ▼                   ▼
                     JitStubDispatchImpl   HybridStubDispatchImpl
                              │                   │
                     ┌────────┴───────┐    ┌──────┴────────┐
                     │                │    │               │
                     ▼                │    │               ▼
                CAS Compile()         │    │          counter.fetch_sub
                     │                │    │               │
                     ▼                │    │         old == 1?
                  compiled.code       │    │          │       │
                     │                │    │          │       │
                     └──► direct_ptr  │    │     Compile()   │
                                      │    │          │       │
                                      │    │     direct_ptr   │
                                      │    │          │       │
                                      │    └──► compiled.code │
                                      │                 │     │
                                      └──────► aot_entry◄────┘
```

## AOT → Hybrid 过渡步骤

将现有 AOT 项目过渡到 Hybrid 模式的推荐步骤：

### 步骤 1：构建验证

```bash
# 先用 AOT 模式确认基线通过
chaos-il2cpp convert-to-cpp --assembly GameLogic.dll --mode aot
cmake -S gen/ -B gen/build && cmake --build gen/build

# 切换到 Hybrid 模式重新构建
chaos-il2cpp convert-to-cpp --assembly GameLogic.dll --mode hybrid
cmake -S gen/ -B gen/build && cmake --build gen/build
```

### 步骤 2：运行时验证

- 确认 `RegisterHybridMethods` 在启动时被调用
- 确认每个方法的 `HotpatchEntryV0::direct_ptr` 被替换为 Hybrid trampoline
- 确认冷调用返回 AOT 函数（结果与纯 AOT 一致）

### 步骤 3：升级验证

通过 Foundation-DLL Hybrid stage 14 三阶段验证：

```
阶段 1 (AOT)     → 29 次调用验证 AOT 结果正确
阶段 2 (Upgrade) → 第 30 次调用触发 JIT 编译
阶段 3 (JIT)     → 验证后续调用返回 JIT 编译结果
```

### 步骤 4：性能基线

- 对比 AOT vs Hybrid 的冷启动延迟（P50/P99）
- 对比 Hybrid 升级延迟（从首次调用到 JIT 编译完成）
- 确认无性能退化

## JIT ↔ Hybrid 互操作

两者共享同一套 JIT 编译基础设施（`jit_engine.cpp`），区别仅在 dispatch 入口：

| 场景 | JIT 模式 | Hybrid 模式 |
|------|----------|-------------|
| 冷调用 | Compile() 阻塞等待（首调用即编译） | AOT 直接执行（零等待） |
| 编译时机 | 首次调用立即触发 | 第 30 次调用触发 |
| 编译期间行为 | 调用方自旋等待 | 调用方继续执行 AOT |
| PGO 升级 | Tier 0 → Tier 1（后台线程） | Tier 0 → Tier 1（后台线程） |
| Hotpatch | direct_ptr 替换 | direct_ptr 替换（aot_entry 保留） |

### 跨模式调用链

- **AOT → JIT/Hybrid 方法**：通过 HotpatchEntryV0::direct_ptr dispatch，AOT 方完全透明
- **JIT → AOT 方法**：JIT 编译代码直接 call AOT 函数地址，零额外开销
- **Hybrid 未编译 → JIT 方法**：Hybrid 冷路径走 AOT，AOT 函数中有 direct call 到目标方法
- **JIT/Hybrid → 被 hotpatch**：slot map 更新机制保证所有 call site 在 patch 后指向新入口

## Hotpatch 与模式关系

| 场景 | AOT | JIT | Hybrid |
|------|-----|-----|--------|
| patchdata 加载 | 同 | 同 | 同 |
| 方法替换 | direct_ptr = new_code | direct_ptr = new_code | direct_ptr = new_code |
| 替换后冷调用 | 新代码立即生效 | 新代码立即生效 | 新代码立即生效 |
| 被内联方法 | 需重新 AOT 编译 | `InlineReverseMap` stale 标记触发 JIT 重编译 | 同 JIT |
| AOT entry 保留 | 否（覆盖） | 否（无 AOT） | 是（`aot_entry` 始终保留） |
| Interpreter 回退 | 通过 dispatch slot | 通过 dispatch slot | 通过 dispatch slot |

## 平台约束

| 特性 | AOT | JIT | Hybrid |
|------|-----|-----|--------|
| Windows x64 | ✅ 完整支持 | ✅ 完整支持 | ✅ 完整支持 |
| Linux x64 | ✅ 支持 | ✅ 支持 | ✅ 支持 |
| ARM64 | ✅ 支持 | ❌ 不支持 | ❌ 不支持 |
| 移动端 (iOS/Android) | ✅ 支持 | ❌ 不支持 | ❌ 不支持 |

JIT 和 Hybrid 模式当前仅支持 x64 架构。ARM64 和移动端支持推迟到下一开发周期。
