# 字符串ID系统

## 核心原理

运行时字符串以 64-bit ID 传递，而非直接创建 `System.String` 对象。**`ldstr` 指令直接 push 标记后的 StringId（tagged integer）到求值栈，不分配堆内存。** 仅在以下 boundary 场景才物化为完整的 `System.String` 对象：

- 存储到托管数组
- 传递给反射 API
- 转型（castclass/isinst 需要完整对象）
- 用户自定义方法中接收 `string` 类型参数

### StringId 标记

- `CHAOS_STRING_ID_TAG` 定义为 bit 63（AMD64/ARM64 用户空间地址最高 48 位，bit 63 永不置位）
- StringId 值在求值栈上通过 bit 63 标记区分：`value | CHAOS_STRING_ID_TAG`
- `chaos_is_string_id(val)` — 检测是否带 bit 63 标记
- `chaos_extract_string_id(val)` — 提取 StringId 值
- `chaos_make_string_id_value(val)` — 创建 StringId 标记值

### Hash 算法

FNV-1a 64-bit hash（与 `TypeInfo::stable_id` 使用相同算法）：
```c
uint64_t hash = 14695981039346656037ULL;
for each byte: hash = (hash ^ byte) * 1099511628211ULL;
hash |= 1U;  // 确保非零
```

### 编译期常量

StringId 在 C# codegen 侧预计算为 constexpr 常量，**无需运行时注册**：
```cpp
constexpr CHAOS_IL2CPP_UINT64 chaos_string_id_2430D84680AABD0B = 2607821981565500683U;
```

### `ldstr` 指令生成

```cpp
// 当前（per-call heap alloc）：
auto* chaos_string = new chaos_type_System_String{};
chaos_string->header.type_info = &chaos_type_info_...;
chaos_string->length = N;
chaos_string->utf8_data = "...";
chaos_eval_stack[...] = reinterpret_cast<CHAOS_IL2CPP_INTPTR>(chaos_string);

// 方案四（StringId-first，零分配）：
chaos_eval_stack[chaos_stack_top++] =
    chaos_make_string_id_value(chaos_string_id_2430D84680AABD0B);
```

## 外部 Runtime Helper 的 StringId 处理

所有接收 `string` 参数的外部 runtime helper 必须同时处理两种表示形式：

```cpp
extern "C" CHAOS_IL2CPP_UINT16
chaos_external_runtime_..._String_(CHAOS_IL2CPP_INTPTR chaos_arg_0)
{
    if (chaos_is_string_id(chaos_arg_0))
    {
        // StringId 快速路径：直接解析
        auto view = string_table::Resolve(chaos_extract_string_id(chaos_arg_0));
        return view.byte_count > 0 ? view.utf8_data[0] : 0;
    }
    // Fallback: 完整的 String 对象指针
    auto* str = reinterpret_cast<..._String*>(chaos_arg_0);
    return str->utf8_data[0];
}
```

## 碰撞处理

- FNV-1a 64-bit 碰撞概率在 <10⁹ 字符串数量级可忽略
- C# codegen 在编译期检测碰撞，使用 overflow synthetic ID
- 运行时 `Intern()` 已做 FNV-1a + dedup

## AOT Baked Table

在 AOT 编译阶段生成排序后的字符串 ID 查找表：

```cpp
constexpr chaos::il2cpp::string_table::StringEntry chaos_aot_string_entries[] = {
    { chaos_string_id_2430D84680AABD0B, "hello", 5u },
    // ...sorted by StringId for binary search...
};
constexpr CHAOS_IL2CPP_UINT32 chaos_aot_string_entry_count = ...;
```

### 使用时机

- **AOT 模块初始化时**：调用 `string_table::InitializeFromAot(entries, count)` 注册 AOT 表
- **`Resolve(id)` 查找路径**：先查动态条目 → 未命中则对 AOT 表二分查找 → 均未命中返回空

## 运行时解析

C++ 端的 `string_table` 子系统实现完整的运行时字符串解析：

### 关键函数

| 函数 | 说明 |
|------|------|
| `InitializeFromAot(entries[], count)` | 批量加载 AOT 数据段的预计算字符串条目 |
| `Resolve(id)` | StringId → StringView 查找：先查动态条目，再对 AOT 表二分查找 |
| `Register(id, str, domain_id)` | 按域注册新字符串，热更新使用 |
| `Intern(str)` | 去重注册（无域关联） |
| `UnregisterDomain(domain_id)` | 批量移除某域的所有字符串 |

### 字符串生命周期

| 来源 | 注册时机 | 释放时机 |
|------|---------|---------|
| AOT 预计算 | `InitializeFromAot()` 引导阶段 | 进程生命周期 |
| 热更新注册 | `Register()` 运行时 | `UnregisterDomain()` 域卸载时 |

### 位置

- 模块: `chaos_runtime_core`
- 文件: `src/native/runtime-core/string_table.*`

## 性能特性

| 操作 | StringId 路径 | 物化路径 |
|------|--------------|---------|
| `ldstr` | 0 堆分配，1 条指令 push | 1 堆分配 + 字段初始化 |
| `String.op_Equality` | O(1) integer 比较 | O(n) memcmp |
| `Convert.ToChar(string)` | `Resolve()` + 读 byte | 读 struct 字段 |
| string 传参给自定义方法 | 无需操作 | 无需操作 |
| string 存入数组 | 需先物化 | 直接存指针 |
