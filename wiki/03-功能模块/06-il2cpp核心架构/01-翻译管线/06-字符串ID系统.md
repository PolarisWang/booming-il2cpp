# 字符串ID系统

## 核心原理

运行时字符串以 64-bit ID 传递，而非直接创建 `System.String` 对象。仅在需要字符串内容时才物化。

> **注意**：`ldstr` 指令本身总是立即物化 `System.String` 对象。StringId 标记值用于运行时 helper（`String.Concat`、`op_Equality`、格式化输出等）中优化字符串运算，避免不必要的中间物化。

### StringId 标记

- `CHAOS_STRING_ID_TAG` 定义为 bit 63
- StringId 值在求值栈上通过 bit 63 标记区分：`value | CHAOS_STRING_ID_TAG`
- `chaos_is_string_id(val)` — 检测是否带 bit 63 标记
- `chaos_extract_string_id(val)` — 提取 StringId 值
- `chaos_make_string_id_value(val)` — 创建 StringId 标记值

### Hash 算法

FNV-1a 64-bit hash：
```c
uint64_t hash = 14695981039346656037ULL;
for each byte: hash = (hash ^ byte) * 1099511628211ULL;
```

## 碰撞处理

- Hash 冲突通过 String equality check 解决
- 碰撞时退化为完整的字符串比较
- 碰撞率极低（64-bit 空间），但支持正确回退

## AOT Baked Table

在 AOT 编译阶段生成字符串 ID 查找表：
- 编译期已知字符串 → 预计算 hash
- 运行时通过 hash → `string_new_utf8` 延迟物化
- Baked table 包含：字符串 hash、字符串内容、是否已物化标志

## 运行时解析

C++ 端的 `string_table` 子系统实现完整的运行时字符串解析：

### 关键函数

| 函数 | 说明 |
|------|------|
| `InitializeFromAot(entries[])` | 批量加载 AOT 数据段的预计算字符串条目 |
| `Resolve(id)` | StringId → StringView 查找：先查动态条目，再对 AOT 表二分查找 |
| `Register(id, str, domain_id)` | 按域注册新字符串，热更新使用 |
| `Intern(str)` | 去重注册（无域关联） |
| `UnregisterDomain(domain_id)` | 批量移除某域的所有字符串 |

### 字符串生命周期

| 来源 | 注册时机 | 释放时机 |
|------|---------|---------|
| AOT 预计算 | `InitializeFromAot()` 引导阶段 | 进程生命周期 |
| 热更新注册 | `Register()` 运行时 | `UnregisterDomain()` 域卸载时 |

### 查找路径

1. 先检查动态条目表（热更新注册的字符串）
2. 未命中则对 AOT 条目表进行二分查找
3. 均未命中则返回空 StringView

### 位置

- 模块: `chaos_runtime_core`
- 文件: `src/native/runtime-core/string_table.*`
