# 泛型上下文运行时

## 核心职责

跟踪封闭泛型类型和方法的实例化。运行时回答"这个泛型实例的类型参数是什么"——这是反射、相等性检查和特化派发的核心。

本系统使用 **Gen-2 Handle 方案**，以 `TypeInfoHandle`（tag-encoded `ReflectionQueryTypeDescriptor*`）作为全局类型身份标识。

## Handle-Based API（当前版本）

所有注册和查询操作以 `TypeInfoHandle` 为类型参数单位（取代早期的 token-based API）：

| 函数 | 说明 |
|------|------|
| `RegisterGenericInstantiation(open_type_handle, closed_type_handle, type_args_handles, count)` | 注册封闭泛型类型（handle-based） |
| `RegisterMethodGenericContext(method_token, class_type_args_handles, method_type_args_handles)` | 注册方法泛型上下文（handle-based） |
| `GetGenericContextForMethod(method_token)` | 查询方法的泛型上下文 |
| `GetClassTypeArg(context, index)` | 查询类类型参数 |
| `GetMethodTypeArg(context, index)` | 查询方法类型参数 |
| `RegisterModuleGenerics(ModuleGenericRegistrationV0)` | 按模块批量注册 |
| `UnregisterModuleGenerics(module_id)` | 按模块清理 |

## 注册流程

### AOT 模块注册

```
Codegen 发射:
  const GenericTypeRegistrationEntryV0[]    (token-based 条目)
  const uint32_t generic_type_args[]         (扁平 token 池)
  const GenericMethodRegistrationEntryV0[]   (token-based 条目)
  const uint32_t generic_method_args[]       (扁平 token 池)

BootstrapRuntime:
  ModuleGenericRegistrationV0.source_image ← 所属 ImageHandle
  ↓
  RegisterModuleGenerics():
    for each type_entry:
      resolve_type_by_token(source_image, open_token)   → TypeInfoHandle
      resolve_type_by_token(source_image, closed_token) → TypeInfoHandle
      resolve_type_by_token(source_image, arg_tokens[]) → TypeInfoHandle[]
      RegisterGenericInstantiation(open_handle, closed_handle, args, count)

    for each method_entry:
      resolve_type_by_token(source_image, class_arg_tokens[]) → TypeInfoHandle[]
      resolve_type_by_token(source_image, method_arg_tokens[]) → TypeInfoHandle[]
      RegisterMethodGenericContext(method_token, class_args, method_args)
```

### HotUpdate 增量注册

```
HotUpdate DLL 加载:
  ModuleGenericRegistrationV0.source_image ← hotupdate 的 ImageHandle
  RegisterModuleGenerics(hu_reg)
  module_id = g_next_module_id++  (>0)

HotUpdate DLL 卸载:
  UnregisterModuleGenerics(module_id)
  types_by_module[module_id] → 从 by_open_type 批量删除
  methods_by_module[module_id] → 从 by_method_token 批量删除
```

## Codegen 发射数据格式（ModuleGenericRegistrationV0）

```cpp
typedef struct GenericTypeRegistrationEntryV0 {
    uint32_t open_token;          // 开放泛型 token
    uint32_t closed_token;        // 封闭实例 token
    uint32_t arg_count;           // 类型参数个数
    uint32_t args_start_index;    // 指向扁平 token 池的偏移
} GenericTypeRegistrationEntryV0;

typedef struct ModuleGenericRegistrationV0 {
    uint32_t struct_size;
    uint32_t module_id;
    const GenericTypeRegistrationEntryV0*  generic_types;
    uint32_t generic_type_count;
    const uint32_t* generic_type_args;
    uint32_t generic_type_arg_count;
    const GenericMethodRegistrationEntryV0* generic_methods;
    uint32_t generic_method_count;
    const uint32_t* generic_method_args;
    uint32_t generic_method_arg_count;
    ImageHandle source_image;          // 运行时填充
    const CodegenBridgeV0* bridge;     // 运行时填充
} ModuleGenericRegistrationV0;
```

## Registry 内部结构

```cpp
struct GenericContextRegistry {
    CHAOS_IL2CPP_MUTEX mutex;

    // ── 类型索引 ──
    // key = TypeInfoHandle (tag-encoded pointer)
    // O(1) 指针比较，跨模块安全
    CHAOS_IL2CPP_UNORDERED_MAP(TypeInfoHandle, InstantiationVector) by_open_type;

    // ── 方法索引 ──
    CHAOS_IL2CPP_UNORDERED_MAP(CHAOS_IL2CPP_UINT32, MethodGenericContextEntry*) by_method_token;
    CHAOS_IL2CPP_VECTOR(CHAOS_IL2CPP_UNIQUE_PTR(MethodGenericContextEntry)) owned_entries;

    // ── 模块索引（hotupdate 清理）──
    CHAOS_IL2CPP_UNORDERED_MAP(uint32_t, TypeInfoVector) types_by_module;
    CHAOS_IL2CPP_UNORDERED_MAP(uint32_t, TokenVector) methods_by_module;
};
```

## RuntimeInstantiationBridgeV0（运行时泛型）

`MakeGenericType` / `MakeGenericMethod` 的 ABI 桥接：

```cpp
typedef struct RuntimeInstantiationBridgeV0 {
    TypeInfoHandle (*resolve_or_instantiate_type)(
        TypeInfoHandle open_type_def, const TypeInfoHandle* type_args, uint32_t count);
    MethodInfoHandle (*resolve_or_instantiate_method)(
        MethodInfoHandle open_method_def, const TypeInfoHandle* type_args, uint32_t count);
    void (*unregister_module_generics)(uint32_t module_id);
    uint32_t runtime_instantiation_count;
    uint32_t interpreted_method_call_count;
} RuntimeInstantiationBridgeV0;
```

### 执行策略

1. `resolve_or_instantiate_type` 先查 `by_open_type` 快路径
2. 未命中 → `RuntimeInstantiateType` 堆分配封闭类型描述符
3. 值类型：运行时计算 `value_size` 和 `field_offsets`
4. 方法体走 IL 解释器
5. 注册到 registry → 后续调用走快路径

## 设计要点

- **Token→Handle 解析在模块注册时完成**，不延迟到查询时
- **幂等性**：按 `closed_type` 指针比较 O(1)，允许多模块声明同一实例化
- **跨模块安全**：`TypeInfoHandle` 是 tag-encoded 全局指针，天然携带 image 身份
- **按模块清理**：types_by_module / methods_by_module 索引支持 O(entries) 全模块注销
- **统一 API**：类型和方法都使用 handle-based 注册，类型参数的 token→handle 解析在注册循环中统一处理
