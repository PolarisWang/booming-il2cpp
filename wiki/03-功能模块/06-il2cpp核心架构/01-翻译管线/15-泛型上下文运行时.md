# 泛型上下文运行时

## 核心职责

跟踪封闭泛型类型和方法的实例化。运行时回答"这个泛型实例的类型参数是什么"——这是反射、相等性检查和特化派发的核心。

本系统使用 **Gen-2 Handle 方案**，以 `TypeInfoHandle`（tag-encoded `ReflectionQueryTypeDescriptor*`）作为全局类型身份标识。

## Handle-Based API（当前版本）

所有注册和查询操作以 `TypeInfoHandle` 为类型参数单位（取代早期的 token-based API）：

| 函数 | 说明 |
|------|------|
| `RegisterGenericInstantiation(open_type_handle, closed_type_handle, type_args_handles, count)` | 注册封闭泛型类型（handle-based） |
| `RegisterMethodGenericContext(method_token, class_type_args_handles, method_type_args_handles)` | 注册方法泛型上下文（handle-based） |
| `GetGenericContextForMethod(method_token)` | 查询方法的泛型上下文 |
| `GetClassTypeArg(context, index)` | 查询类类型参数 |
| `GetMethodTypeArg(context, index)` | 查询方法类型参数 |
| `RegisterModuleGenerics(ModuleGenericRegistrationV0)` | 按模块批量注册 |
| `UnregisterModuleGenerics(module_id)` | 按模块清理 |

## Registration Flow (B+ Two-Tier)

### Module Load (Eager Phase)

```
Codegen 发射:
  const GenericTypeRegistrationEntryV0[]    (token-based 条目)
  const uint32_t generic_type_args[]         (扁平 token 池)
  const GenericMethodRegistrationEntryV0[]   (token-based 条目)
  const uint32_t generic_method_args[]       (扁平 token 池)

BootstrapRuntime:
  ModuleGenericRegistrationV0.source_image ← 所属 ImageHandle
  ↓
  RegisterModuleGenerics():
    Phase 1 (Eager): 解析 open_token → open_handle → 在 by_open_type 创建空 vector
      └─ 保存 raw tokens (closed_token, arg_tokens) 到 ModuleShard.lazy_types
      └─ 类/方法泛型参数的 raw tokens 存入 shard.token_pool（不解析）

    Phase 2 (Eager): 方法泛型 raw tokens 存入 shard.lazy_contexts
      └─ method_token_owners[token] = shard
      └─ 不解析 type args → 大幅降低冷启动开销
```

### First Query (Lazy Phase)

```
TryResolveClosedType(open_handle, args):
  ├─ by_open_type[open_handle] 查找命中
  ├─ 未 resolved → 触发 LazyResolveOpenType()
  │   ├─ 遍历 shard.lazy_types 中匹配 open_handle 的条目
  │   ├─ batch 解析 closed_token → closed_handle, arg_tokens → arg_handles
  │   ├─ 填充 by_open_type[open_handle].closed_types
  │   └─ 标记 resolved → retry lookup
  └─ 返回 closed_handle 或 0

GetGenericContextForMethod(token):
  ├─ by_method_token 查找未命中
  └─ method_token_owners[token] → LazyResolveMethodContext()
      ├─ 解析 class_type_args, method_type_args
      └─ 填充 by_method_token[token]
```

### HotUpdate Unload (O(1))

```
UnregisterModuleGenerics(module_id):
  ├─ RoutingTableRemove(module_id) → 找到 ShardEntry, CAS 清除
  ├─ 从 by_open_type 清除属于该 shard 的 closed_types
  ├─ 从 by_method_token 清除属于该 shard 的 tokens
  └─ delete ModuleShard → unique_ptr 自动释放 owned_entries
      (O(1) — 不再迭代全局 index 做 remove_if/erase)
```

## Registry 内部结构 (B+ Segmented Shard)

```cpp
// ── Per-module shard ──
struct ModuleShard {
    CHAOS_IL2CPP_MUTEX shard_mutex;
    uint32_t           module_id;
    ImageHandle        source_image;

    vector<TypeInfoHandle>        open_definitions;   // eager
    vector<LazyTypeEntry>         lazy_types;          // raw tokens
    vector<LazyMethodContextEntry> lazy_contexts;       // raw tokens
    vector<uint32_t>              token_pool;           // flat storage

    vector<unique_ptr<MethodGenericContextEntry>> owned_entries;
    vector<bool> resolve_state;  // per-open-type resolved flag
};

// ── Lock-free routing table ──
ShardEntry s_routing_table[347];     // prime, open-addressing, CAS-based

// ── Slimmed global registry ──
struct Registry {
    CHAOS_IL2CPP_MUTEX global_mutex;

    // Type index: open → (closed_types vector + owner_shard for lazy)
    CHAOS_IL2CPP_UNORDERED_MAP(TypeInfoHandle, TypeEntry) by_open_type;

    // Method token index (bare ptr, owned by shard)
    CHAOS_IL2CPP_UNORDERED_MAP(uint32_t, MethodGenericContextEntry*) by_method_token;
    CHAOS_IL2CPP_UNORDERED_MAP(uint32_t, ModuleShard*) method_token_owners;

    // Orphan entries (module_id=0 standalone registration)
    vector<unique_ptr<MethodGenericContextEntry>> orphan_entries;
};
```

## RuntimeInstantiationBridgeV0（运行时泛型）

`MakeGenericType` / `MakeGenericMethod` 的 ABI 桥接：

```cpp
typedef struct RuntimeInstantiationBridgeV0 {
    TypeInfoHandle (*resolve_or_instantiate_type)(
        TypeInfoHandle open_type_def, const TypeInfoHandle* type_args, uint32_t count);
    MethodInfoHandle (*resolve_or_instantiate_method)(
        MethodInfoHandle open_method_def, const TypeInfoHandle* type_args, uint32_t count);
    void (*unregister_module_generics)(uint32_t module_id);
    uint32_t runtime_instantiation_count;
    uint32_t interpreted_method_call_count;
} RuntimeInstantiationBridgeV0;
```

### 执行策略

1. `resolve_or_instantiate_type` 先查 `by_open_type` 快路径
2. 未命中 → `RuntimeInstantiateType` 堆分配封闭类型描述符
3. 值类型：运行时计算 `value_size` 和 `field_offsets`
4. 方法体走 IL 解释器
5. 注册到 registry → 后续调用走快路径

## 设计要点

- **两级注册（Two-Tier）**：模块加载时只注册 open definition（Eager），closed type 的 token→handle 解析推迟到首次查询（Lazy），大幅降低冷启动开销
- **幂等性**：按 `closed_type` 指针比较 O(1)，允许多模块声明同一实例化
- **跨模块安全**：`TypeInfoHandle` 是 tag-encoded 全局指针，天然携带 image 身份
- **Per-Module Shard**：每个模块的原始 token 数据存入独立 `ModuleShard`，生命周期与模块绑定
- **O(1) 模块卸载**：通过 lock-free RoutingTable，卸载时直接 CAS 清除 ShardEntry + 析构 shard，无需遍历全局 index
- **消除内存泄漏**：`owned_entries` 移至 `ModuleShard`，shard 析构时 unique_ptr 自动释放
- **动态 arg_buffer**：消除 `arg_buffer[8]` 硬编码限制，支持 >8 类型参数的泛型
- **细粒度锁**：per-shard mutex + 全局 CAS routing table，减少锁竞争
