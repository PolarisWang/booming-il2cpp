# 模式选择决策树

> AOT / JIT 两种编译模式的选择指南。帮助项目根据部署场景、性能要求和热更新需求选择最佳模式。

---

## 两种模式一句话定位

| 模式 | CLI 选项 | 一句话描述 |
|------|----------|-----------|
| **AOT** | `--mode aot`（默认） | 所有方法在构建期编译为 C++ 原生代码，零运行时开销 |
| **JIT** | `--mode jit` | 所有方法启动时注册 JitPrecode，首次调用触发 Quick JIT 编译 |

---

## 决策树

```
项目需求分析
  │
  ├─ 生产发布（用户设备运行）?
  │   └─ YES → AOT (性能最优，零运行时开销，patchdata 支持热更)
  │
  ├─ 开发迭代（频繁改代码）?
  │   ├─ YES → JIT (无需等待 AOT 编译，首调用自动编译)
  │   └─ NO  → 继续
  │
  ├─ 启动性能敏感（冷启动时间受限）?
  │   ├─ YES → AOT (预编译原生代码，最快启动)
  │   └─ NO  → 继续
  │
  ├─ 热更新是核心需求（不重启换逻辑）?
  │   └─ YES → AOT + patchdata (C++ 级别替换)
  │
  └─ 峰值性能（计算密集型、物理模拟）?
      ├─ YES → AOT (直接原生执行，无 JIT 编译开销)
      └─ NO  → AOT (默认安全选择)
```

---

## 详细对比表

| 维度 | AOT | JIT |
|------|-----|-----|
| **冷启动性能** | ★★★★★ 最快（零开销） | ★★☆☆☆ 最慢（每方法首次需 JIT 编译） |
| **峰值性能** | ★★★★☆ 较好（AOT） | ★★★★★ 最好（PGO + Tier 1 图着色分配） |
| **峰值内存** | ★★★★★ 最低（只有 AOT 代码） | ★★★☆☆ 较高（额外 JIT 代码 + trampoline） |
| **热更灵活度** | ★★★☆☆ 支持（patchdata C++ 替换） | ★★★★★ 灵活（直接替换代码指针） |
| **编译时间** | ★★★★★ 构建期完成（不影响运行时） | ★★★☆☆ 运行时逐步编译（首调用延迟） |
| **代码体积** | ★★★★★ 最小（只有 AOT 段） | ★★★★☆ 较小（无 AOT 代码） |
| **调试/Profile 友好度** | ★★★☆☆ 中等（C++ 级别符号） | ★★★★★ 好（保留 IL/IR 结构） |
| **平台支持** | 跨平台（C++ 编译） | 当前仅 x64 |

## 典型场景推荐

### 手游/Mobile 游戏发布
**推荐：AOT**
- 用户设备上无编译器，AOT 是唯一可行选项
- 可通过 patchdata 实现轻量级热更新（C++ 函数替换）
- 内存和包体积最优化

### 手游 + 重度热更新需求
**推荐：AOT + patchdata**
- AOT 保证基础性能
- patchdata 支持方法级替换和 Interpreter 回退
- 不需要运行时编译器（降低平台兼容风险）

### PC/Console 游戏开发迭代
**推荐：JIT**
- 开发阶段频繁改代码，JIT 消除 AOT 编译等待时间
- 首调用自动 JIT 编译，适合快速原型和调优
- PGO 自动优化热点方法

### 需要完整热更新能力的发布项目
**推荐：AOT + patchdata**
- AOT 保留原方法条目，支持 hotpatch 替换
- patchdata 提供方法级热修复能力
- 部署灵活度最高

---

## 误选代价与回退

| 误选 | 代价 | 回退方案 |
|------|------|----------|
| 对冷启动敏感的项目选了 JIT | 首调用方法都要 JIT 编译，启动时间显著增加 | 切换为 AOT，JIT 模式可预编译启动路径 |
| 对峰值性能要求高的项目选了 AOT | AOT 无法做运行时窥孔优化/PGO，可能损失 10-30% 性能 | JIT 模式自动优化热点方法 |
| 需要热更但选了 AOT | patchdata 只能替换 C++ 函数指针，不能改 IL 逻辑 | 接受 patchdata 约束 |
