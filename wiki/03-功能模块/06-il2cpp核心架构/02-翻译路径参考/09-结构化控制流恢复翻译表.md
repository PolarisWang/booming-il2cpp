# 结构化控制流恢复翻译表

## 概述

NativeAOT 代码生成器不再对每条 IL 指令发射 `chaos_ip_N:` 标签 + `goto chaos_ip_{N+1}`。改为通过 CFG 分析恢复结构化控制流（if-else、switch），消除直落 goto chain。

## 流程图

```
指令列表 → BuildBasicBlocks() → 基本块列表
                               ↓
                         BuildControlFlowGraph() → CFG
                               ↓
                          IsCfgReducible() ──false──→ EmitInstructionRange() [回退 goto 风格]
                               ↓ true
                         RecoverStructure() → 结构化节点树
                               ↓
                         EmitStructuredNode() → C++ if/else/switch
```

## 关键文件

| 文件 | 职责 |
|------|------|
| `Emission/NativeAotLoweringPlanner.StructuredControlFlow.cs` | CFG 构建 + 结构化恢复算法 |
| `Emission/NativeAotLoweringPlanner.MethodEmission.cs` | 结构化发射方法族 |
| `Emission/NativeAotLoweringPlanner.ExceptionEmission.cs` | 异常 handler 的结构化发射 |

## 数据结构

| 类型 | 说明 |
|------|------|
| `BasicBlock` | 基本块：起始偏移、体指令列表、终结指令、分支目标 |
| `ControlFlowGraph` | CFG：块列表、偏移→块索引映射、可归约性标志 |
| `BasicBlockNode` | 叶子节点：单一基本块 |
| `SequenceNode` | 顺序节点：子节点序列 |
| `IfThenElseNode` | 条件节点：条件块 + then/else 分支 + merge 点 |
| `SwitchNode` | 开关节点：开关块 + case body + default + merge 点 |

## 结构化覆盖范围

| 模式 | 检测 | 发射 |
|------|------|------|
| 直落块序列 | `IsBlockTerminatorOpcode` 为 false → fall-through | 块内容顺序发射，无 label/goto |
| 无条件分支 | `br` / `leave` | `goto chaos_ip_target` |
| 条件分支 | `brtrue` / `brfalse` / `beq` / `bne.un` / `bge`(`.un`) / `bgt` / `ble` / `blt` | `if (condition) { ... } else { ... }` |
| 开关 | `switch` | `switch (value) { case N: ... break; }` |
| 终结指令 | `ret` / `throw` / `rethrow` / `endfilter` / `endfinally` | 直接发射，无后继 goto |

## 未覆盖模式（回退）

| 模式 | 原因 | 行为 |
|------|------|------|
| 后向分支（循环） | 跑在方案一范围内，方案二不处理 | `IsCfgReducible = false` → 回退 goto 风格 |
| 交叉分支（不规则 CFG） | 无法表示为结构化 if-else/switch | 同上 |

## merge 点识别

`FindMergePoint()` 对 then/else 两条路径分别做 `WalkForward()`，取可达块集合的交集中索引最小的块作为 merge 点。

## `_suppressGotoNext` 机制

`EmitStructuredInstructionRange()` 入口处设置 `_suppressGotoNext = true`，使 `AppendGotoNext()` 在结构化上下文中变为空操作（no-op）。退出时在 `finally` 块中恢复为 `false`，确保 fallback 路径的 `EmitInstructionRange()` 正确发射 goto。

## 与异常处理集成

5 种异常 shape（catch-only / filter-only / finally-only / catch-and-finally / filter-and-finally）中的每个 partition（prefix / try / handler / tail）各自独立调用 `EmitStructuredInstructionRange()`。统一替换前导的 `goto chaos_ip_firstInstr` + `EmitInstructionRange` → `EmitStructuredInstructionRange`。

## 验证方式

| 方法 | 说明 |
|------|------|
| dotnet build | 编译零错误 |
| 生成代码审查 | 检查 if-else 结构正确性、goto 消除效果 |
| 行为等价性 | 现有 foundation-dll 测试验证输出行为一致 |
