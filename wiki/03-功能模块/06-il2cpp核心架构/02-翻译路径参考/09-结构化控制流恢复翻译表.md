# 结构化控制流恢复翻译表
## 概述

Native AOT 主路径不再使用 `label/goto` 续流模型。当前实现先恢复 CFG 的结构化控制流，再直接发射 C++ 的 `if/else`、`while`、`do/while`、`switch`。

对性能敏感的 structured 主路径，IL 求值栈会在发射阶段映射为局部 slot 变量：

```cpp
CHAOS_IL2CPP_INTPTR _s0{};
CHAOS_IL2CPP_INTPTR _s1{};
```

这样可以避免主路径里的 `chaos_eval_stack[chaos_stack_top++]` / `chaos_eval_stack[--chaos_stack_top]` 热点访问。

## 主路径

流程：

```text
instructions
  -> BuildBasicBlocks
  -> BuildControlFlowGraph
  -> RecoverStructure
  -> StructuredIR tree
  -> direct C++ emission
```

StructuredIR 主要节点：
- `IRBlock`
- `IRSequence`
- `IRIfThenElse`
- `IRWhileLoop`
- `IRDoWhileLoop`
- `IRSwitch`
- `IRExceptionRegion`

## Slot Lowering

- slot 上下文贯穿整棵 `StructuredIR` 树，`IRBlock`、条件片段、循环、`switch`、`ret`、`throw`、`catch/filter` 对象流都直接读写 `_sN`
- `call` / `callvirt` / `newobj` 和常见算术、比较、字段访问直接按 slot 发射，不再经过字符串后处理
- delegate `callvirt` 也已纳入 direct slot emission，不再默认退回 residual dispatch
- 旧的 `ReplaceStackOpsWithSlots(...)` 过渡链路已删除

Structured `IRBlock` 和条件片段会走 direct slot lowering：
- push 结果改写到 `_sN`
- 能在当前片段内配对的 pop 直接读 `_sN`
- 返回值直接从 `_sN` 读出，不再回落到 `chaos_eval_stack`

异常分区有一条额外规则：
- 对已经按 prefix/try/handler/tail 切开的 exception partition，末尾仅用于“离开当前分区”的 `br/leave` 会在建树后被消解，不再阻塞 `IRExceptionRegion` 发射

这是一种 B+ 方案：
- structured 主路径使用局部 slot
- residual fallback 继续保留真实 eval stack

## Fallback

以下情况会抛出硬错误（`NotSupportedException`），不再降级：
- CFG 不可规约
- 结构化恢复后仍残留 `br/leave`

Flat-goto 回退路径已被完全移除。所有方法必须通过结构化恢复才能发射。这保证了生成代码中不会出现 `label/goto` 续流模型。

## 异常路径

异常统一走 `IRExceptionRegion`。

当前支持的 structured exception 主路径：
- catch-only
- filter-only
- finally-only

规则：
- try/catch/filter/finally 的 structured 分区优先走 StructuredIR
- 分区内部若不可安全结构化，退回局部 `EmitInstructionRange(...)` correctness fallback
- 不把异常主路径改回旧的 `label/goto` 模型

## 约束

- generated cpp 主路径不得再出现 `goto chaos_ip_*`
- `IRExceptionRegion` 是异常统一入口
- `pc-dispatch` 仅作为 residual correctness fallback
- structured path 优先优化性能，fallback 优先保证正确性

## Codegen 度量

P2-A1/A2 实现后，每个 subject 生成 `codegen/native-aot.codegen-metrics.json`：

| 字段 | 含义 |
|------|------|
| `structuredMethodCount` | 非 EH 方法中成功结构化恢复的数量 |
| `structuredExceptionBodyCount` | EH 方法中成功结构化恢复的数量 |
| `flatFallbackCount` | 退回到 flat-goto 的方法数（当前为 0） |
| `totalMethodCount` | 总方法数 |
| `structuredRecoveryRate` | `(structuredMethodCount + structuredExceptionBodyCount) / totalMethodCount` |

## P2-A2 Flat-Fallback 消除模式

四种已知 flat-fallback 模式已修复：

1. **多锁存循环（Pattern 1）**：`BuildLoop` 使用 `BodyIndices.Max()` 而非 `LatchIndices.Max()`，确保所有循环体块被正确消耗
2. **Switch-Case Fallthrough（Pattern 2）**：`BuildSwitch` 检测空 case body 并记录为 fallthrough，`EmitIRSwitch` 跳过 break 插入
3. **深度 EH 嵌套（Pattern 3）**：当 5 种预定义 EH 形状都不匹配时，回退到 `IRFlatRegion` 而非返回 false（防止生成空函数体）
4. **Finally 控制流（Pattern 4）**：`TryCreateFinallyHandlerEmissionPlan` 接受 forward-branch guard（如 `finally { if (obj!=null) cleanup; }`）

关键文件：
- `NativeAotLoweringPlanner.StructuredControlFlow.cs` — BuildLoop、BuildSwitch
- `NativeAotLoweringPlanner.StructuredIR.cs` — TryBuildStructuredMethodBody、EmitIRSwitch
- `NativeAotLoweringPlanner.ExceptionShapePlanning.cs` — TryCreateFinallyHandlerEmissionPlan
