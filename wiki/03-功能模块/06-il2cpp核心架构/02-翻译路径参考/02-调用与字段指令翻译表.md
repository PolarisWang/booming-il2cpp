# 调用与字段指令翻译表

## 方法调用

| Opcode | 翻译策略 | 特殊处理 |
|--------|---------|---------|
| `call` | 直接函数调用 | 静态方法/实例方法直接调用 |
| | → direct_fn 快速路径（external runtime callee） | Call 指令的 `direct_fn != nullptr` 时走 direct_fn 绕过 runtime dispatch |
| `callvirt` | `resolve_virtual_method_by_token` → `vtable_registry::ResolveVirtualMethodPointer` 继承链查找 | 虚方法表分发（三步回退链） |
| | → 去虚拟化（devirtualization） | Phase 4 reachability-based: 当编译闭包内接收者类型唯一时降级为直接调用 |

### Call direct_fn 快速路径

当 `IRInstruction::direct_fn` 被设置时（通过 AotDirectFn table 解析 external runtime callee），Call 路径绕过完整 dispatch：

```
call 指令（direct_fn != nullptr）
  │
  ├─ FastExecute (fast_dispatch.cpp) Handle_Call:
  │   ├─ Pop args from FastFrame stack → raw_args[]
  │   ├─ fn = (DirectFn)instr.direct_fn
  │   ├─ result = fn(a0,...,a7)
  │   ├─ 从 CachedCallInfo 读 ret_tag → push result
  │   └─ 无 SEH → 最快路径
  │
  └─ InterpreterVM (interpreter_vm.cpp) Call handler:
      ├─ Pop args from InterpreterValue stack → raw_args[]
      ├─ fn = (DirectFn)instr.direct_fn
      ├─ result = fn(a0,...,a7)
      ├─ try/catch chaos_managed_exception
      └─ push result → SEH 展开（需要时）
```

该路径用于调用 `Convert.ToChar(System.Byte)` → `chaos_external_runtime_*` 等预编译 external runtime 函数。
| `callvirt` | `resolve_virtual_method_by_token` → `vtable_registry::ResolveVirtualMethodPointer` 继承链查找 | 虚方法表分发（三步回退链） |

## 虚方法分派机制

`callvirt` 的分派路径：

```
callvirt → resolve_virtual_method_by_token(instance_type_token, declared_method_token)
           → vtable_registry::ResolveVirtualMethodPointer(instance_type_token, declared_method_token)
             → 沿 type→base_type 继承链查找 method_token 匹配的 slot
               → 返回 method_pointer
```

回退链（`bootstrap.cpp` `ResolveVirtualMethod`）：若 vtable registry 返回 nullptr，依次尝试 (2) unresolved-virtual-call table → (3) 返回 declared method 作为兜底。

### 去虚拟化（Devirtualization，Phase 4）

在 Phase 3（类型层次去虚拟化）之后，新增 Phase 4 reachability-based 去虚拟化：

1. **收集实例化类型**：扫描所有可达方法体内的 `newobj` 指令，记录实例化类型 SubjectId
2. **过滤候选路由**：对每个虚调用点，过滤路由表至仅保留实例化类型的实现
3. **决策**：
   - 仅一个实现可实例化 → 无条件去虚拟化（无 guard）
   - 多个但仅一个具体实例化 → guard-based 去虚拟化
   - 多个可实例化 → 保持虚调用

实现文件：`Planning/NativeAotLoweringPlanner.InvocationPlanning.cs`（`ResolveVirtualDispatchRoutes` Phase 4）

> **实现状态**：运行时 registry（`RegisterTypeVTable`/`ResolveVirtualMethodPointer`）已实现。codegen 发射 `const VTableSlot[]` + `const TypeVTable` 并在 bootstrap 中注册**尚在规划中**，当前 callvirt 通过 `resolve_virtual_method_by_token` 桥接函数走运行时解析。<!-- 更新此标记前，确认 codegen 中 VTableSlot 发射已实现 -->

## 约束调用（constrained. 前缀）

| 场景 | 实际处理 | 说明 |
|------|---------|------|
| `constrained.` + `callvirt` 值类型接口方法 | `SkipConstrainedInstruction` 丢弃前缀 → `HybridDispatchResolver` 将非虚 callee 解析为 `DispatchKindCode = Direct` → 直接调用 | 无显式 constrained 处理，效果通过 dispatch kind 间接实现 |
| `constrained.` + `callvirt` 泛型约束 | 同上路径 → 泛型约束接口 slot 解析为 `DispatchKindCode = Virtual` | `test_dispatch_generic_constraint_native_aot.py` 验证 |

> **约束**：`constrained.` 前缀被 loader 丢弃（`LoaderStage.InstructionDecoding.cs:968-972`），`ManagedInstructionModel` 无约束类型字段。当前实现依赖 `HybridDispatchKind` 间接产生语义正确结果，但缺少显式的 box 规避优化。

## Enum 运行时元数据分发表

Enum 运行时 stubs（`enum_stubs.cpp`）使用编译期生成的 dispatch table 加速类型→元数据查找：

| 组件 | 策略 | 说明 |
|------|------|------|
| Dispatch Table 生成 | `EnumMetadataExtractor.cs` → `enum_metadata.generated.h` | 按 FNV-1a 24-bit hash 排序的 `EnumDispatchEntry[]` 数组，codegen 时生成 |
| 查找算法 | `chaos_dispatch_lookup()` — 二分查找 | O(log n) 查找，~9 次比较（360 个 enum 类型），取代旧的 switch-case |
| 运行时注册 | `ChaosEnumRegisterDispatchTable()` → `g_chaos_enum_dispatch_lookup` | 由 `_EnumMetadataRegistrar` 静态初始化器调用，热更新通过 `ChaosEnumUpdateDispatchTable()` 替换 |
| 使用路径 | `enum_resolve_meta()` → `g_chaos_enum_dispatch_lookup` | 当 TypeInfoHandle 含 0x02XXXXXX 格式 FNV-24 hash 时直接查找，跳过 `resolve_type_arg` |
| 内联宏 | `CHAOS_IL2CPP_ENUM_LOOKUP(meta_table, value, fallback)` | codegen 可直接在 generated 代码中扫描 metadata 数组，零函数调用开销 |
