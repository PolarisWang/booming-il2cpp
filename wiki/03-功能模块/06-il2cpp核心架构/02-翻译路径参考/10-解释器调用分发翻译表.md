# 解释器调用分发翻译表

> 解释器 (`InterpreterVM::Execute`) 在执行 `call`/`callvirt`/`callbridge` 指令时，通过 `DispatchCallback` 将调用分发给 runtime-core 层的 `InterpreterDispatch`，最终路由到 AOT 编译方法或另一段解释方法。本文描述该跨层调用的完整路径。

## 总体架构

```
InterpreterVM::Execute (interpreter 层)
  │ 遇到 Call/CallVirt/CallBridge/CallVirtConstrained 指令
  │
  ├─ frame->dispatch_fn != nullptr → 同步 callback 路径
  │   │
  │   └─ InterpreterDispatch (runtime_instantiation.cpp)
  │       │ 将 InterpreterValue[] 转为 ABI 参数数组 (void* argv[])
  │       │
  │       ├─ MethodInvoke (runtime_core.cpp)
  │       │   │ 通过 RuntimeAbiV0::method_invoke 函数指针调用
  │       │   │
  │       │   ├─ AOT 方法 → 直接执行已编译代码
  │       │   ├─ 解释器方法 → InterpretMethodCall → Execute 递归
  │       │   └─ 异常 → 设置 CHAOS_RUNTIME_STATUS_MANAGED_EXCEPTION
  │       │
  │       └─ 将 ABI 返回值转为 InterpreterValue 返回给 Execute
  │
  └─ dispatch_fn == nullptr → 外部 dispatch 回退（legacy）
      └─ 设置 ExecutionResult::needs_external_dispatch = true
```

## 关键接口

### DispatchCallback（跨层契约）

```cpp
using DispatchCallback = auto (*)(
    void*                               call_target,       // MethodInfoHandle
    const InterpreterValue*             call_args,         // 参数数组
    CHAOS_IL2CPP_UINT32                 arg_count,         // 参数个数
    bool                                is_instance_call,  // 是否实例方法
    void*                               dispatch_context   // 执行上下文
) -> DispatchResult;
```

### DispatchResult（异常安全的返回值）

```cpp
struct DispatchResult {
    bool has_value = false;          // 有正常返回值
    InterpreterValue value = {};     // 返回值
    bool threw_exception = false;    // 被调方抛了异常
    InterpreterValue exception_value = {};  // 异常对象
};
```

`DispatchResult` 替代 C++ 异常穿越 callback 函数指针边界。所有异常通过结构体字段传递，由 Execute 内部的 SEH 机制（`findCatchHandler` + `setupFinallyUnwind`）处理。

## 翻译路径

### 1. Call / CallBridge

| 步骤 | 操作 |
|------|------|
| 1 | 从 eval stack 弹出 `arg_count` 个参数到 `InterpreterValue[]` 缓冲区（小数量用栈分配 `kMaxCallArgs=8`，大数量 heap fallback） |
| 2 | 调用 `frame->dispatch_fn(call_target, arg_buf, arg_count, is_instance_call, dispatch_context)` |
| 3 | 处理 `DispatchResult`（见下文"结果处理"） |
| 4 | `dispatch_fn==nullptr` 时：回退到 `ExecutionResult::needs_external_dispatch=true` |

### 2. CallVirt

| 步骤 | 操作 |
|------|------|
| 1 | 收集 eval stack 参数到缓冲区 |
| 2 | 虚拟分发：从 `cv_args[0]`（`this`）获取实例的 `type_token`，通过 `vtable_registry::ResolveVirtualMethodPointer` 解析目标方法 |
| 3 | 调用 `dispatch_fn(resolved_target, ...)` |
| 4 | 处理 `DispatchResult`（同 Call） |

### 3. CallVirtConstrained

| 步骤 | 操作 |
|------|------|
| 1 | 收集 eval stack 参数到缓冲区 |
| 2 | 检查 `this` 是否为值类型（`ValueTag::Struct`）：是 → 直接调（不 box）；否 → 正常虚分发表解析 |
| 3 | 调用 `dispatch_fn(resolved_target, ...)` |
| 4 | 处理 `DispatchResult`（同 Call） |

### 4. 结果处理（`handleDispatchResult` lambda）

所有 call 指令共享同一结果处理逻辑：

```
DispatchResult 返回
  │
  ├─ threw_exception == true
  │   ├─ → findCatchHandler(instruction_index) 找到 catch
  │   │   ├─ setupFinallyUnwind → 有 finally → 跳 finally handler 开始展开
  │   │   └─ 无 finally → 直接跳 catch handler，push exception_obj
  │   └─ → 未找到 catch → ExecutionResult::threw_exception=true，返回
  │
  └─ has_value == true
      ├─ 尾调用检测：下条指令是 Ret → 直接设 return_value，跳过 push/pop
      └─ 非尾调用 → push 到 eval stack，继续执行
```

## InterpreterDispatch 实现

位于 `src/native/runtime-core/runtime_instantiation.cpp`。

### 参数转换（InterpreterValue → ABI）

| ValueTag | ABI 表示 |
|----------|---------|
| `Int32` | 4 字节写入 `raw_data[ai]`，`argv[ai]` 指向它 |
| `Int64` | 8 字节写入 `raw_data[ai]` |
| `Float32` | 4 字节写入 `raw_data[ai]` |
| `Float64` | 8 字节写入 `raw_data[ai]` |
| `ObjectRef` / `Null` | 指针值写入 `raw_data[ai]` |
| `Struct` | 直接使用 `arg.obj` 指针（heap 上已分配的数据块） |

### 返回值转换（ABI → InterpreterValue）

- 标量返回值：通过 `CHAOS_IL2CPP_UINT64 ret_scalar` 接收 → 按 `MapMemberTypeToValueTag` 解析类型后转对应 `ValueTag`
- 结构体返回值：通过 `LayoutEngine::GetOrComputeLayout` 获取 `value_size` → 分配 `struct_ret_buf` → `InterpreterValue::from_struct`

### 方法调用

通过 `RuntimeAbiV0::method_invoke` 函数指针调用，该指针指向 `runtime_core.cpp` 中的 `MethodInvoke`：

```cpp
const auto* abi = runtime_core::GetRuntimeAbiV0();
RuntimeStatus status = abi->method_invoke(
    ctx->runtime_state, ctx->thread_state,
    method, this_ptr,
    argv, param_count,
    ret_buf, ret_size, &ex);
```

- `CHAOS_RUNTIME_STATUS_MANAGED_EXCEPTION` → 设置 `DispatchResult::threw_exception`
- `CHAOS_RUNTIME_STATUS_OK` → 正常返回值转换

## 尾调用优化

当 `call` 指令后紧跟 `ret` 指令时，跳过 eval stack 的 round-trip：

```cpp
if (instruction_index + 1u < method.instructions.size() &&
    method.instructions[instruction_index + 1u].op_code == IROpCode::Ret) {
    result.has_return_value = true;
    result.return_value = dret.value;
    return result;  // 直接返回，不 push/pop
}
```

**优化效果**：消除一对 `push`（call 结果）→ `pop`（ret）操作，在链式调用场景（`A → B → C`）中每层节省一次栈操作。

**覆盖范围**：仅覆盖 `call + ret` 连续模式。不覆盖：
- `call → brtrue/brfalse → ret`（条件分支后的尾调用）
- `call → pop → ...`（返回值被丢弃）

## Depth Guard（递归保护）

当解释方法通过 dispatch callback 调用另一解释方法时形成递归（`Execute → InterpreterDispatch → MethodInvoke → InterpretMethodCall → Execute → ...`），`InterpreterDispatchContext::recursion_depth` 防止无限递归：

```cpp
constexpr int kMaxDispatchDepth = 200;

// InterpreterDispatch 入口
if (ctx->recursion_depth >= kMaxDispatchDepth) {
    result.threw_exception = true;  // 深度超限 → 异常信号
    return result;
}
++ctx->recursion_depth;

// 所有退出路径
--ctx->recursion_depth;
return result;
```

**深度计数手工维护**：由于 `InterpreterDispatch` 有 4 个退出点（ABI 空、异常、非 OK 状态、正常返回），每个退出点前必须手工 `--ctx->recursion_depth`。

## InterpretMethodCall 入口转换

从 ABI 到解释器的反向转换（入口侧）：

```
ABI 参数 (void* const* argv, uint32_t argc)
  │ + object_instance ('this')
  ▼
InterpreterValue[] (ExecutionFrame::arguments)
  │
  ├─ signature-aware (V1): 通过 MapMemberTypeToValueTag 确定每个参数的 ValueTag
  │   ├─ Int32/Float32: memcpy 4 字节
  │   ├─ Int64/Float64: memcpy 8 字节
  │   ├─ ObjectRef: memcpy 指针
  │   └─ Struct: LayoutEngine 获取 value_size → from_struct
  └─ fallback (V0): 全部作为 Int32 读取
```

返回值反向转换（`ExecutionResult → ABI out_return_value`）：同上的 tag 分发，按 `return_value.tag` 选择 `memcpy` 大小。

## 异常穿越边界流

```
Callee 抛异常 (throw IL 指令或 AOT side exception)
  │
  ├─ AOT 方法 → MethodInvoke 返回 CHAOS_RUNTIME_STATUS_MANAGED_EXCEPTION
  │   └─ InterpreterDispatch → DispatchResult::threw_exception = true
  │
  ├─ 解释器方法 → InterpretMethodCall 抛 ManagedExceptionCarrier
  │   └─ MethodInvoke catch → 转为 CHAOS_RUNTIME_STATUS_MANAGED_EXCEPTION
  │
  ├─ Execute (handleDispatchResult)
  │   ├─ findCatchHandler → 有 handler → SEH 展开
  │   └─ 无 handler → ExecutionResult::threw_exception = true
  │
  └─ InterpretMethodCall
      └─ 抛 ManagedExceptionCarrier → MethodInvoke 继续向上传播
```

## 约束与限制

1. 尾调用优化不覆盖条件分支后的模式
2. Depth Guard 硬限制 200 层（可通过 `kMaxDispatchDepth` 调整）
3. 结构体返回值需要 `LayoutEngine` 已初始化
4. 旧 `needs_external_dispatch` fallback 路径保留但不再被主路径使用
