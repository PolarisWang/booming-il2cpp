# 20-Namespace与Include工程规范统一决策

## 背景

项目 native C++ 代码存在以下工程规范问题：
1. **命名空间分裂**：`common/chaos/` 模块使用 `ChaosIl2cpp::Common`（PascalCase），其余模块使用 `chaos::il2cpp::*`（小写）
2. **Include 风格混用**：三种风格并存（`"chaos/header.h"`、`<chaos/header.h>`、`"../module/header.h"`）
3. **`.clang-format` 关闭了 include 排序**：`IncludeBlocks: Preserve` + `SortIncludes: false`
4. **`runtime_core.h` 包含文件作用域 `using namespace`**
5. **extern "C" 无注释说明**

## 决策

### 命名空间统一

**方案**：统一使用小写 `chaos::il2cpp::<module>`，废弃 `ChaosIl2cpp::Common`。

| 模块 | 旧命名空间 | 新命名空间 |
|------|-----------|-----------|
| `common/chaos/` | `ChaosIl2cpp::Common` | `chaos::il2cpp::common` |
| 其余模块 | `chaos::il2cpp::*` | 不变 |

**向后兼容**：在 `chaos/common.h` 末尾添加别名 `namespace ChaosIl2cpp { namespace Common = chaos::il2cpp::common; }`，确保旧代码可编译。

### Include 风格统一

1. 所有 `"chaos/header.h"` → `<chaos/header.h>`（尖括号表示系统/模块路径）
2. 所有 `"../module/header.h"` → `"module/header.h"`（CMake `target_include_directories` 提供搜索路径）
3. 文件名冲突（如 `runtime_instantiation.h` 同时在 `contracts/native/v0/` 和 `src/native/runtime-core/` 存在）使用相对路径注释说明

### clang-format

- `IncludeBlocks: Preserve` → `Regroup`
- `SortIncludes: false` → `true`
- 添加 IncludeCategories（主 .h → chaos/ → 标准库 → 外部依赖）

### runtime_core.h 清理

- 移除文件作用域 `using namespace chaos::il2cpp::marshal_abi;`
- 保留显式 using-declarations（更精确的类型导入）

### extern "C" 文档化

- 对使用 extern "C" 的 .cpp 文件添加文件顶部注释块
- 统一注释格式：`// ABI exports: extern "C" linkage for managed/NativeAOT callability.`
