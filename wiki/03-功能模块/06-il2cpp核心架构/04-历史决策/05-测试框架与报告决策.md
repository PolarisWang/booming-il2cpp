# 测试框架与报告决策

**来源**: `docs/discuss/il2cpp-mainline/20260407-12-*`, `20260407-13-*`, `20260407-14-*`, `20260407-15-*`, `wiki/03-功能模块/06-il2cpp核心架构/05-架构参考/subject-test-framework-v1/`

## 决策

### Subject Framework

基于"被测试主体"（Subject）的测试框架：

| 概念 | 说明 |
|------|------|
| Subject | 被测试的单一功能单元（一个翻译路径、一个 EH shape、一个 helper） |
| Test case | Subject + 输入数据 + 预期输出 |
| Matrix | Subject 的测试覆盖矩阵（不同输入排列） |
| Manifest | 测试清单，描述 Subject 集合和覆盖目标 |

Subject 测试的三阶段：
1. **Truth layer**：生成预期输出
2. **Evidence layer**：执行并收集实际结果
3. **Verification layer**：比对预期与实际

### Reporting Schema

测试结果报告格式：

```
TestReport
 ├── SubjectMetadata       -- Subject 标识、版本、类型
 ├── CoverageMatrix        -- 覆盖矩阵（哪些场景已测/未测）
 ├── EvidenceResults       -- 每条 evidence 的通过/失败/跳过
 ├── GapAnalysis           -- 未覆盖路径分析
 └── Chronology            -- 测试执行时间线
```

报告按 foundation DLL 分组输出为 HTML：
- `dlls/System.Private.CoreLib.html`
- `dlls/System.Linq.html`
- 等

### Engine Binding

测试引擎与主引擎的合约：
- 测试引擎通过 `engine_binding` 接口注册 Subject
- 每个 Subject 在引擎中注册为可执行的 test hook
- 测试结果通过 `evidence` 回调收集

### Phase A / B 边界

| Phase | 测试范围 | 目标 |
|-------|---------|------|
| Phase A | 核心翻译路径正确性 | 所有基础 opcode + EH shape + 委托 |
| Phase B | 性能回归 + 边界条件 | 在 Phase A 基础上扩展 |

### 审计报告

Foundation DLL 审计报告自动生成：
- 每个 foundation DLL 独立 HTML 报告页面
- 覆盖矩阵以表格展示
- Gap 分析标注未覆盖路径
- Dashboard 汇总所有 DLL 的审计状态
