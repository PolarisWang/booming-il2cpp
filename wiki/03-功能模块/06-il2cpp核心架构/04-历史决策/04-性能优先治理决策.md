# 性能优先治理决策

**来源**: `docs/discuss/il2cpp-mainline/20260408-26-*`, `20260407-02-*`

## Phase A 8 项正式决策

| # | 决策 | 说明 |
|---|------|------|
| 1 | 编译时计算优先 | 能在编译期计算的值绝不在运行时计算 |
| 2 | StringId 惰性物化 | 字符串在不需要内容时保持 ID 形态 |
| 3 | AOT baked table | 编译期生成查找表，运行时直接索引 |
| 4 | 封闭泛型完全展开 | 每个封闭实例化独立生成代码，不做泛型共享 |
| 5 | `std::call_once` cctor | 线程安全的一次初始化，无重复检查开销 |
| 6 | Carrier kind 直接映射 | ABI carrier 直接映射到 C++ 类型，无中间转换层 |
| 7 | 编译期 token 解析 | metadata token 在编译期解析为直接指针/偏移 |
| 8 | Emitter 不做语义反射 | Emitter 不扫描 IL，语义完全由 CodeGen 决定 |

## OptimizationFacts Contract

编译期记录的性能相关事实，供 CodeGen 决策参考：

```
OptimizationFacts
 ├── IsCompileTimeConstant     -- 值是否为编译期常量
 ├── CanFold                   -- 是否能折叠为更简单的形式
 ├── StringIdEligible          -- 是否能编码为 StringId
 ├── InlineCandidate           -- 是否为内联候选
 ├── BakedTableEligible        -- 是否能放入 AOT baked table
 └── RequiresRuntimeLookup     -- 是否必须运行时查找
```

## 性能优先原则

1. **零开销抽象**：不使用的特性不产生开销
2. **编译期偏执**：任何能提前计算的工作都要提前做
3. **直接映射**：尽量减少间接层和抽象包装
4. **惰性求值**：StringId 是典型例子——能不物化就不物化
5. **批量初始化**：AOT baked table 批量加载优于按需加载

## Phase A / B 边界

| Phase | 范围 | 目标 |
|-------|------|------|
| Phase A | 核心翻译管线（五层职责） | 正确性 + 架构完整性 |
| Phase B | 性能优化（内联、寄存器分配等） | 在 Phase A 基础上做优化 |

Phase A 期间不做 Phase B 类优化，Phase A 8 项决策是 Phase A 内置的性能保障基线。
