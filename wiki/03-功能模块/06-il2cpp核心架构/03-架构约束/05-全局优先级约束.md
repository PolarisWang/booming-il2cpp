# 全局优先级约束

## 三条优先级（强制）

| 优先级 | 名称 | 说明 |
|--------|------|------|
| 1（最高） | 性能最优 | 一切以 il2cpp 生成的 C++ 代码运行性能为第一考量。方案选择、翻译路径决策、代码生成策略，当其他因素与性能冲突时，性能优先。 |
| 2 | 方案完美性 | il2cpp 最终方案的架构完整性、正确性、可维护性为第二考量。在性能不受损的前提下，追求架构的干净、一致、可维护。 |
| 3 | HotUpdate 支持 | 最大化支持热更新为第三考量。在性能和方案完整性都满足的前提下，优先选择对热更新友好的方案。 |

## 裁决规则

- 低优先级与高优先级冲突时，低优先级让位于高优先级
- 高优先级方案不应故意破坏低优先级——在保证高优先级的前提下，尽量兼顾低优先级
- 当方案选择涉及优先级冲突时，必须在方案文档中明确记录裁决理由

## 覆盖范围

这三条优先级从 brainstorm 开始、经过 roadmap 规划、writing-plans 实现计划、architecture-first 架构查询、executing-plans 执行、verification 验证验收，覆盖全开发流程。所有相关 skill 中均已植入对应检查点：

| 阶段 | Skill | 检查点位置 |
|------|-------|-----------|
| 思想收敛 | dev-brainstorm | 方案对比时必须用三优先级排序 |
| 架构查询 | dev-architecture-first-development | 步骤 1 开始前检查优先级对齐 |
| 规划 | dev-writing-plans | 计划头部字段 + architecture intake |
| 路线图 | dev-roadmap | 阶段切分前检查优先级 |
| 执行 | dev-executing-plans | 第零步检查优先级冲突 |
| 验证验收 | dev-verification-before-completion | 声明完成前检查优先级满足情况 |
| 测试生成 | dev-foundation-dll-ai-test-generation | 生成前确认 benchmark/hotupdate 覆盖 |
