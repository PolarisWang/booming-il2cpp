# COM 扩展互操作

## 概述

本文档覆盖 COM 互操作的扩展能力：IErrorInfo 集成、STA/MTA 套间支持、SAFEARRAY marshaling、ICustomMarshaler V4 等。这些功能构建在 CCW/RCW/IDispatch 基础之上。

---

## 1. IErrorInfo 支持

### 问题

`Marshal.ThrowExceptionForHR(Int32)` 仅将 HRESULT 编码为 hex 字符串（如 `"0x80004005"`），不查询 `IErrorInfo` 获取友好的错误描述信息（description、source、help file）。

### 方案

HRESULT 失败时（< 0），运行时调用 `GetErrorInfo(0, &pErrInfo)` 从当前线程的 COM 错误对象获取丰富信息。新增 TLS `ComErrorInfo` 结构替代之前单一的 `tls_com_failure_hr`：

```cpp
struct ComErrorInfo {
    CHAOS_IL2CPP_INT32 hr;
    wchar_t description[1024];
    wchar_t source[256];
    wchar_t help_file[256];
};
```

### ICALL 接口

| ICALL | 用途 |
|-------|------|
| `ChaosGetComErrorDescription()` | 获取 IErrorInfo description |
| `ChaosGetComErrorSource()` | 获取 IErrorInfo source |

Managed `COMException` 构造时优先使用 IErrorInfo 描述信息，回退到 HRESULT hex 格式。

### 关键文件

- `src/native/runtime-core/core/marshal_api.cpp` — IErrorInfo 查询 + TLS 存储
- `src/native/runtime-core/engine_binding.h` — ICALL 声明
- `src/native/bootstrap/bootstrap.cpp` — ICALL 路由注册

## 2. STA/MTA 套间支持

### 问题

已有 `CoInitializeApartment` ICALL，但缺乏：
- 线程 TLS 套间类型追踪
- STA 线程的 Windows message pump
- `CoInitializeSecurity` 全局安全配置

### TLS 套间追踪

每个线程通过 `tls_com_apartment_type` 记录当前的 COM 套间类型：

```cpp
thread_local CHAOS_IL2CPP_INT32 tls_com_apartment_type = -1;
// 取值: COINIT_MULTITHREADED=0, COINIT_APARTMENTTHREADED=2, -1=未初始化
```

`CoInitializeApartment` 在 `SUCCEEDED(hr)` 时设置 TLS，`CoUninitializeApartment` 重置为 -1。

### ICALL 接口

| ICALL | 用途 |
|-------|------|
| `Marshal.GetComApartmentType()` | 查询当前线程的套间类型 |
| `Marshal.ComPumpMessages()` | STA 线程消息泵（PeekMessageW/DispatchMessageW） |

### 初始化顺序

`RuntimeInit()` 中调用 `CoInitializeSecurity(nullptr, -1, nullptr, nullptr, 0, 3, nullptr, 0, nullptr)`：
- 认证级别: `RPC_C_AUTHN_LEVEL_DEFAULT` (0)
- 模拟级别: `RPC_C_IMP_LEVEL_IMPERSONATE` (3)
- 使用默认安全配置，允许所有进程访问

### 新线程自动初始化

`chaos_thread_start` 在 worker lambda 中自动调用 `CoInitializeEx(nullptr, COINIT_MULTITHREADED)`，确保托管创建的线程始终在 COM 套间中运行。

### 关键文件

- `src/native/runtime-core/core/engine_lifecycle.cpp` — CoInitializeApartment/CoUninitializeApartment/CoInitializeSecurity
- `src/native/runtime-core/core/marshal_api.cpp` — GetComApartmentType/ComPumpMessages
- `src/native/runtime-core/core/runtime_init.cpp` — CoInitializeSecurity 调用
- `src/native/runtime-core/runtime_stubs/threading_stubs.cpp` — 新线程 CoInitializeEx

## 3. SAFEARRAY Marshaling

### 问题

COM SAFEARRAY 是 OLE 自动化中最常用的数组传递方式，但运行时缺乏原生支持。Variant VT_ARRAY (0x2000) 类型的 boxing/unboxing 也未实现。

### OLEAUT32 Thunk

采用与 BSTR 相同的延迟加载模式（`ResolveOleAut32Proc`），通过 `LoadLibraryA("oleaut32.dll")` / `GetProcAddress` 在首次使用时解析函数指针：

| Thunk | OLEAUT32 函数 | 用途 |
|-------|---------------|------|
| `SafeArrayCreateThunk` | `SafeArrayCreate` | 创建 SAFEARRAY |
| `SafeArrayAccessDataThunk` | `SafeArrayAccessData` | 锁定并获取数据指针 |
| `SafeArrayUnaccessDataThunk` | `SafeArrayUnaccessData` | 解锁数据 |
| `SafeArrayDestroyThunk` | `SafeArrayDestroy` | 销毁 SAFEARRAY |

### 数据结构

```cpp
#pragma pack(push, 8)
struct SafeArrayHeader {
    uint16_t   dimensions;    // 数组维度数
    uint16_t   features;      // FADF_* flags
    uint32_t   element_size;  // 元素大小（字节）
    uint32_t   locks;         // 锁定计数
    uint32_t   data_offset;   // 数据偏移（从 header 到数据的字节偏移）
    uint32_t   element_count; // 总元素数
    // 后跟 SAFEARRAYBOUND[] 和实际数据
};
#pragma pack(pop)
```

### Bridge 函数

| 函数 | 用途 |
|------|------|
| `MarshalSafeArrayToManaged()` | SAFEARRAY* → 托管 byte[] 数组 |
| `MarshalManagedToSafeArray()` | 托管 byte[] → SAFEARRAY* |
| `MarshalDestroySafeArray()` | 释放 SAFEARRAY 资源 |

### Struct Field Marshaling 集成

`StructFieldKind` 新增 `SafeArrayField` 枚举值：

- `MarshalFieldManagedToNative` → 调用 `MarshalManagedToSafeArray()` 写入 SAFEARRAY*
- `MarshalFieldNativeToManaged` → 调用 `MarshalSafeArrayToManaged()` 转换为托管数组
- `DestroyFieldNative` → 调用 `MarshalDestroySafeArray()` 清理

### Variant VT_ARRAY 集成

`ChaosGetObjectForNativeVariant` 新增 VT_ARRAY 分支：
- 提取 `vt` 字段清除 VT_ARRAY 标志（`vt & ~VT_ARRAY`）获取元素 VARTYPE
- 调用 `MarshalSafeArrayToManaged()` 创建托管 byte[]
- `parrayshape` 字段提供 SAFEARRAY 指针

### 关键文件

- `src/native/runtime-core/core/marshal_api.cpp` — OLEAUT32 thunks + SafeArray bridge + Variant VT_ARRAY
- `src/native/runtime-core/engine_binding.h` — SafeArray bridge 声明
- `src/native/runtime-core/marshal_abi.h` — StructFieldKind::SafeArrayField
- `src/native/runtime-core/core/struct_marshal.cpp` — SafeArrayField 字段分发

## 4. ICustomMarshaler V4

### 改进

V4 在 V3 基础上增加了明确的 cleanup 语义支持：

| 函数 | 用途 |
|------|------|
| `CustomMarshalerNativeToManaged(cookie, ptr)` | 反方向 marshaling |
| `CustomMarshalerManagedToNative(cookie, obj)` | 正方向 marshaling |
| `CustomMarshalerCleanupNativeData(cookie, ptr)` | 清理 native 侧数据 |
| `CustomMarshalerCleanupManagedData(cookie, obj)` | 清理 managed 侧数据 |

Cleanup 函数在 marshaling 完成后自动调用，防止内存泄漏。使用 cookie 字符串从注册表中查找对应的 marshaler 类型实例。

## 架构依赖

```
IErrorInfo ← GetErrorInfo (ole32.dll)
    └── tls_com_error_info (marshal_api.cpp)

STA/MTA ← CoInitializeEx / CoInitializeSecurity (ole32.dll)
    ├── tls_com_apartment_type (marshal_api.cpp)
    ├── RuntimeInit() 初始化安全配置
    └── chaos_thread_start 自动初始化

SAFEARRAY ← SafeArray* (oleaut32.dll, 运行时 thunk)
    ├── Variant VT_ARRAY 分支
    └── StructFieldKind::SafeArrayField
```
