# 统一入口脚本

一句话摘要：仓库根目录的 `run.ps1` / `run.sh` / `run.cmd` 是统一入口；它们负责拉起仓库内 Python runtime，并把当前真实可执行的 build、test、verify、prepare、clean、inspect 能力收敛到同一套 CLI 与 `--json` 协议。

## 关键结论

- 统一入口采用四层结构：wrapper、runtime bootstrap、command/manifest、handler。
- Python 实现代码固定在 `build/toolchains/run/`，wrapper 只做薄包装。
- Python runtime 不 vendored，首次通过 `bootstrap` 下载并缓存到 `artifacts/toolchains/python/<platform>/<version>/`。
- 交互式直接执行 `run` 会进入全屏 TUI 菜单；非交互式直接执行 `run` 会输出 help 并退出。
- CI / harness 必须显式调用子命令，并统一携带 `--json`。
- `prepare` 负责可复用环境准备，`clean --scope ...` 负责按 scope 回收统一入口托管的输出。
- 统一入口只暴露当前仓库里真实可执行的能力，不放占位命令。

## 分类导航

- Bootstrap 规则：何时自动确认、何时必须显式 `--yes`、runtime 缓存落点在哪里。
- 常用命令：本地开发、smoke、Roadmap 0 verify、inspect 的标准入口。
- Harness 协议：推荐生命周期、`--json` 要求、scope 复用方式。
- 产物边界：统一入口会写哪些目录，不会碰哪些目录。

## 入口分层

### Wrapper 层

- 根目录提供 `run.ps1`、`run.sh`、`run.cmd`。
- 负责 host 平台识别、runtime 检测、bootstrap 分流、参数透传。
- 不承载业务命令逻辑。

### Runtime bootstrap 层

- 实现位于 `build/toolchains/run/runtime.py`。
- 按 `runtime_manifest.json` 锁定 `python-build-standalone` release、平台下载 URL、SHA256、缓存布局。
- 当前锁定版本是 `20260303` / `CPython 3.12.13`。

### Command / manifest 层

- 入口位于 `build/toolchains/run/run.py`。
- 元数据位于 `build/toolchains/run/run_manifest.json`。
- 全屏交互菜单实现位于 `build/toolchains/run/tui.py`。
- 负责 CLI 解析、平台可见性过滤、菜单生成、`list/help/capability`、统一 JSON 结果。

## 交互菜单

- 交互终端里直接执行 `run` 时，会进入全屏 TUI 菜单，而不是纯文本分组列表。
- 当前按键为：上下方向键移动，`PgUp/PgDn` 按分组跳转，`Home/End` 跳到首尾，`Enter` 执行，`q` / `Esc` 退出。
- 菜单项完全复用 `run_manifest.json` 中 `show_in_menu=true` 的真实能力，不展示占位命令。
- 选中命令后，入口会先退出全屏菜单，再执行原始命令，避免构建/测试日志被 TUI 覆盖。
- `--json`、CI、harness 和其他非交互场景不会进入 TUI，仍然保持稳定的 CLI / JSON 协议。

### Handler 层

- `commands/build.py`
- `commands/test.py`
- `commands/verify.py`
- `commands/doctor.py`
- `commands/prepare.py`
- `commands/clean.py`
- `commands/inspect.py`

## Bootstrap 规则

- 首次交互式执行 `run` 且未发现缓存 runtime 时，wrapper 会先询问是否 bootstrap。
- 非交互环境不会自动下载 runtime；必须显式执行 `run bootstrap --yes`。
- `run bootstrap --yes --json` 是 CI / harness 的标准入口。
- bootstrap 成功后会写入 `artifacts/toolchains/python/current.json`。
- 已安装 runtime 再次执行 bootstrap 会返回 `already-installed`，不会重复下载。

## 常用命令

### 环境与检查

```powershell
./run.ps1 doctor --json
./run.ps1 bootstrap --yes --json
./run.ps1 prepare smoke --json
./run.ps1 prepare verify roadmap-0 --host windows --json
./run.ps1 clean --scope verify-roadmap0-windows --json
```

### 本地验证

```powershell
./run.ps1 build smoke HelloWorld --json
./run.ps1 test smoke HelloWorld --json
./run.ps1 verify roadmap-0 --host windows --json
```

### Inspect

```powershell
./run.ps1 list --json
./run.ps1 capability bootstrap --json
./run.ps1 help
```

macOS 使用 `./run.sh`，Windows `cmd.exe` 环境使用 `run.cmd`；三者都转到同一套 Python 命令层。

## Harness 接入建议

推荐生命周期：

1. `run bootstrap --yes --json`
2. `run prepare <scope> --json`
3. `run build ... --json` / `run test ... --json` / `run verify ... --json`
4. `run clean --scope <scope> --json`

补充规则：

- harness 只调用非交互命令，不依赖菜单，不依赖 alias。
- `prepare` 默认复用已有 scope，避免重复做昂贵构建。
- `prepare` 的 scope 状态写到 `artifacts/run/prepare/*.json`。
- `clean --scope ...` 只清统一入口管理的输出，避免误删仓库其他产物。

## `--json` 协议摘要

所有非交互命令都返回稳定 JSON 外形，基础字段包括：

- `command`
- `status`
- `hostPlatform`
- `target`
- `durationMs`
- `checks`
- `errors`

不同命令会补充自己的字段，例如：

- `bootstrap`：`runtimeStatus`、`pythonPath`、`runtimeRoot`
- `prepare`：`prepareScope`、`preparedCommands`、`cached`
- `clean`：`cleanScope`、`removedPaths`
- `build` / `test` / `verify`：`artifacts`

## 产物边界

- Python runtime 缓存：`artifacts/toolchains/python/`
- prepare 状态：`artifacts/run/prepare/`
- smoke 构建产物：`artifacts/smoke/`
- verify 产物：`artifacts/verify-roadmap-0/`
- 最终发布产物：`deploy/`

统一入口不会创建新的目录级 `README.md`，也不会清理源码目录、`third_party/` 或不受它托管的产物。

## 何时绕过统一入口

只有在以下情况才建议直调底层脚本：

- 调试 `build/scripts/verify-roadmap-0.*` 本身
- 需要最小化复现 wrapper 之外的问题
- 需要单独验证底层脚本与统一入口的映射是否一致

常规本地验证、harness、CI 都应优先走 `run.*`。
