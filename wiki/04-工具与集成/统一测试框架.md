# 统一测试框架

一句话摘要：本仓库的统一测试主线为 `managed solution -> dotnet 8 collection analysis -> collection files -> managed/native/hotupdate test hosts`，其中 `Chaos.TestFramework.Sdk` 是 subject-side test SDK，`Chaos.TestFramework.Runtime` 是执行宿主侧运行环境。

## 关键结论

- subject 目录只维护 solution 级 source，不再手工注册测试项。
- subject / managed project 只直接引用 `Chaos.TestFramework.Sdk`。
- `subject.features.json` 是 completed feature 的 owner subject 与 proof / benchmark obligation authority。
- `Chaos.TestFramework.Sdk` 同时承载：
  - attributes
  - enums
  - stable contracts
  - `Assert`
  - 最小 assertion state
- `.NET 8` collector 分析 managed project 中 `Chaos.TestFramework.Sdk` 的声明，输出 versioned collection file。
- `Chaos.TestFramework.Runtime` 负责 collection loader、managed/hotupdate test host、benchmark harness、结果汇总。
- managed proof / benchmark 必须优先使用共享 runtime host `Chaos.TestFramework.Runtime`，不得再生成 `DeclaredProofHost`、`DeclaredBenchmarkHost` 这类 per-subject managed 宿主。
- 若 subject 中仍保留 `Program.cs`、`ProofEntry`、`BenchmarkEntry`，它们只能作为 native owner contract、trace/export 或兼容过渡入口，不能再承载 managed proof / benchmark 执行。
- native test project 不直接依赖 `Runtime` DLL，而是作为各宿主消费 collection + native dispatch manifest。
- hotupdate patch project 只引用 `Sdk`；hotupdate test host project 引用 `Sdk + Runtime`。

## 正式主线

```text
managed solution
  -> dotnet 8 collection analysis
  -> collection files
  -> managed test project
  -> native project
  -> native test project
  -> hotupdate patch project + hotupdate test host project
```

解释：

- managed solution：subject 真实源工程
- dotnet 8 collection analysis：独立 collector 分析 managed project 中的 `Sdk` 声明
- collection files：collector 产出的 UnitTest / Benchmark / HotUpdate 清单
- managed test project：在 managed 环境执行正式测试
- native project：IL2CPP 生成产物
- native test project：加载 collection file 与 native dispatch manifest 执行 native 验证
- hotupdate patch project：只包含 patch 代码，引用 `Sdk`
- hotupdate test host project：加载 collection file 与 hotupdate binding manifest，执行 patch 验证

## 分层边界

### `Chaos.TestFramework.Sdk`

- subject authoring surface
- attributes
- enums
- stable contracts
- `Assert`
- `ChaosAssertionException`

### `Chaos.TestFramework.Runtime`

- execution host surface
- collection loader
- benchmark harness
- execution sink
- reporting / result state
- managed / hotupdate hosts

注意：

- `Sdk` 可被 subject 直接引用，`Runtime` 不应进入 subject 引用面。
- native / hotupdate 的执行绑定信息不写入 collection，而是通过 manifest 分层。
- subject 只声明，不再自己维护测试列表。

## collection 与 manifest 规则

- collection file：稳定测试声明与选择清单
- native dispatch manifest：`EntryId -> native callable` 绑定
- hotupdate binding manifest：`EntryId -> patch binding` 绑定
- collection 与 manifest 都必须 versioned

## Python 测试规则

- 优先使用 `tests/templates/` 下的最小模板
- 优先由 Python 参数化生成临时 managed/native/hotupdate 样例
- 手工 benchmark、dashboard 页面和控制台输出都不是正式自动测试
- compiler/runtime/test-flow bugfix 必须先补失败自动测试
- 测试阶段如果 `dotnet build` / `dotnet test` / `msbuild` 编译崩溃，必须先查明崩溃原因并修复，不能通过重试或跳过继续验证

## codegen 规则

- 生成完整 C# / C++ 文件默认使用 Scriban
- `NativeAotEmitter` 也在该规则内
- planner、emitter、runtime support、template 必须分模块，不继续向单文件聚合

## 清理规则

- 不保留长期 `Annotation` alias
- 迁移完成后删除旧 runner、旧 registry、旧 fixture、旧文档
- 项目中不允许长期并存新旧双轨入口
- 清理顺序优先移除 per-subject managed host 与其生成产物；`Program.cs` / `ProofEntry` / `BenchmarkEntry` 只有在 native owner contract 一并完成迁移后才允许彻底删除
- canonical proof / benchmark / host correctness 不允许使用 `Console.WriteLine` 或 `ChaosEvidenceKind.Stdout`
- product pipeline 不允许回退到 `ChaosSourceEntryArguments`、`DeclaredProofEntriesBySourceEntry` 或旧 subject 命名协议

## CLI 命令体系

本仓库的正式测试入口统一收归 `run test` 命令树：

| 命令 | 用途 |
|------|------|
| `run test inventory --json` | formal refresh 入口，刷新 archive / projection / evidence |
| `run test list` | 列出所有公开 test suite |
| `run test all` | 批量运行所有公开 suite + subject |
| `run test <family> <suite>` | 运行指定 suite（如 `run test smoke managed-entry-basic`） |
| `run test suite --family <f> --suite <s>` | 显式 suite selector |
| `run test subject --id <id>` | 运行指定 subject object |
| `run test module --module <m> --profile <p>` | 运行指定 module |
| `run test system --id <id>` | 运行指定 system scenario |
| `run test registry list` | 查看注册表 |
| `run test registry refresh` | 刷新注册表 |
| `run test workflow <id>` | 运行 workflow（如 `runtime-baseline-windows`） |
| `run test watch` | 持续观察测试结果 |
| `run test summary` | 查看汇总 |

### Foundation-DLL 独立管线

Foundation-DLL 审计保留独立 `run foundation-dll *` 命令，不混合到 `run test`：

| 命令 | 用途 |
|------|------|
| `run foundation-dll derive --scope <dll>` | 派生 candidate denominator |
| `run foundation-dll promote --scope <dll>` | 提升为正式 authority |
| `run foundation-dll refresh` | 刷新 projection/docs |
| `run foundation-dll verify-consistency` | 校验一致性 |
| `run foundation-dll full --scope all` | 完整执行全链路 |

### Native C++ 测试

Native C++ GoogleTest 通过 `run test system/module/suite` 方式访问，通过 `build/toolchains/run/testing/registry.py` 扫描注册到统一命令树。

## 统一测试与验证管道关系

```text
run test smoke <suite>  ──→  Chaos.TestFramework.Runtime  ──→  managed/native test
run test contract <id>  ──→  contract checker             ──→  schema validation
run test inventory       ──→  inventory_generator          ──→  archive + projection
run foundation-dll full  ──→  foundation-dll pipeline      ──→  capability ledger
```
