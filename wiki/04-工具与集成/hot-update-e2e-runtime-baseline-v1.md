# Hot Update E2E Runtime Baseline v1

## 目标

Phase C 的长期目标是把 hot update 从 Phase 5 的 skeleton 提升为可验证的端到端闭环：

- package 可以按目录加载与卸载；
- AOT 调用点可以被方法替换表接管；
- AOT 与 HotUpdate 间的常见签名可以自动 bridge；
- 运行时可以记录历史并回滚；
- hot update benchmark subjects 可以走正式 `run benchmark --record` 入口。

## Managed 运行时边界

### RuntimeManager

`src/managed/Chaos.IL2CPP.HotUpdate/RuntimeManager.cs` 现在负责：

- 从 `packageRootPath` 读取 manifest，并做版本兼容检查；
- 在切入 Mixed mode 之前捕获 `RuntimeSnapshot`；
- 把 subject-id 级 constant/unary/generic target 注册进 `HotUpdateMethodRegistry`；
- 暴露 `LoadPackage(...)`、`UnloadPackage()`、`Rollback()`、`GetActivePatches()`、`ValidateIntegrity()`；
- 在回滚时恢复 package、AOT 版本、mode 与 registry 快照。

### HotUpdateMethodRegistry

- 当前 registry 同时支持常量 `int -> int` stub、`Func<int, int>` unary target、`Func<IReadOnlyList<object?>, object?>` 泛型 target。
- `TryDispatch(...)` 是当前 Phase C 的统一入口。

### 架构取舍

- `RuntimeManager` 没有在本项目内直接依赖 `Chaos.IL2CPP.Interpreter` 做 package → lowering → IRMethod 注册。
- 这是为了避免 `HotUpdate` 与 `Interpreter` 之间形成项目循环引用。
- 因而 Phase C 的长期稳定边界是：
- package / rollback / integrity / registry 归 `HotUpdate`；
- 具体解释执行与 bridge 调度由外部注入 target 或 `ManagedInterpreterExecutor` 承接。

## Auto Bridge 边界

### AutoBridgeGenerator

`src/managed/Chaos.IL2CPP.HotUpdate/AutoBridgeGenerator.cs` 当前只承诺 5 类签名：

- `System.Void()`
- `System.Int32(System.Int32)`
- `System.Int32(System.Int32,System.Int32)`
- `System.String(System.String)`
- `System.Object(System.Object)`

不在这 5 类里的签名必须抛出 `NotSupportedException`，而不是静默降级。

### BridgeDispatcher

`src/managed/Chaos.IL2CPP.HotUpdate/BridgeDispatcher.cs` 当前负责：

- `RegisterAutoGenerated(BridgePlan)` 接入自动生成结果；
- `Dispatch(string bridgeId, IReadOnlyList<object?> args)` 把 auto-generated bridge 路由到 managed target；
- 同时保留 AOT→HotUpdate、HotUpdate→AOT、HotUpdate→Engine、delegate wrapper 的显式表面。

## Native 运行时边界

### package loading

`src/native/hot-update/hot_update.h` 暴露：

- `HotUpdatePackageHandle`
- `LoadHotUpdatePackage(...)`
- `UnloadHotUpdatePackage(...)`

这里的长期稳定职责是原生侧 package 句柄、assembly image 和 supplemental metadata image 的装载面，而不是 managed registry。

### 方法替换

`src/native/hot-update/method_replacement.h/.cpp` 提供：

- `Register(token, thunk)`
- `Revert(token)`
- `RevertAll()`
- `Resolve(token)`
- `ActiveCount()`

`src/native/bootstrap/bootstrap.cpp` 的规则是：

1. 先查 `method_replacement::Resolve(method_token)`
2. 命中则返回替换 thunk
3. 否则回落原始 code registration

这意味着 Phase C 的方法替换是“查询时劫持”，不是直接覆写 AOT 表。

