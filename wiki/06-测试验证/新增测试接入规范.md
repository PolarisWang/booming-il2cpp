# 新增测试接入规范

## 重要验证升格规则

- 修复真实 bug 的回归验证，必须沉淀为正式 case。
- 被 skill 标记为 `required-before-completion` 的验证，必须沉淀为正式对象。
- 被 module/system/pipeline 引用的验证，必须沉淀为正式对象。

## 典型例子

- IL2CPP 翻译器修复了泛型方法实例化丢失问题，不能只在本次开发里手工跑一个样例；应补成对应 suite 下的正式 case。
- hosted runtime 修复了 attach/detach 生命周期错误，如果它已经成为“完成前必须验证”的项目规则，就要落成 `module/...` 或 `system/...` 对象，而不是继续写成口头 checklist。
- release 前要求同时跑代码 smoke、模块验证和宿主场景验证时，应沉淀为 `pipeline/...` 对象，而不是在任务单里手工抄三条命令。

## 默认优先级

1. 先把验证加入现有 suite 的新 case。
2. 只有执行单元、准备流程、目标平台、主验证目标发生实质变化时，才新建 suite。
3. 当验证目标跨 suite 或跨模块时，新增 module/system/pipeline 对象而不是继续堆手工步骤。
