# 新增测试接入规范

本仓库新增测试的正式入口是：

`managed solution -> dotnet 8 collection analysis -> collection files -> managed test project -> native project -> native test project -> hotupdate patch project + hotupdate test host project`

如果本次新增的是 AOT 主线新 feature，而不是单纯补一个测试入口，请继续阅读：

- [`AOT新Feature接入自测规范.md`](./AOT新Feature接入自测规范.md)

## 接入步骤

1. 在 subject 的 managed solution 中新增测试源码。
2. 引用 `Chaos.TestFramework.Sdk`。
3. 使用 `Chaos.TestFramework.Sdk` 中的 attribute 声明 UnitTest / Benchmark / HotUpdate 入口，并使用 `Sdk.Assert` 编写断言。
4. 由 `.NET 8` collector 分析 managed project 中的 `Chaos.TestFramework.Sdk` 声明并输出 collection file。
5. 由后续 managed test project、native test project、hotupdate test host project 统一消费 collection file。

## 强制规则

- subject 目录只保留 managed solution 级 source。
- subject / managed project 只直接引用 `Sdk`。
- 测试项通过 `Sdk` attribute 声明，不再手工注册。
- collection file 统一由 `.NET 8` collector 产出，执行侧只消费它。
- native 与 hotupdate 的执行绑定信息通过 manifest 分层，不写回 collection file。
- AOT 主线新 feature 必须先明确 `owner subject`，canonical proof / benchmark 只放在该 owner subject 中。
- 非 owner subject 默认不复制完整 proof / benchmark；只有存在独立集成差异时，才允许补 consumer smoke。

## 不允许的做法

- 在 subject 中直接引用 `Runtime`
- 在 managed/native/hotupdate 三端各自重新扫描 `Sdk`
- 在 runner 中手工维护测试列表
- 依赖 `Console.WriteLine` 再在外层脚本里判定成功失败
- 用 dashboard 结果替代正式自动测试
- 长期保留 `Annotation` 兼容别名
- collector / registry / workspace 接线未验收就直接进入 proof 执行
