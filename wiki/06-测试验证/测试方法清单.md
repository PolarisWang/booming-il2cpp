# 测试方法清单 — 全链路索引

> 本文档系统化梳理项目中所有主要的测试方法和测试链路，按测试链分层组织，覆盖 Python 测试、C# Foundation-DLL 验证、Native 编译验证和基础设施管线。

---

## 一、测试架构全景

项目采用**双语言、三层级、三闸门**的测试架构：

```
┌─────────────────────────────────────────────────────────────┐
│                    测试入口层                                │
│  run.sh / run.cmd → build/toolchains/run/run.py             │
│  pytest.ini → testpaths = tests                              │
├─────────────────────────────────────────────────────────────┤
│                    测试框架层                                │
│  ┌──────────────────┐  ┌─────────────────────────────────┐  │
│  │ Python 测试链     │  │ C# Foundation-DLL 验证链        │  │
│  │ pytest+unittest   │  │ xUnit 2.9 + Chaos.TestFramework │  │
│  │ ~436 文件         │  │ ~1192 文件 (14 个 DLL)          │  │
│  └──────────────────┘  └─────────────────────────────────┘  │
├─────────────────────────────────────────────────────────────┤
│                    验证闸门 (三闸门)                          │
│  Fact (正确性) → Benchmark (性能) → HotUpdate (热更新)      │
├─────────────────────────────────────────────────────────────┤
│               Native 编译验证层                               │
│  native_compile_runner.py → MSVC cl.exe → .obj              │
│  native_benchmark_runner.py → 编译+运行 → JSON 计时结果      │
└─────────────────────────────────────────────────────────────┘
```

## 二、Python 测试链（tests/）

### 2.1 测试模式分类

| 模式 | 验证手段 | 代表文件 | 验证深度 |
|------|----------|----------|----------|
| **A: C++ 文本断言** | 生成 `.cpp` 文件包含特定 C++ token | `test_not_opcode_native_aot.py` | 验证 C++ 结构对，不验证可编译/运行 |
| **B: 源码契约断言** | proof `.cs` 文件包含预期的 C# 片段 | `test_dispatch_virtual_native_aot.py` | 验证 proof 代码结构正确 |
| **C: IR 中间表示断言** | `aot-core-ir.json` 包含期望 opcode/方法名 | `test_overflow_opcode_native_aot.py` | 可验证 IR 变换正确性 |
| **D: 合成项目测试** | 动态写入 .cs → 整个管线验证 | `test_string_concat_native_aot.py` | 验证对新语法特性的管线支持 |
| **E: 端到端程序执行** | 编译运行并断言 stdout | `test_hot_update_e2e_flows.py` | 最强验证 — 实际运行托管程序 |

### 3.3 C# 测试方法模式

每个能力族包含四类测试文件，每种文件包含对应的方法级测试：

#### 3.3.1 AutoGenerated 测试（`src/*.AutoGenerated.cs`）

每个方法 subject ID 生成 3 种方法：

**测试方法** — 实例方法，通过 `[MethodSubjectId]` 反射发现：
```csharp
[MethodSubjectId("System.Private.CoreLib/System.Convert::ToChar:System.Char(System.Boolean)")]
[CapabilityFamilyId(CapabilityFamilyId.SystemPrivateCoreLib_ConvertChar)]
[VerificationRoute(VerificationRoute.Native)]
public void Method_System_Private_CoreLib_System_Convert_ToChar_System_Char_System_Boolean()
{
    var result = Convert.ToChar(true);
}
```

**Benchmark 方法** — 静态 void，通过 `[BenchmarkSubjectId]` 标记：
```csharp
[BenchmarkSubjectId("System.Private.CoreLib/System.Convert::ToChar:System.Char(System.Boolean)")]
[BenchmarkRoute(BenchmarkRoute.Native)]
[BenchmarkProfile(BenchmarkProfile.Default)]
public static void Benchmark_System_Private_CoreLib_System_Convert_ToChar_System_Char_System_Boolean()
{
    _ = Convert.ToChar(true);
}
```

**HotUpdate 方法** — 静态 void，通过 `[HotUpdateSubjectId]` 标记，HostToPatch 方向：
```csharp
[HotUpdateSubjectId("System.Private.CoreLib/System.Convert::ToChar:System.Char(System.Boolean)")]
[HotUpdateDirection(HotUpdateDirection.HostToPatch)]
public static void HotUpdate_System_Private_CoreLib_System_Convert_ToChar_System_Char_System_Boolean()
{
    _ = Convert.ToChar(true);
}
```

#### 3.3.2 Phase 2 手写测试（`test/*Tests.cs`）

根据方法分类生成不同的测试体：

| 分类 | 条件 | 测试体 | 断言 |
|------|------|--------|------|
| **simple** | 全原始类型参数+返回值 | `var result = Call();` | `Assert.NotNull(result)` |
| **mixed** | 含复杂类型参数 | `_ = Call();` | 仅 smoke（无断言） |
| **unsafe** | 含 ref/pointer/generic 参数 | 跳过 | `[Fact(Skip = "needs-manual")]` |
| **needs-manual** | 显式标记为需手动处理 | 跳过 | `[Fact(Skip = "reason")]` |

#### 3.3.3 Phase 2 手写 Benchmark（`benchmark/*Benchmarks.cs`）

```csharp
[BenchmarkSubjectId("...")]
[BenchmarkRoute(BenchmarkRoute.Native)]
[BenchmarkProfile(BenchmarkProfile.Default)]
public static void Benchmark_...() { ImmutableArray.Count; }
```

#### 3.3.4 Phase 2 HotUpdate 双向测试
- `host/*HotUpdate.cs` — HostToPatch 方向
- `patch/*Patch.cs` — PatchToHost 方向

## 八、测试颗粒度总结

| 颗粒度层级 | 能验证什么 | 状态 |
|-----------|-----------|------|
| C++ 代码文本 token | 生成的 `.cpp` 包含期望的 C++ token | ✅ 精确验证 |
| IR 中间表示 | IR 变换是否正确（如 overflow 提取） | ✅ 精确验证 |
| 方法签名接入 | 特定签名的方法能否在 Native 端调用 | ✅ 精确验证 |
| C++ 编译通过 | 生成的 `.cpp` 能否通过 MSVC 编译 | ✅ 精确验证 |
| 方法调用不崩溃 | 调用是否抛异常/崩溃 | ✅ 基本覆盖 |
| 程序 stdout | 托管程序输出是否符合预期 | ⚠️ 仅 HotUpdate |
| 数值正确性 | 翻译后代码计算结果是否正确 | ❌ 不验证 |
| 内存正确性 | GC、对象生命周期、野指针 | ❌ 不验证 |
| 异常语义 | .NET 异常是否正确传播 | ❌ 不验证 |
| IL 语义等价 | IL → C++ 翻译语义完全等价 | ❌ 不验证 |
