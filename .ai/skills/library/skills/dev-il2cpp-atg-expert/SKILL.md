## Layer 1 — Probe 核心

### 方法选择逻辑

```csharp
// 当前选择条件:
//   1. public 类型 + public 方法
//   2. 跳过: 泛型类型参数未满足 new() 约束
//   3. 跳过: JsonSerializerContext.AddContext 等已知问题方法
//   4. 受 namespace-filter 限制（chunk 模式下）
```

**已知问题：**

| 问题 | chunk | 根因 |
|------|-------|------|
| `enum-parsing` 0 subjects | enum-parsing | .NET 9 SPC 中 `System.Enum` 的 public API 无匹配方法（类型结构变了） |
| `global-ns` 0 subjects | global-ns | `--namespace-filter` 过宽或过窄 |

### 值集生成

```csharp
// 当前行为:
//   为每个参数生成 1-3 组值:
//   1 组: default(T) — 所有参数 zero-initialized
//   2 组: explicit(T)0 — 明确类型的零值
//   3 组: boundary value — 边界值（仅对数值类型）

// 输出: ValueSet → 生成 [Fact] 方法的多个变体
//   IsPow2_0_int_0: default(int)
//   IsPow2_0_int_1: (int)0
```

### Probe 判定逻辑

```
执行 2 次 → 比较结果
  ├── 结果一致? → IsDeterministic = true
  │   ├── 非 void? → kind = "hotupdate", 合约值 = 结果
  │   └── void?    → kind = "fact"
  └── 结果不一致? → IsDeterministic = false → kind = "fact"
      └── 抛异常? → HasException = true → kind = "hotupdate" (无合约值)
```

**已知的 Probe 误判定：**

```
Vector.EqualsAny(zero, zero) → .NET 执行返回 true
  → 第 2 次执行返回 true → IsDeterministic = true
  → 合约值 = 1 → kind = "hotupdate" ✅ 正确

但 CS 生成的 C++ 测试代码中:
  _s2 = 读取 Probe 结果（=1）
  _s3 = actual_result（来自 chaos_external_runtime_* fallback = 0）
  if (1 != 0) throw → crash!

根因：Probe 的合约值（1）和 AOT 执行结果（0）不匹配。
这不是 ATG 的问题，这是 AOT fallback 返回错误值的问题。
```

## Layer 2 — SubjectId 规范

### SubjectId 传递链

```
ATG 生成:  SubjectId = "CombinedSubjects/AutoGenerated.System.Convert::Subject_0:System.Int32()"
                          ↓
metadata.json → CodeGen → AOT Core IR → 匹配方法
                          ↓
TPG 生成 dispatch

必须 100% 一致的部分：
  1. Assembly name      ("CombinedSubjects")
  2. AutoGenerated.NS   ("AutoGenerated.System.Convert")
  3. ::MethodName       ("::Subject_0")
  4. :ReturnType(Params) (":System.Int32()")
```

### generatedMethodId 规范

```
格式: {MethodName}_{MethodIndex}_{ParamSuffix}_{SetIndex}
示例: IsPow2_0_int_0
分解:
  MethodName    = IsPow2       (C# 方法名, SanitizePath)
  MethodIndex   = 0            (同一方法的重载索引)
  ParamSuffix   = int          (参数类型的 SanitizeIdentifier)
  SetIndex      = 0            (值集变体索引)
```

**一致性要求：**
- `generatedMethodId` 在 metadata.json 中定义 → CodeGen 用来生成 C++ 符号名 → TPG 用来生成 dispatch entry
- 任何一端修改命名规则都必须同步更新其他两端

```json
{
  "schemaVersion": 1,
  "assemblyName": "CombinedSubjects",
  "chunkSlug": "numerics",

    }
  ]

```

### 消费方契约

| 消费方 | 读取的字段 | 用途 |
|--------|-----------|------|
| build.py | `totalMethods` | `meta_total` 比对 |
| CodeGen | `methods[].generatedMethodId` | AOT subject ID 列表 |
| TPG | `methods[]` | dispatch entry 生成 |
| fact_chunk.py | `totalMethods` | dropped methods 检测 |
| coverage-audit | `methods[]` | 覆盖率计算 |

## Layer 4 — 测试代码质量门

### [Fact] 方法生成规则

```csharp
// ✅ 正确模式: 
[Fact]
public long Foo_0_int_0() {
    var result = TargetMethod(default(int));  // 调用目标
    return result ? 1L : 0L;                  // 合约返回值
}

// ❌ 禁止模式:
// 1. 无 Assert.AreEqual 的非确定性方法
// 2. 传 null 给值类型参数
// 3. 在 void-returning benchmark 中调用 Assert
```

### [Benchmark] 方法生成规则

```csharp
// ✅ 正确模式:
[Benchmark]
public static void Benchmark_Foo_0_int_0() {
    _ = TargetMethod(default(int));  // 丢弃返回值
}
```

### [HotUpdate] 方法生成规则

```csharp
// ✅ 正确模式:
[Fact]
[HotUpdate]
public long Foo_0_int_0() {
    var result = TargetMethod(default(int));
    return result ? 1L : 0L;  // 与 Fact 相同
}
```
