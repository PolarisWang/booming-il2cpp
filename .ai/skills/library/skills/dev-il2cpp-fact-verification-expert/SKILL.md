## 核心流程

### 流程 1: Fact 执行与结果判定

```
输入: chunk_dir / entry_exe_path / meta_total
输出: StageResult(status, passed/total, errors)

1. 运行 entry.exe --fact-json（AOT）
2. 如果存在 entry-jit.exe，同时运行（JIT）
3. 解析 JSON 输出:
   - 提取 factResults[]
   - 计算 passed / total
4. 应用 skip-list 过滤（_KNOWN_FACT_FAILURES + fact_skip_indices.json）
5. 判断 status:
   - passed: rc==0 && passed==total
   - passed: rc in SHUTDOWN_AV_CODES && passed==total（CRT teardown crash）
   - partial: 部分通过
   - error: 全部失败或 entry.exe 不存在
   - skipped: total==0
6. Metadata 交叉检查: meta_total vs actual_total（检测 silent method drop）
7. Value 告警检测: passed 但 value < 0（非 -1）
```

### 流程 2: 错误诊断与路由

```
fact result = error / partial → 诊断:
  1. 检查 entry.exe 是否存在 → 否 → route to build-fixer（构建未生成）
  2. 检查 returncode:
     - rc in SHUTDOWN_AV_CODES → 接受，标记 passed
     - rc == -1 (timeout) → 重试一次，仍超时 → route to debug-expert
     - 其他非零 rc:
       a. 查 stderr 中是否有 C++ 异常/ASSERT FAIL
       b. 查 stdout 末尾是否有 JSON truncation
  3. 查 passed/total 比例:
     - passed 接近 total（少量失败）:
       a. 查失败 method 的 si（subject index）
       b. si 在 codegen known issues 范围 → route to codegen-expert
       c. si 在 runtime known issues 范围 → route to debug-expert
     - passed 远小于 total（大量失败）:
       a. 查是否为 codegen 输出为空 → route to codegen-expert
       b. 查是否为 AOT IR 不完整 → 审查 native/subjects/aot-core-ir.json
       c. 查是否为 ATG 输出为空 → 审查 managed/subjects/*.cs

  路由输出: {diagnosis: "xxx", evidence: {stdout_snippet, stderr_snippet, failed_si_list}, route_to: "xxx"}
```

### 流程 3: Skip-List 维护

```
场景: 新的 pre-existing failure 出现 / 已有 failure 被修复

1. 确认 failure 是 pre-existing（非本次改动引入）
2. 确认 root cause:
   - codegen ABI 限制（如 Int128 struct return）→ 加 _KNOWN_FACT_FAILURES
   - stub 实现缺失 → 检查是否可修复，不可则加 fact_skip_indices.json
3. 更新:
   - _KNOWN_FACT_FAILURES（fact_chunk.py 中的 frozenset）
   - fact_skip_indices.json（pipeline 用）
   - fact_skip_indices.h（native 用）
4. 验证: 重新跑 fact，确认 skip 后全部 passed
5. 记录: 更新 skip-list 的注释，说明原因和跟踪 issue
```

### 流程 4: Codegen 输出审查（触发式）

```
触发条件: fact 失败 + 怀疑 codegen 输出问题

审查清单:
□ native-aot.generated.cpp:
   - 结构完整性（method 入口、code registration 是否存在）
   - 方法签名与 metadata 一致
   - 无明显的 C++ 语法错误（不完整语句、括号不匹配）

□ aot-core-ir.json:
   - methodSubjectIds 完整 vs metadata 声明的方法数
   - lowering-plan 的 emit 状态

□ enum_metadata.generated.h / runtime_helper_shapes.h:
   - type handle 定义与 fact 中引用的 subject 一致

审查输出: {passed: bool, findings: [...], recommendation: "route to codegen-expert" | "fact 重跑即可"}
```

### 已知故障模式

| 症状 | 根因 | 路由 |
|------|------|------|
| fact 全部失败（0 passed） | entry.exe 不存在或崩溃 | build-fixer |
| fact 少量 failure | codegen ABI 限制（Int128/Int16） | fact: 加 skip-list / codegen-expert |
| fact partial + value < 0 | stub 返回 sentinel（-1） | fact: 标记 value_suspicious |
| fact partial + shutdown-AV | CRT teardown crash | fact: 接受（已知模式）|
| fact AOT partial + JIT passed | AOT codegen 不支持某些方法 | fact: JIT 结果优先提升 |
| metadata 差异（silent drop） | codegen 未生成某些 subject | codegen-expert |
| ATG 输出为 0 methods | DllScanner 未扫描到 public API | build-fixer |
| fact_skip_indices 不同步 | JSON + header 不一致 | fact: 同步两者 |
