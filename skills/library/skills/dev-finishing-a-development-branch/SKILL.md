# 完成开发分支

## 概述

本技能负责 plan 执行完成后的固定收尾，不再提供 PR、保留分支或丢弃工作的多选分流。

**核心原则：** 先确认归档与验证证据，再做本地合并；合并后自动提交并推送。

**开始时宣布：** "我正在使用 finishing-a-development-branch 技能来完成这项工作。"

## 前置条件

- 调用方已经完成 `completed` 归档
- 已有最新的架构合理性审视结论与项目级测试通过证据
- 如果前置证据缺失、过期或无法证明当前状态，先回到执行主线补齐，不要在本技能里假设通过
- 如果归档动作产生了新的本地改动，先在当前工作分支完成本地提交，再切换目标分支

## 流程

### 第一步：确定目标分支

1. 优先使用用户明确指定的目标分支
2. 未指定时，默认尝试 `main`，其次 `master`
3. 如果无法确定目标分支，或目标分支上存在会污染本次收尾的未提交变更：停下来向用户确认

### 第二步：确保当前工作分支已提交并执行本地合并

- 如果当前工作分支仍有未提交改动，先完成本地提交；否则不要切换分支
- 这些提交通常包含归档 `completed` 产生的 `STATUS.md` / `INDEX.md` / 目录终态变更

```bash
git checkout <target-branch>
git merge <feature-branch>
```

- 如果当前工作已经直接在目标分支上完成，无需额外合并，直接进入“提交收口”
- 如果出现冲突，先解决冲突并记录原因；冲突未解决前不得宣称收尾完成

### 第三步：验证合并结果

- 如果是快进合并，且目标分支只是前移到已经验证过的提交，可以复用归档前的完整测试证据
- 如果发生冲突、手工改动，或目标分支在合并前有新增提交，必须在合并结果上重新运行受影响验证；必要时重跑项目级测试套件
- 如果测试阶段出现 `dotnet build` / `dotnet test` / `msbuild` 编译崩溃：
  - 立即视为失败
  - 收集 stderr、binlog、崩溃堆栈或 dump 信息（如果可用）
  - 使用 `dev:systematic-debugging` 修复根因后再继续

### 第四步：提交收口

- 合并后的结果必须在目标分支形成可追踪的本地提交历史
- 非快进合并时，保留 merge commit 或按仓库 git 工作流完成本地提交
- 快进合并时，可以直接接受已验证提交，不必额外制造空提交
- 如果合并冲突修复或其他收尾改动导致工作区仍有未提交变更，必须在结束前完成本地提交
- 记录最终目标分支与 commit SHA

### 第五步：清理本地分支与 Worktree

- 只在合并成功、验证完成、没有未提交变更后删除 feature branch
- 如果本次工作来自 `dev:using-git-worktrees` 创建的 worktree，同步清理对应 worktree
- 不自动执行 `git push`、`gh pr create` 或丢弃分支

## 常见错误

- **把 `completed` 归档误当成已经完成 git 收尾**
  - **问题：** 任务目录已关闭，但代码还停留在功能分支或临时 worktree
  - **修复：** 归档后必须继续完成本地合并与提交收口
- **归档后直接 push / PR**
  - **问题：** 绕过本地合并验证，与本仓库固定收尾顺序冲突
  - **修复：** 先完成本地合并与提交；推送是否需要由用户单独决定
- **快进合并后仍保留未提交改动**
  - **问题：** 目标分支状态不可追踪
  - **修复：** 结束前确保工作区干净，必要时补本地提交
- **把 `dotnet` 编译崩溃当成环境偶发**
  - **问题：** 合并结果未经稳定验证
  - **修复：** 先查根因并修复，再继续收尾

## 红旗

**绝不：**
- 把本技能改回多选分流
- 在没有 `completed` 归档和最新验证证据时继续
- 在合并冲突未解决或测试失败时宣布收尾完成
- 自动 `git push`、自动创建 PR、自动丢弃分支

**始终：**
- 先确认目标分支
- 本地合并后保留可追踪提交结果
- 合并后如有新风险重新验证
- 清理前确认无未提交变更

## 集成

**由以下调用：**
- **subagent-driven-development** - 所有任务完成并归档后
- **executing-plans** - 所有批次完成并归档后

**配合：**
- **using-git-worktrees** - 清理该技能创建的 worktree
- **systematic-debugging** - 处理合并验证阶段的编译崩溃或其他阻断性问题
