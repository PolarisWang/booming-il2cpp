# Foundation DLL — New Family Onboarding

## 概述

将一个新的 capability family 接入 foundation DLL 验证体系。覆盖从更新 ledger 到跑通 verification pipeline 的完整流程。

**入口信号**：`dev-foundation-dll-onboard-family`

## 前置条件

- 该 family 的翻译路径已在 codegen 中实现
- 对应的 managed API 方法已确认 subject ID

## 步骤

### Step 1: 确认 methodSubjectIds

```bash
# 确认 ledger 中有该 family 的定义和 methodSubjectIds
python -c "
import json
from pathlib import Path
ledger = json.loads(Path('verification/projections/foundation-dll-audit/capability-family-ledger.json').read_bytes())
for dll in ledger['dlls']:
    if dll['assemblyName'] != 'System.Private.CoreLib':
        continue
    for fam in dll.get('families', []):
        if 'reflection' in fam['familyId']:  # 按需过滤
            mids = len(fam.get('methodSubjectIds', []))
            print(f'{fam[\"familyId\"]}: {mids} MIDs')
"
```

如果 family 尚未在 ledger 中或 methodSubjectIds 为空：

```bash
# 更新 ledger → 运行 candidate ledger 生成
python build/toolchains/run/testing/foundation_dll/derive.py \
  --assembly System.Private.CoreLib \
  --scope capability-family
```

### Step 2: Phase 1 — AutoGenerate 测试骨架

```bash
python build/toolchains/run/testing/foundation_dll/test_code_generator.py \
  --assembly System.Private.CoreLib \
  --family <family-slug>
```

这会生成：
- `src/<Family>.AutoGenerated.cs` — 测试 + benchmark + hotupdate 方法
- `src/patch/<Family>Patch.AutoGenerated.cs` — patch 侧代码
- `managed_test/tests/` — xUnit entry point
- `managed_test/benchmarks/` — benchmark harness

### Step 3: Phase 2 — 手写测试生成

```bash
python build/toolchains/run/testing/foundation_dll/run_phase2.py \
  --assembly System.Private.CoreLib
```

这会生成：
- `test/<Family>Tests.cs` — 带 `[Fact]` 的手写测试
- `benchmark/<Family>Benchmarks.cs`
- `host/<Family>HotUpdate.cs`
- `patch/<Family>Patch.cs`

### Step 4: Codegen Pipeline

```bash
python build/toolchains/run/testing/foundation_dll/batch_native_aot_runner.py \
  --assembly-name System.Private.CoreLib \
  --families <family-slug>
```

**验证产物**：
```bash
# coverage JSON 必须存在
ls verification/foundation-dll/System.Private.CoreLib/<family>/il2cpp_dist/native-reference.runtime-skeleton.coverage.json

# 生成的 C++ 文件
ls verification/foundation-dll/System.Private.CoreLib/<family>/il2cpp_dist/genuine/generated/native-aot.generated.cpp
```

### Step 5: 验证管线

```bash
# 刷新 dashboard → claims 纳入新 family
python -c "
from pathlib import Path
import sys
sys.path.insert(0, 'build/toolchains/run/testing')
sys.path.insert(0, 'build/toolchains/run')
from foundation_dll_audit_generator import write_foundation_dll_audit_outputs
write_foundation_dll_audit_outputs(Path('.').resolve())
"

# 运行 verification pipeline
dev:foundation-dll-verification-pipeline
```

### Step 6: 确认 Dashboard

```bash
python -c "
import json
claims = json.load(open('verification/projections/foundation-dll-audit/family-verification-claims.json'))
for asm in claims['assemblies']:
    if asm['assemblyName'] != 'System.Private.CoreLib':
        continue
    for c in asm.get('claims', []):
        if '<new-family-id>' in c.get('familyId', ''):
            print(f'{c[\"familyId\"]}: gate={c[\"gateCode\"]} denom={c[\"denominator\"]} mids={len(c[\"methodSubjectIds\"])}')
"
```

确认新 family 出现在 claims 中，denominator 与方法数匹配。

## 产出清单

| Step 2 | `*.AutoGenerated.cs` | 文件存在 |

| Step 4 | `native-aot.generated.cpp` | 文件存在 |

| Step 5 | Claims 包含新 family | `family-verification-claims.json` |
| Step 5 | Fact/Benchmark/HotUpdate 门全部通过 | verification dashboard |

## 已知问题

- **Phase 1/Phase 2 脚本依赖于 `capability-family-contract.json`** — 确保该文件已从 ledger 生成或手动创建
- **batch pipeline 需要先 build Driver** — 如果 Driver 还没 build，先跑 `dotnet build src/managed/Chaos.IL2CPP.Driver`
- **新 family 的 reflection 系列需要额外的 metadata supplement** — 如果 family 涉及泛型/反射，可能需要先跑 metadata supplement 管线
